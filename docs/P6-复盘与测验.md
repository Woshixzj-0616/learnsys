# P6 验收记录 · 复盘 / 测验两个插件

> 日期：2026-10-21 ｜ 版本：`2.0.0` ｜ 状态：两个插件从 `planned` 变为 `ready`


## 一、复盘插件

- 入口：`#/review`，学习台插件卡片、侧栏「复盘」。
- 素材：`GET /api/study/today` 汇总今天的
  - 录制窗口摘要（`session_summary` + 窗口标题）；
  - 课堂转写正文（`transcripts_digest`）；
  - 今日问答；
  - 网工训练事件、六级断点。
- 拼题口径只在 `learnsys/ask/study.py::build_review_question` 一处。
- 「开始复盘」→ `POST /api/agent/chat`（`mode=explain`，`module=review`，`internal=true`）流式写进右侧卡片。
- 成功后写一条 `events`（`module=review, kind=report`），学习点 +25。
- 内部提示词**不记成「我问过什么」**：`internal=true` 时只存会话消息，不写 `asks`；
  问一问会话列表默认只列 `module=ask`。
- 页面材料区显示：记录摘要、今天问过的、可折叠的课堂转写。

实测（真实模型）：复盘输出按「①在学什么 / ②5 个要点 / ③哪里没学进去 / ④10 分钟复习建议」组织；
数据不足时明确说「判断不了」，不编。关闭页面重进后按钮根据今日数据自动启用/禁用。

## 二、测验插件

- 入口：`#/quiz`。
- 「出 5 道题」→ 用 `build_quiz_question` 拼题，`mode=quiz`、`module=quiz`、`internal=true`；
  题型从今日窗口、问答、训练、六级断点里来。
- 对话区逐题作答：Enter 发送，AI 当场批改并出下一题；可「停止」。
- 每轮作答复用同一个 `conversation_id`，多轮上下文正常。
- 开始测验写一条 `events`（`module=quiz, kind=quiz`），学习点 +20；作答本身不再记成问答，
  避免把「第 1 题选 C」这类内部对话塞进今日时间线。
- 页面顶部显示今日素材：专注 / 问答 / 转写 / 网工训练 / 六级断点。

实测（真实模型）：
- 出题：5 道（选择 + 简答，覆盖 /27 掩码、块大小、/28 主机数、/26 网络/广播、路由汇总）。
- 作答「第 1 题选 C，/27 是 255.255.255.224」→ 判定正确，解释 224 的来源和易错点，接着出第 2 题。

## 六、已知缺口

1. 刷新 `/quiz` 不能恢复上一场测验（会话 id 没写进 URL）；复盘结果也没有历史列表。
2. 测验答错的内容还没有自动进错题本；下一步做「错题本」插件时接上。
3. 复盘/测验的质量取决于当天记录；只有一条训练事件时，模型会明确说「数据太薄」。
4. 两个插件目前都用 `internal=true`，不产生问答，所以问一问的「今日问答」数字不会被它们抬高。
