> 2026-10-23。把 Agent 从「只会读写学习数据」推到「能在本机做受控操作」：
> 打开文件 / 启动程序 / 在一个独立浏览器里打开网址并读回访问记录。
> 起点 2.15.0（582 测试）→ 2.18.0（662 测试全过）。
> 本版包含三个阶段：P19（2.16.0）、P20.1（2.17.0）、P20.2（2.18.0）。

### 真机发现并修掉的两个问题

1. **Windows 11 的记事本 / 计算器 / 画图是 UWP，没有 `.lnk`**：
   开始菜单索引补 `Get-StartApps`，目标写成 `shell:AppsFolder\<AppID>`，仍只由 `os.startfile` 启动。
2. **同 profile 已有浏览器时，新起的 launcher 会立刻退出**（Chromium 单例转发）：
   `_alive()` 改成以 CDP 端口为准；接管实例没有 Popen，关闭时用 `netstat` 按端口反查 PID。

## 2. 明确仍然没做

- **不读网页正文、不截图、不点击/填表**：本版浏览器只负责打开和记录 URL / 标题。
- **不做 iframe 内嵌、不做 WebView2/QtWebEngine 壳**：第三方站点普遍禁止被 iframe，真内嵌留阶段 C。
- **不接管日常浏览器**：独立 profile，不导入密码 / Cookie / 收藏。
- **不批量操作**：每个打开动作都要一次确认；没有「连续打开 N 个标签」的免确认模式。
- **CDP 仍是本机可信模型**：同用户进程理论上能访问随机端口；不开放 WebSocket / `Runtime.evaluate` / `Page.navigate`。

## 4. 升级说明

- **数据只加一张 `browser_events` 表**；回滚到 2.17.0 / 2.16.0 留表不影响，无需迁移。
- `设置.json` 新增 `browser` 块（首次按默认值工作）：
  `enabled` / `record` / `exclude_domains` / `history_days` / `close_on_exit`。
- 浏览器首次启动会在数据目录创建 `浏览器配置/` 与 `浏览器下载/`；不读用户日常浏览器数据。
- PWA 缓存升 **v18**；升级后刷新一次页面。
- 无新依赖；打包体积不变。

## 5. 已知边界

- `--download-directory` 不是 Chromium 官方开关，下载目录不保证生效，可能回退浏览器默认策略。
- Edge 新建标签页 `ntp.msn.cn` 会进历史；嫌吵可加入 `exclude_domains`。
- 标题从空变成实际标题时会多一条记录（口径是「URL 或标题变化才写」）。
- `close_on_exit` 只在后台正常退出时生效；强杀进程不会触发关闭。
