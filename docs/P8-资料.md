# P8 验收记录 · 资料插件

> 日期：2026-10-21 ｜ 版本：`2.2.0` ｜ 状态：资料从 `planned` 变为 `ready`
> 本轮口径（已拍板）：**闭环优先、浏览器上传/拖拽、站内 Markdown 笔记**。

## 一、定位

资料库不是网盘，是学习系统的长期上下文库：导入课件 → 抽正文 → 能搜到段落 →
能挂到问一问 → 能让 AI 生成术语表/提纲。和现有「一次性文档附件」的区别是：
**资料有 id、会长期留在库里、能被检索和反复引用。**

## 二、数据与存储

新增 `materials` 表（`learnsys/core/db.py::SCHEMA`）：

| 字段 | 用途 |
| --- | --- |
| `title / kind / source` | 标题、类型（pdf/docx/pptx/txt/md/note）、来源（upload/note） |
| `path` | 原文相对数据目录的路径；笔记为空 |
| `body` | 抽取正文 / 笔记 Markdown —— **正文只存这一份** |
| `chars / pages / size` | 字数、页数/幻灯片数、原文件大小 |
| `sha256` | 同内容去重（部分唯一索引） |
| `course / tags / status` | 课程、标签、active/trashed |
| `meta_json` | 原始文件名、是否截断等 |

- 原文：`<数据目录>/资料库/原文/<uuid>.<ext>`；删除先进 `回收站/`，可恢复。
- 正文上限 200 万字；FTS 索引（`search_idx`，module=`material`）只是派生索引。
- 备份沿用 `backup.py`：资料原文和 `learning.db` 一起打包。
- 笔记和课件同表：`kind=note`、`path=''`、正文就是 Markdown；术语表也是笔记。

## 三、抽取与页码

`study.extract_document()` 是唯一抽取入口（旧的 `extract_doc_text` 变成薄壳）：

| 类型 | 分页方式 | 页数 |
| --- | --- | --- |
| PDF | 页之间插换页符 `\f` | 真实页数 |
| PPTX | `--- 第 N 页 ---` | 幻灯片数 |
| DOCX / TXT / MD | 不分页 | 0 |

扫描版 PDF 文字太少时直接 400，并在中文提示里说明「需要先 OCR」，不假装读到了正文。

## 四、检索：参考智能旅行的检索层

`learnsys/materials/search.py` 上半段是纯函数，下半段才碰数据库：

1. **候选召回**：整句 + 中文连续段 + 中文二元组 + 英文词，`LIKE` 预筛最多 300 条。
2. **实体整体命中**：查询里的中文段在标题/正文里越长越相关（「子网划分」整体命中 > 只命中「子网」）。
3. **关键词重合**：中文二元组 + 英文单词，算重合比例。
4. **snippet**：命中位置前后取 280 字，压空白；`page_at()` 算回页码。
5. **排序**：标题整体命中 > 正文整体命中 > 标签/课程 > 重合度 > 更新时间；
   同一份资料最多两条，避免一份课件刷满结果。
6. 接口返回 `snippet / page / score`，前端直接显示「命中第 N 页」。

## 五、接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/materials/upload?name=&course=&tags=` | 原始字节上传（非 base64/multipart），抽正文、SHA256 去重 |
| POST | `/api/materials/note` | 新建 Markdown 笔记 |
| GET | `/api/materials?q=&kind=&course=&status=` | 列表 / 检索 |
| GET | `/api/materials/{id}?body=1` | 详情 + 正文 |
| POST | `/api/materials/{id}` | 改标题 / 正文（仅笔记）/ 课程 / 标签 |
| POST | `/api/materials/{id}/trash`、`/restore` | 回收站 |
| DELETE | `/api/materials/{id}` | 彻底删除（只允许回收站里的） |
| POST | `/api/materials/{id}/open` | 用系统默认程序打开原文 |
| GET | `/api/materials/{id}/export` | 导出 Markdown |

## 六、问一问与 Agent

- `ChatRequest.material_id`：后端按 id 取正文，**前端不搬几十万字**；会话消息里记 `material_id` 便于追溯。
- Agent 新增两个读工具：
  - `search_materials(query)`：返回资料 id、标题、页码、命中段；
  - `read_material(id, offset, length)`：按字符偏移顺序读正文。
- 系统提示词要求：引用资料时标资料名和页码，资料里没有就直说没有。
- 问一问附件区新增「资料库」按钮：弹层搜索/选择，选完显示「资料 · 标题 · N 字」；
  保存时只传 `material_id`。`#/ask?material=<id>&prompt=...` 可被资料页深链。
- 资料页「问这份资料」跳到问一问并预填问题；「生成术语表 / 提纲」在资料页内流式生成，
  结果可一键保存为笔记（`internal=true`，不混进问一问列表）。

## 九、已知缺口

1. 扫描版 PDF 没有做 OCR 兜底；会明确拒绝并提示先 OCR。
2. 没有向量库/嵌入模型；检索是 FTS/LIKE + 实体命中 + 重合度。资料上百份后再评估。
3. 没有「选本地文件夹批量导入」；本轮只做浏览器上传/拖拽。
4. 不做站内 PDF 原版渲染，原文用系统默认程序打开。
5. 资料导入/生成暂未接入学习点与时间线事件（避免先定一个会被推翻的数值）。
6. 笔记暂无版本历史；覆盖保存前没有 diff 确认。
