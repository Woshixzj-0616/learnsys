# 学习工作台 2.46.1 发布说明

> 2026-10-29 · 修复每日简报发布时间随机器时区漂移

## 修什么

`services/briefing/feed.py::_parse_time` 原来用 `astimezone()` 把带时区的发布时间
换到**运行机器的本地时区**。本机（UTC+8）看不出问题，但 GitHub CI runner 是 UTC，
同一条 RSS 会差 8 小时，`test_briefing::test_rss_and_atom` 在 CI 上一直失败
（2.43.0 起 CI 红）。

现在统一换算到**北京时间（UTC+8）**再存：

- 中文 RSS 按北京时间读最符合直觉；
- 简报按时间排序不再随机器时区漂；
- 测试断言固定值，本地与 CI 一致。

## 测试

- 全量 1352 个 Python 测试通过；
- 两个结构门禁通过；
- 补充断言：Atom 的 `2026-10-28T02:00:00Z` 固定得到 `2026-10-28 10:00`。
