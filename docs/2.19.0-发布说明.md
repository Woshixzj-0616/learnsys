# 学习工作台 2.19.0 发布说明

> 2026-10-24。把「问一问」的回答从「每次一份讲义」改成「默认短答、按需展开」。
> 起点 2.18.0（662 测试）→ 2.19.0（664 测试全过）。

## 1. 为什么改

10-23 的真实对话实测：讲解模式 41 条回答平均 **2637 字**（提示词原目标 1200–1800），
**36/44 带代码块**、**39/44 结尾带「想一想」**；用户说「你以后用 C 写」时回了 4466 字，
还重做了上一题。用户的反馈是：太长，代码和提问每次都出现会降低兴趣；
但明确要求出题或看源码时仍应照做。

根因：提示词里「充分回答 / 把原理讲透」与「1200–1800 字」互相打架；
「最后给想一想 2–3 个」是无条件要求；没有任何按需触发的机制。

## 2. 这次做了什么

| 改动 | 落地 |
|---|---|
| 篇幅四档自适应 | 名词/事实 ≤300、机制 ≤800、排错/对比 ≤1500、明确说「详细讲讲」才不限 |
| 代码默认关闭 | 只有「给代码 / 写一段 / 实现一下 / 源码 / 跑一下」才贴；贴报错允许引用 1–5 行 |
| 出题默认关闭 | 只有「出题 / 考考我 / 问我几个问题」或测验模式才出 |
| 偏好只回一行 | 「以后用 C」→ 存记忆 + 一行确认，不重做上一题 |
| 历史长回答不传染 | 系统提示明确「历史里的长回答不代表本轮篇幅标准」 |
| 记忆冲突清理 | `agent_memories` #1（C++ 优先）归档；#5 改为「需要写示例代码时默认用 C」 |
| 自检重写不扩写 | `REWRITE_SYSTEM` 明确不扩写、不加代码块、不追加提问 |
