# 后台守护与「启动后台」——验收记录（2.10.1）

## 问题

任务栏 / 开始菜单点的是 **PWA 网页壳**；Service Worker 把壳缓存住了，所以后台 exe 退出后
页面照样能打开，只显示「后台未连接」。浏览器不能启动本地进程，点图标永远拉不起后台。

## 根本原因

- 后台只靠 Startup 里的 `--background` 拉一次，中途退出没有任何兜底；
- 任务栏 PWA 和后台是两个东西，「点开」不等于「后台在跑」；
- 页面断线后只有一句「重启一次」，重试还要手点。

## 改法（三处，一份判断）

| 位置 | 做什么 |
|---|---|
| `learnsys/ask/guard.py`（新） | 计划任务 `LearnSysGuard` 每分钟跑 `exe --watchdog`；有手动退出标记 / 后台健康 → 立刻退出，否则按后台模式拉起 |
| `learnsys/ask/app.py` | `--watchdog` 入口；托盘「退出」落标记；托盘菜单「后台守护」开关；任何正常启动清标记 |
| `learnsys/ask/shortcuts.py` | 登记 `learnsys://` 协议（HKCU，无需管理员）→ `exe --background` |
| `web/js/shell.js` | 断线页 3 秒自动重试 +「启动后台」按钮（跳 `learnsys://start`） |
| `web/sw.js` | 缓存版本 v5 → v6 |

判断只在 `guard.should_start()` 一处：`not 手动退出 and not 后台健康`。
用户自己点过「退出」就不再拉起；开机自启（`--background`）会清掉标记，新的一天照常起来。

## 验证证据

| 场景 | 结果 |
|---|---|
| 后台健康时守护 | 441ms 退出，进程数不变（PID 2932） |
| 强杀后台后跑守护 | 自动拉起，8765 恢复，PID 19788 |
| 写「手动退出」标记后跑守护 | 退出码 0，8765 无监听、进程数 0 |
| `learnsys://start`（等价点按钮） | 后台起来，退出标记被清 |
| 断线页面（Chrome 实测） | 显示「连不上本地服务」+ 倒计时 + 两个按钮 |
| 点「启动后台」 | exe 起来，页面 3 秒内自动重连，今日页恢复 |
| 计划任务 | 每分钟自动触发，`LastTaskResult=0`；健康时不留下多余进程 |
| 笔记本电池 | schtasks 默认「用电池不启动」，已改为允许（真踩过） |

`python -m unittest discover -s tests -p "test_*.py"` → **430 tests OK**。

## 已知限制

- PWA 不能零点击拉起后台，靠「计划任务 1 分钟内自愈 + 页面按钮」两段兜底；
- 进度条式的最坏情况：后台在两次检查之间刚退出，页面要等下一次检查或你点一下；
- 计划任务指向当前 exe 路径，安装目录搬走后需要重新打开托盘开关（会自动重建）。
