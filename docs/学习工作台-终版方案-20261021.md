# 学习工作台 · 终版方案（讨论稿）

> 2026-10-21。基于 `学习工作台-方向决策-20261021.md` 与 P1–P11 现状，
> 对照「智能旅行」可复用资产、外部产品与算法后整理。
> **本文只定方向、顺序和验收，未改任何代码。**

## 0. 一句话

方向不变：**不做类 OS，做「学习上下文工作台 / 学习 Agent 平台」**。
但要补三根梁：**结果资产化、上下文协议化、复习调度科学化**；平台化继续让位于「六级 1–2 周实验」这道闸门。

## 1. 判断：原方案哪里不够

| 原方案 | 问题 | 后果 |
|---|---|---|
| Context + Service + Surface | 只有能力分层，没有「今天做什么」的闭环 | 功能越堆越多，日常入口仍是统计页 |
| AI 分析/翻译结果存前端 state | 结果不是资产，收起即丢、重开要重跑 | 六级第 1 条问题的根因 |
| `ChatRequest.context` 是自由字符串 | 每个页面自己拼上下文，Agent 读不到结构化状态 | 无法复用、无法审计、无法跨插件 |
| 错题复习 1/3/7 固定间隔 | 不按个人遗忘曲线，成熟后复习过多或过少 | 复习负担与留存都不最优 |
| 有测试、有验收记录 | 没有 trace、没有成本账、没有 golden set | 回归只能靠人肉，模型/提示词一改就说不清 |

## 2. 我补的 7 条

### 2.1 结果资产化（最高优先级）

新增一张表，而不是继续用前端 `state.analysis`：

```
service_results(
  id, kind, target_type, target_id,
  context_hash, prompt_version, model,
  status, content, error,
  tokens_in, tokens_out, cache_hit, ms,
  created_at, updated_at
)
UNIQUE(kind, target_id, context_hash, prompt_version)
```

- `kind`：analyze / translate / define / explain / quiz / grade / summary
- `status`：pending / streaming / done / error / canceled
- 前端「打开上次结果」、失败重试、去重、离线查看都从这张表来
- 会话消息只存 `result_id` 引用，不复制正文 —— 天生一份
- **六级第 1 条不是修 UI 状态机，而是把「分析结果」变成可寻址的对象**

### 2.2 上下文协议化（ContextSnapshot）

```json
{
  "surface": "cet6 | materials | wrongbook | ...",
  "object": {"type": "sentence", "id": "paper/item/sentence", "title": "..."},
  "selection": {"text": "...", "start": 0, "end": 0},
  "surrounding": {"before": "...", "after": "...", "page": 3},
  "learning_state": {"done": 12, "loops": 3, "plays": 5, "tags": ["细节"]},
  "recent_actions": ["play", "loop", "mark"],
  "provenance": {"source": "cet6", "captured_at": "...", "ttl": 300}
}
```

- 服务端统一装配；前端只传 ID 和选区，不搬大段正文
- 顶部「上下文条」可见、可删、可固定 —— 避免「魔法」和错误不可见
- 按选区长度给动作，而不是一长串菜单：
  - 1–3 个词 → 查词 / 翻译
  - 一句 → 翻译 / 语法 / 解释
  - 一段 → 摘要 / 出题 / 存笔记
- Agent 侧补 `get_cet6_context` 工具（现只有 7 个工具，缺这个）

### 2.3 Service 统一层

`translate / define / explain / analyze / quiz / grade / summarize` 走同一个入口：

- 统一缓存、取消、超时、降级、成本计量
- UI 和 Agent 共用，插件不再各自调模型
- 查词优先本地词典，查不到再走模型；结果进同一张 `service_results`
- 每个结果带出处：资料 id + 页码 / 六级试卷 + 题型 + 句号

参考 Readwise Quick Lookup 的三页签（Define / Lookup / Translate）和 LingoLens 的「带周边上下文 + 30 分钟缓存」。

### 2.4 学习闭环（今日计划）

今日页从「统计」升级为「3 张行动卡」，最多 3 张：

1. 到期错题（FSRS 排程）
2. 昨天没消化的资料 / 听力断点
3. 昨日薄弱点 → 一道小题

不做强制日程、不做打卡压力；只回答「现在最值得做的三件事」。

### 2.5 复习调度换 FSRS

- 用 MIT 的 `py-fsrs`；错题、生词、后续卡片统一 `review_state + review_log`
- 字段：stability / difficulty / due / last_review / reps / lapses / state
- 目标留存 0.9；约 1000 次复习前用默认参数，之后按月优化
- 旧 1/3/7 数据保留兼容，不迁移丢历史
- **BKT 先不做**：FSRS 管「何时复习」，BKT 管「懂没懂」；BKT 需要知识点标签和足够答题数据，放到 P16 可选

### 2.6 观测、成本与评估

- 每个请求一行 trace：surface → 上下文摘要 → 工具调用 → 模型 → token / 缓存命中 / 耗时 → 状态
- 用量落库（现在 `usage` 拿到但没存），按天显示花费
- 延迟预算：首 token < 2s，完整回答 P95 < 15s；超时走降级链
- 降级链：完整答案 → 部分 + 明确标注 → 「不知道 + 现在能做什么」
- 建 20–30 题 golden set（六级分析、资料问答、错题复习），改提示词/模型前后重放

### 2.7 单一真源与工程纪律

- **P11 先收尾**：49 个改动 + 7 个新文件未提交；commit → tag 2.5.0 → 打 zip → 真机复核
- 六级迁移桥现在是 localStorage ↔ learning.db 双写；迁移完成后 **HTTP 成为唯一写入口**，file:// 只读/导出
- 六级源码/产物不在 git，风险高：进私有仓或 learnsys 子目录（音频、试卷不进 Git）
- 补 `docs/README.md`（当前状态 + 路线图 + 账本索引）和 `AGENTS.md`（构建/测试/验收命令）
- 流程照搬智能旅行：**施工单 → 先必红 → 实现 → 跑满 → 单提交 → 停下汇报**

## 3. 可复用清单

### 3.1 智能旅行：搬判据，不搬整套

它有 583 个 Python 文件、306 个测试文件；learnsys 的 Agent 循环、单库、插件、PWA 都已经有了。**整套平移会制造第二套架构**，违背「天生一份」。

| 值得搬 | 具体做法 | 落点 |
|---|---|---|
| 分层判据 | LLM 负责判断，代码负责判定与装配；输出结构化、可校验 | 出题、判错、排程、引用回核 |
| 上下文注入纪律 | system 头放稳定项，消息尾放易变项；`size_of` 计量、工具回执截断、历史滚动摘要 | Agent 上下文层 |
| 观测与成本 | trace id、每请求流水、`usage_brief`（含缓存命中）、脱敏、软失败归口 | 轻量版即可，不必搬告警 |
| 检索判据 | 实体整体命中、关键词重合、snippet 带页码 | 已在 `materials/search.py`，继续用 |
| 数据层习惯 | WAL、`write_txn` 写锁、幂等补列、`.backup` 在线备份 | 对照现有实现补缺 |
| 工程纪律 | 批次门、单一真源检查、文档新鲜度、依赖方向 | 流程照搬 |

**不搬**：旅行业务模块（行程/分账/高德/景点抓取）、整套 orchestrator、插件注册表（learnsys 已有自己的 `plugin.json` 形状）、2600 个测试。

### 3.2 外部产品与算法

| 来源 | 可复用 | 怎么用 |
|---|---|---|
| Readwise Ghostreader / Quick Lookup | 选区大小决定动作；Define / Lookup / Translate 三页签；库级问答带引用；结果可存为笔记 | 划词浮层 + 资料库全局问答 |
| LingoLens | 选区周边上下文、30 分钟缓存、多模型预设、生词本导出 | 翻译服务与生词本 |
| FSRS | 同等留存下少 20–30% 复习量；`py-fsrs` MIT | P14 替换 1/3/7 |
| BKT | 掌握概率、可解释；适合「懂没懂」 | P16 可选，先有知识点标签 |
| Context engineering | 压缩、工具结果清理、即时检索、稳定前缀吃缓存、子 Agent 只回摘要 | Agent 长会话与深分析 |

## 5. 六级实验成功线（先写死，再开始）

14 天内：

- ≥ 10 天实际使用
- 使用日里每天 ≥ 3 次「带上下文提问 / 划词翻译」
- 分析结果 0 丢失；重复请求 < 10%
- 首 token < 2s，完整回答 P95 < 15s
- 抽样 20 次回答，引用当前句/试卷正确 ≥ 18 次
- 主观：如果撤掉这个功能，会想念（≥ 4/5）

**不达标就停止平台化**，继续打磨六级单点功能，不写 ContextSnapshot 抽象层。
