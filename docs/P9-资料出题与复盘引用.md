# P9 · 资料出题与复盘引用

> 日期：2026-10-21 ｜ 版本：`2.3.0` ｜ 状态：完成
> 承接 P8：让资料库不只“能查”，还能直接进入测验与复盘。

## 一、从资料出题

### 入口

资料详情页新增「用这份资料出题」→ `#/quiz?material=<id>`。

### 后端

- `GET /api/materials/{id}/quiz-prompt`：
  - 只允许 `status=active` 的资料；
  - `study.build_material_quiz_question()` 生成提示词（口径只在这一处）；
  - 正文按页截前 **12000 字**（PDF 的 `\f` 换成「第 N 页」），不够时提示模型调用
    `read_material(material_id=...)` 继续读；
  - 返回资料元信息（不含正文）+ 提示词，前端不搬几十万字。
- 提示词要求：只基于这份资料、一次只出一题、`【第N题】`/`【批改】` 标记、
  判错先 `save_wrongbook`。

### 前端

- 测验页识别 `material` 查询参数：
  - 标题改成「用《资料名》出 5 道题」；
  - 统计 chips 换成「资料 / 类型 / 规模」；
  - 按钮改成「从这份资料出 5 道题」；
  - 返回入口变成「返回资料」。
- 开始测验写两条事件：`quiz/quiz`（标题带资料名，meta 带 `material_id`）与
  `materials/quiz`。
- 作答轮不挂 `material_id`（避免重复塞正文），模型用 `read_material` 自己翻。

## 二、复盘引用资料

- 新增统一事件函数 `store.add_event()`；`/api/events` 也改走它。
- 资料相关事件：
  - `materials/open`：打开原文；
  - `materials/ask`：用资料开始一轮问一问（只在新建会话时记一次，不刷屏）；
  - `materials/quiz`：从资料开始测验。
- `GET /api/study/today`：
  - 汇总今天资料事件，例如「资料：子网课件.md（资料出题 1 次）」；
  - `stats.materials` 给出今天资料使用次数；
  - 复盘页统计 chips 增加「资料」。
- 资料事件计入连续学习天数（不额外加学习点）。

## 三、实测

1. 全量回归：`Ran 298 tests ... OK`。
2. 真实模型资料出题：
   - 资料页点「用这份资料出题」→ 测验页显示资料信息；
   - 出题 `/27 的掩码、地址总数、可用主机数`，确实来自资料正文；
   - 故意把掩码答成 240，模型判错并讲清 /27 vs /28，自动收进错题本；
   - `/api/study/today` 出现「资料：…（资料出题 1 次）」，`stats.materials=1`。
3. 验收产生的资料、事件、会话、错题已按 id 精确删除。

## 五、已知缺口

1. 错题本条目还没存 `material_id`，暂时不能按资料看薄弱点。
2. 复盘只汇总资料事件标题，没有回链到资料页。
3. 资料事件暂不加学习点（避免先定一个会被推翻的数值）。
4. 超长资料（>12000 字）依赖模型主动 `read_material`；模型不读时只能覆盖前 12000 字。
