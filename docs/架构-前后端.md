# 学习工作台 · 前后端架构索引

> **改代码前先查这张索引**：先定位到模块，再动手；不要在一个几千行文件里找。
> 本文件是**目录与改动入口的唯一索引**；阶段计划看 [施工单/00-阶段总览](施工单/00-阶段总览.md)，
> 方向看 [终版方案](学习工作台-终版方案-20261021.md)。
> 体量红线只在 `tools/arch_report.py` 定义，本文件不抄数字。

## 0. 一句话

一个 Qt 主进程（托盘 + 快捷栏）里跑一个 FastAPI 线程；Web 工作台、快捷栏、六级 iframe、
MCP 客户端共用同一套 Agent、同一套数据层、同一个 `learning.db`。

## 1. 运行拓扑

```
Windows 桌面
├─ 学习工作台.exe / python -m learnsys.ask.app
│  ├─ Qt 主线程
│  │  ├─ 快捷栏 AskBar（屏幕上方一条，Alt+Q 框选）
│  │  ├─ 托盘 / 热键 / 录制 / 截图 / 定时器
│  │  └─ 启动 FastAPI 线程（127.0.0.1:8765，占用退 8766）
│  ├─ FastAPI 线程  /api/*  /web/*  /cet6/*
│  ├─ Web 工作台（Edge/Chrome --app 或 PWA）
│  │  └─ 壳层 shell.js + 每个插件一页
│  ├─ 六级精听工作台（iframe，源码在 D:\cet6_tool）
│  └─ MCP stdio 服务（Claude Code / Codex 只读接入）
└─ D:\学习系统\learning.db（SQLite WAL）
```

## 8. 分层纪律（沿用阶段总览）

| 层 | 只做 | 不做 |
|---|---|---|
| routes | 参数校验、鉴权、拼响应、SSE | 写 SQL、拼提示词、算业务规则 |
| services | 业务用例、缓存、状态机、任务调度 | 直接碰 FastAPI `Request` |
| store | SQL、事务、行 ↔ dict | 调模型、判断业务 |
| core / browser | 建表、连接、路径、浏览器定位 | 业务逻辑、导入上层包 |
| 前端 | 展示与交互 | 自己拼大段上下文（传引用） |

**反向依赖零容忍**：core/store/browser 不得导入 services/agent/ask/server；
agent/services 不得导入 ask/server。门禁零白名单，出现反向依赖就改依赖。

## 9. 体量红线与分层门禁

红线只在 `tools/arch_report.py` 定义（Python/JS 与 CSS 各一档，含排除目录）。
分层规则只在 `tools/layering_report.py` 的 `RULES` 定义。
`tests/test_architecture.py` 同时调用两者：超线或出现反向依赖即测试失败。

```bash
.venv/Scripts/python.exe tools/arch_report.py           # 报告 + 观察区
.venv/Scripts/python.exe tools/arch_report.py --check   # 超线返回 1
.venv/Scripts/python.exe tools/layering_report.py       # 分层报告
.venv/Scripts/python.exe tools/layering_report.py --check  # 反向依赖返回 1
```

观察区（≥400 行）由脚本自动列出；改到观察区里的文件时，优先判断这次改动是否顺手拆分。
名单和行数不在文档里写死，避免和代码漂移。

## 10. 改代码的固定流程

1. **查索引**：在第 7 节找到入口；跨层改动先确认职责边界。
2. **单一落点**：同一规则只改一处（例如 XP 只在 `routes_data/overview.py::XP_RULES`）。
3. **先失败测试，再实现**：至少覆盖改动的边界（中文错误、空数据、旧库）。
4. **跑全量**：
   ```bash
   .venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -p "test_*.py"
   node --test web/tests/context.test.mjs
   .venv/Scripts/python.exe tools/arch_report.py --check
   .venv/Scripts/python.exe tools/layering_report.py --check
   ```
5. **页面实测**：起 8799 源码后台，用 Chrome DevTools MCP 打开相关插件页，确认无控制台错误。
6. **更新本文件**：新增插件 / 表 / 路由 / 拆分模块时，同步第 2–7 节。
7. 发版前重打 exe（PyInstaller 会按 `__init__` 的显式导入收集新包）。

## 11. 已知边界

- 六级精听**真源**仍是 `D:\cet6_tool`；本仓库 `cet6-src/` 只是文本快照，提交前跑 `tools/sync_cet6_src.py`。
- 六级分析的唯一真源是 `service_results`（`/api/cet6/analysis`）；`cet6_progress` 只存
  done/tags/note/loops/plays，不要给它加 analysis 列。
- 六级双写退休的硬开关是六级前端构建常量 `WB.FLAGS.retired`（`workbench_src/js/00-core.js`）；
  改 true 后必须重建工作台 HTML 并同步快照。`file://` 退休后只读，HTTP 成为唯一写入口。
- 整卷审计的空快照保护：本地 4 个同步字段全空、服务端有进度时，`/api/cet6/sync-paper` 返回 409
  并记 `blocked_empty`，前端先从 `/api/cet6/state` 恢复再重试一次。
- 深度分析的 API 模式只在有 key 时可用；命令模式不经过 shell，但命令本身由用户配置。
- 模型路由是显式映射，不做自动按成本/可用性选择。
- `learnsys/ask/bar.py`、`learnsys/ask/app.py` 是**兼容门面/入口**，真正逻辑在子包；
  新代码不要往门面里加逻辑。
- 工作台浏览器用独立 profile（`<数据目录>/浏览器配置`），只管理自己 Popen 的 PID；
  CDP 只开放 `/json/list`、`/json/new`、`/json/close`，不开放 WebSocket /
  `Runtime.evaluate` / `Page.navigate`；端口、PID、profile 路径不返回前端。
  本机同用户进程理论上能访问 CDP 端口 —— 这是「本机可信」威胁模型，不是多用户隔离。
- `store` 的全局写锁在 `store/_base.py`，子模块不得各建一把锁。
- `routes_agent.agent` / `routes_agent._CONFIRM` / `routes_agent._trace_event` 是测试兼容转发，
  修改这些符号时先跑 `test_server_v2`、`test_agent_context`、`test_agent_p16_obs`。
