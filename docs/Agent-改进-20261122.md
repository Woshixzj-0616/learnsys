# 学习工作台 Agent 改进（2026-11-22）：快答 + 深入按需 / 公式可读 / 逐轮可观测

> 目标：不把默认体验拖慢；难题给用户一个显式的「深入讲」；快捷栏公式不再乱码；
> 每一轮都有可核对的运行流水。设计原则参考智能旅行的
> `web/js/pages/agent-design-data.js`（控制流归代码、打回、上下文预算、一处为源、先 shadow 后 on）。

## 一、改之前的证据

| 问题 | 证据 |
|---|---|
| 难题不深入 | 生产 `speed=balanced` + `auto_route=shadow`；372 次有流水的路由里建议深入 35 次、**实际深入 0 次**；30 天 `deepseek-v4-pro` 只调用 1 次 |
| 答案不稳 | 2026-11-22 15:40「答案选 C……我上面写的 C 是错的」；15:43「选 C……等一下……答案是 D」；思考关着，模型只能在正文里改口 |
| 慢 | 快捷栏近 7 天 129 条：首字 P50 0.79 秒 / P95 1.3 秒；完整答案 P50 2.9 秒 / P90 5.1 秒 / P99 28.8 秒 / 最慢 41 秒；快捷栏不写 `agent_runs`，无法归因 |
| 公式乱码 | 快捷栏 `QTextDocument.setMarkdown` 不认 LaTeX；实测 `$H(K)=3K \bmod 11$` 原样显示；网页有本地 KaTeX，只有原生快捷栏坏 |

## 二、设计决定

1. **快答优先，深入按需**：不全局打开自动路由；用户点「深入讲」时，这一轮用
   这一轮开思考，按讲解口径回答。模型取 `strong_model`；生产已留空 = 主模型 + 思考
   （6 题 A/B 全对、平均约 3.8 秒；填 `deepseek-v4-pro` 也是 6/6，但平均约 9.5 秒）。
2. **一处为源**：
   - 路由决策只在 `agent/router.py`；请求级开关是 `AgentRequest.deep`。
   - 流水折叠只在 `agent/run_record.py`（服务端和快捷栏共用）。
   - 公式转换只在 `ask/quickbar/math_text.py`（Qt 端唯一入口）。
3. **打回只提示、不改写**：快捷栏答完后用 `agent/answer_audit.py` 做结构检测；
   命中「先给一个答案、后面改口」时，只在答案底部挂「深入复核」入口。
4. **先 shadow、再 on、留回滚**：默认行为不变；`deep` 默认 False；公式转换是纯函数；
   旅行工具只读；资料导入只增不删。

## 三、改动清单

### 1. 请求级 deep

- `learnsys/agent/turn.py`：`AgentRequest.deep: bool = False`。
- `learnsys/agent/router.py`：`decide(..., force_deep=False)`；最顶层返回
  `tier=deep`、`model=strong_model or model`、`thinking=True`、`concise=False`、
  `reason="用户点了深入讲"`。优先级：显式深入 > 手动 routes > 速度档 > ops > 自动路由。
- `learnsys/agent/loop.py`：`_plan_config` 传 `force_deep`；route trace 写
  `forced="request_deep"`；`deep=True` 且 mode 是 quick/quiz 时，提示词与工具按
  `explain` 走，避免「150 字 / 一次一题」和深入档冲突。
- `learnsys/agent/finish_turn.py`：`done` 事件增加实际 `model`，快捷栏以它为准。
- `learnsys/agent/prompts.py`：
  - 基础纪律增加「用户说没懂/再讲/为什么 → 先点出卡点、换讲法」；
  - 深入档增加「先给判断依据和前提，再给结论；不要边写边改口；两种结论并列」。

### 2. 快捷栏「深入讲」

- `ask/quickbar/workers.py`：
  - `_AskWorker._deep`（属性赋值，不改构造函数，兼容旧 FakeWorker）；
  - `deep_suggested` 信号：route 建议 deep 时发 `complex`；答案改口时发 `audit`；
  - 每轮写一条 `agent_runs`：实际模型、首字、总时长、steps/model_calls/tool_count、
    usage/cost、trace、error；失败只记诊断，不影响回答。
- `ask/quickbar/streaming.py`：
  - 快照上一道真正的用户问题（文本/图/上下文），`_start_deep()` 复用它；
    深入轮统一 `mode="explain"`，图片只给模型看、不重复归档；
  - 答案底部 `deep:<轮次>` 链接：旧答案上的入口不能深入新题；
  - `_finish` 把 `model/first_ms/run_id/deep` 放进 `answered`。
- `ask/quickbar/actions.py`：⋯ 菜单常驻「深入讲上一题」；复制答案与显示一致（公式已转）。
- `ask/desktop/sessions.py`：`add_ask` 用本轮实际模型，补 `first_ms`。

### 3. 公式兜底

- 新 `ask/quickbar/math_text.py`：
  - 逐行状态机跳过 ``` / ~~~ 围栏（未闭合也不误伤）和行内反引号；
  - 只转闭合的 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；货币 `$5` / `$5 and $10` / `\$` 不转；
  - 常用 LaTeX→Unicode：希腊字母、关系/集合/箭头、`\sum/\int/\nabla`、
    `\lceil/\rceil`、`\frac`、`\sqrt`、`^`/`_`；复杂环境降级为线性文本，不吐反斜杠。
- `streaming.py` 渲染前调用 `math_text.render`；`actions.py` 复制同样转换。

### 4. 逐轮观测

- 新 `learnsys/agent/run_record.py`：`TRACE_KINDS` / `clip` / `trace_event` 唯一落点；
  `server/routes_agent/{common,state}.py` 只做 re-export，测试不需要改。
- 快捷栏 worker 在 `finally` 写一条 `agent_runs`（`conversation_id=0`），
  done / error / cancel 三条路径都只写一次。

### 5. 智能旅行整合

- **设计原则**：本文第二、三节；打回 → 改口审计；分项 → 逐轮流水；一处为源 → 三个唯一落点。
- **资料**：新 `tools/import_travel_architecture.py`（默认 `--dry-run`，`--apply` 才写），
  导入《症状与排查》《行为开关总表》《架构总览》，课程「智能旅行后端」，按 sha256 + 同名跳过；
  写库前备份。
- **工具**：新 `agent/tools/travel.py::travel_trace_summary` + `schemas_travel.py`，
  只读查询 `store/agent_trace` 的最近/最慢/单条 trace；不返回用户名，事件最多 30 条；
  缺库回中文原因并标 `ok=False`。不做旅行对话工具（已有 travel-agent 页面直接对话）。

## 五、回滚

- `deep` 默认 False；快捷栏不点「深入讲」就是原来的快答。
- 两条提示词纪律（没懂换讲法 / 不要边写边改口）是**全局**的；要完全回到旧口径，
  删掉 `prompts.py` 里对应两行即可，不影响路由与流水。
- 公式转换只影响 Qt 渲染；去掉 `streaming.py` 里的一行调用即可恢复。
- 流水写入是 best-effort；`agent_runs` 多出的 `conversation_id=0` 行可按模型/时间清理。
- 旅行工具只读；资料导入同名/同内容跳过，不做删除/覆盖。
- `auto_route` 仍保持 `shadow`；`speed` 仍是 `balanced`。
- 生产 `strong_model` 已留空（深入讲 = 主模型 + 思考）；要换回强模型，
  在设置里填 `deepseek-v4-pro` 即可，不需要回滚代码。
