# 学习工作台 2.33.1 · DeepSeek 的 key 直接用来看图

> 2026-10-26 · 生产 8765 已运行 2.33.1
> 上一版 2.33.0（Agent 补齐学习数据域与能力体检）

## 结论先说

**DeepSeek 的 key 现在就是视觉 key**，不用再单独申请、不用填两处。
实测（2026-10-26）：

| 模型 | 图片输入 | 实测结果 |
|---|---|---|
| `deepseek-flash` | 支持 | 正确读出「黄色圆形、紫色三角形、绿色箭头指向右」 |
| `deepseek-v4-pro` | **不支持** | 返回「抱歉，我无法查看这张图片」 |

因此自动复用主配置时**优先用快模型**（默认就是 `deepseek-flash`），
并把「模型说看不到图」当失败处理，自动退回 OCR，而不是把道歉当答案。

## 改了什么

- `llm/config.py`：`vision` 段留空时，视觉自动复用主模型的 base / key，
  模型取 `fast_model`；显式填了 `vision.base_url` 或 `vision.api_key` 则完全按填写走。
- `agent/vision.py`：同时支持两种协议 ——
  - DeepSeek / Claude：Anthropic Messages（`/v1/messages`，`x-api-key`）；
  - GLM / Qwen 等：OpenAI 兼容（`/chat/completions`，`Bearer`）。
  DeepSeek 看图时关闭思考，避免正文被 reasoning 截断；识别到「无法查看图片 /
  图片格式不受支持」时抛中文错误，交给 OCR 兜底。
- 设置页（网页 + Qt）：文案改为「留空 = 复用主模型」；
  密钥提示显示「跟随主模型 key」；复用时不回填地址/模型，避免一保存就把 fallback 写死。
- 设置页「测试视觉连接」改为调用正式实现，不再自己拼一套 OpenAI 请求。

## 注意

- 如果你的主模型被设成 `deepseek-v4-pro`，视觉仍会自动用 `fast_model`
  （默认 `deepseek-flash`）；把 `fast_model` 也改成不支持的模型时，截图会退回 OCR。
- 想用 GLM / Qwen 的视觉能力，照旧在「视觉模型」里单独填地址、key、模型即可。
