## 一、产品方向调整

用户要求把学习系统做成**综合舞台**：问一问、六级精听都是插件；平台要对网络工程专业学生友好，
并且能激发动力。本轮据此把「模块」正式升级成「插件」，并补了一个网工训练场。

| 变化 | 落地 |
| --- | --- |
| 插件化 | `learnsys/plugins/<id>/plugin.json` 一个插件一份清单；壳层只读 `/api/modules` |
| 舞台首页 | 学习台：今日学习点、连续天数、等级、插件卡片、时间线、专注、成就 |
| 网工插件 | 6 条主线 × 3 张训练卡；开练 = 记事件 + 题目预填进问一问 |
| 激励系统 | 学习点、等级（网络小白 → 系统架构师）、连续天数、10 个成就 |
| 插件中心 | 启停、版本、分类、入口；开关写回 `设置.json` |
| 首次引导 | 没配模型时首页显示「三步跑起来」面板 |

## 三、学习点 / 等级 / 成就

规则只在 `learnsys/server/routes_data.py::XP_RULES` 一处：

| 行为 | 学习点 |
| --- | --- |
| 问答 | 10 |
| 转写 | 5 |
| 六级断点 | 8 |
| 网工训练 | 15 |
| 专注 1 分钟 | 1 |
| 收藏 | 3 |

- `GET /api/overview` 返回今日 XP / 目标、累计 XP、等级、连续天数、周统计、10 个成就。
- 等级门槛：300、500、700…（逐级 +200）；标题走网工成长线。
- 连续天数：问答 / 转写 / 六级 / 网工事件 / 录制任一项算一天。

## 四、实测证据

### 舞台与训练场

- 学习台真实数据：Lv.3「寻址新手」、累计 810 点、连续 1 天、成就 2/10；插件卡片 3 个。
- 网工训练场：18 张卡全部渲染；点「开练」→ `POST /api/events` 成功 → `#/ask?prompt=...`，
  输入框预填 120 字题目，状态行提示「题目已填好」。
- 训练后 `/api/overview`：今日 `netlab=1`、今日 XP `15`、累计 XP `825`、等级进度更新。
- 测试事件随后按 `id + 时间戳` 精确删除，未留假进度。

### 插件中心

- 页面显示 10 个插件、6 个可用、10 个启用。
- 关闭「网工训练场」→ 侧栏立即消失；再打开 → 恢复。两次都写回 `设置.json` 的 `modules`。
- 控制台 0 error / 0 warn。

### 模型未配置的首次引导

- `today.js` 仅在 `/api/settings.agent.ready === false` 时显示三步引导；
  已配置模型的机器上隐藏（本轮实测 `onboardingHidden=true`）。

### 打包（T5.1）

- `问一问.spec` 收录 `learnsys/plugins/`；重打包后 `_internal/learnsys/plugins/` 下 10 个目录齐全。
- 用**临时数据目录**启动 `dist\问一问\问一问.exe`（不碰用户真实数据）：
  - `/api/health`：`version=2.0.0`、`ok=true`、`quickbar=true`、`db=<临时目录>\learning.db`
  - `/api/plugins`：10 个插件，顺序 `today → ask → netlab → cet6 → … → plugins`
  - `/`：200
- 打包过程中发现并修了一个真机 bug：无监听时 Windows 上 `connect` 可能**超时而不是拒绝**，
  原来的 `port_free()` 会把空闲端口判成占用，导致 exe 永远不起后台。
  修法：超时后再用 `SO_EXCLUSIVEADDRUSE` 做 `bind` 探测；新增 `PortProbeTest` 锁住。

## 五、已知缺口

1. 复盘 / 测验 / 错题本 / 资料仍是 `planned`，只在侧栏占位。
2. 首次引导是首页面板，不是独立向导；模型、数据目录的修改仍在设置页。
3. 网工训练场的内容写在 `web/js/pages/netlab.js`，加卡要改前端源码；后续可拆成 `plugin.json`
   旁边的 `content.json`。
4. 发布未推 GitHub Release / 未打 tag（需要用户确认后再对外发布）。
5. 没有在「干净 clone + 无 key + 无 Codex」的独立账户下完整跑一遍；本轮用临时数据目录模拟了首次启动。
