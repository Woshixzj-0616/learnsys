### fact-net-tcp-handshake · 通过
- **问**：用一句话解释 TCP 三次握手
  **答**：**TCP 三次握手是通信双方各确认一次「我发的对方能收到、对方发的我能收到」后才建立连接，用三次而不是两次是为了防止旧的重复请求造成假连接。** 要点： - 第一次（SYN）：客户端发送 `seq=x`，服务端由此确认「客户端→服务端」通。 - 第二次（SYN+ACK）：服务端发送 `seq=y, ack=x+1`，客户端确认两个方向都通。 - 第三次（ACK）：客户端发送 `ack=y+1`，服务端确认「服务端→客户端」通；到此双方各自的发送能力都得到对端确认。 容易出错的地方：第三次握手的 ACK 报文里，从这之后就可以携带数据，因此握手结束后才能真正开始传数据；两次握手无法让服务端分辨「这次 SYN 是新的，还是网络里滞留的旧 SYN」，这正是第三次握手的核心价值。 （这属于传输层。你最近的错题里没有 TCP 相关记录，网络这块练没练我看不到。）

  **答**：先说清楚：Nginx 有两个动作，**reload（不断连接重新加载配置）**和 **restart（停止再启动）**。改完配置一般只用 reload，restart 会断掉正在处理的连接。 **改完配置的标准流程（推荐）** ```bash sudo nginx -t # 先测语法 sudo nginx -s reload # 通过就热加载 ``` `nginx -t` 预期输出两行：`nginx: configuration file /etc/nginx/nginx.conf test is successful`。只要这句没出现，`reload` 会静默失败或按旧配置继续跑，别跳过这步。reload 之后可以 `sudo tail -n 20 /var/log/nginx/error.log` 看有没有残留错误。 **用 systemd 管理时（Ubuntu/Debian 常见）*

### multi-cert-L · 通过
- **问**：我说的是证书签名里面的L是什么
  **答**：证书签名里出现 L，最可能指**证书主体中的 L 字段（Locality，所在地/城市）**，不是密码学里的某个参数。 - **在证书 DN 里**：Subject 的 RDN 常见缩写——C=国家、ST=省/州、**L=Locality（城市）**、O=组织、OU=部门、CN=通用名。比如 `C=CN, ST=Zhejiang, L=Hangzhou, O=XXX, CN=example.com`。 - **它不是签名算法的参数**：和签名相关的算法标识里没有“L 表示长度/阶”这种字段，那是教材里 ECDSA 的写法，不会出现在证书 DN 中。 判断方法：如果这个 L 出现在证书的 Subject/Issuer 一栏，就当“城市”读；如果出现在算法参数说明里，则要按具体上下文看。你看到的那一行原文贴出来，我可以确认。
