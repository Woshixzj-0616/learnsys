# P26.3 · Agent 中枢：队列 + 路由影子建议

> 2026-10-28 定稿并完成。目标版本 **2.40.0**。
> 承接 P26.2：可写 + 审批 → **队列 / 路由**。

## 0. 一句话

忙时不再拒绝：任务先排队，由队列按「每 agent 串行 + 全局并发」自动接续；
同时按纯规则给出「建议用哪个 agent」的**影子建议**并落库，界面展示，
**不改变实际执行**——先攒数据，再决定是否开自动路由。

## 1. 方案决策（2026-10-28）

| 决策 | 结论 |
|---|---|
| 路由口径 | 影子建议（与 `agent/router.py` 同口径）：只记录、只展示、不自动改 agent |
| 队列上限 | `agents.queue_max` 默认 10（1–100）；满了返回 429，不无限堆积 |
| 并发 | 每 agent 仍串行；全局 `agents.max_concurrent`（默认 2）只算真正 running |
| 超时 | 从进程真正 spawn 算起；排队时间不计入 timeout / `duration_ms` |
| 重启 | 首次访问中枢时 `running` → failed（工作台重启，任务已中断），`queued` 继续接续 |
| 可写任务建议 | 一律建议 Claude Code（逐条审批留审计）；Claude 不可用才回落 Codex |
| 只读任务建议 | 最近同模式终态 ≥3 条才比较：完成率差 ≥20 个百分点 → 中位耗时低 30% → 费用 |
| 费用 | 只有两边中位 `cost_usd` 都 >0 才比较；Codex 不自报费用时标「无可比数据」，不按 0 算 |

## 2. 数据（schema 7 → 8）

`agent_tasks` 只做加法：

| 字段 | 说明 |
|---|---|
| `route_json` | 影子路由建议：`recommended` / `chosen` / `mode` / `reason` / `samples` / `fallback`；≤2KB，坏了按 `{}` |
| `timeout_s` | 建任务时的自定义超时；0 = 启动时用设置默认值（排队跨重启不丢） |

队列本身复用现有字段：`status=queued`、`created_at`（入队）、`started_at`（真正开始），
不新增表；排队位次由同 agent 的 `queued` 按 id 排名实时计算。

## 3. 后端

| 文件 | 作用 |
|---|---|
| `store/agent_tasks.py` | `add_queued`（队列未满才插入）、`claim_next`（单条 SQL 原子认领：该 agent 无 running 且全局 running<上限）、`count_running` / `count_queued`、`cancel_queued`、`queue_positions`、`recent_terminal`、`fail_running_tasks` |
| `services/agents/queue.py` | 唯一派发入口：`schedule_drain` / `ensure_started` / `recover` / `cancel`；进程内派发锁；认领前重查 agent 是否可用；启动失败也落 failed |
| `services/agents/route.py` | 纯函数 `recommend()`：不读库、不起进程；规则与阈值集中在此 |
| `services/agents/runner.py` | `start_task(..., on_finish)`；`_run` 在 Popen 前重查取消，已取消不再拉起进程；结束回调触发下一轮派发 |
| `services/agents/registry.py` | 新增 `queue_max()` |
| `server/routes_agents.py` | 建任务先入队再派发；返回 `queue_position`；取消支持 queued；`/api/agents` 返回 `queue_max`；首次访问恢复残留任务 |

`store.agent_tasks_running` 语义收紧为**只算 running**；排队任务不再占并发名额。

## 4. 接口

| 方法 | 路径 | 变化 |
|---|---|---|
| POST | `/api/agents/tasks` | 忙时不再 409；返回 `{task, queue_position}`；队列满 429 |
| GET | `/api/agents/tasks*` | 任务多 `queue_position`、`route`、`timeout_s` |
| POST | `/api/agents/tasks/{id}/cancel` | queued 也能取消（200）；已结束仍 409 |
| GET | `/api/agents` | 新增 `queue_max` |

## 5. 前端

- 任务日志顶部：「路由建议（影子）：建议 X · 理由…；本次按你的选择执行」；一致时写「与建议一致」。
- 历史卡片：排队任务显示「排队中 · 第 N 位」；建议与选择分歧时加「建议 X」徽标（悬停看理由）。
- 派活成功 toast 区分「已启动」/「已排队（第 N 位）」；SW v38。

## 6. 口径与限制

- **完成率 ≠ 正确率**：`done` 只代表任务正常结束；界面与报告统一写「完成率 / 中位耗时」。
- 历史样本来自用户手动指派，存在选择偏置；影子记录只能说明「建议与人工选择的一致率」。
- **已知限制**：两个进程共用同一个数据库时，后启动的会把前一个的 running 误判为中断
  ——与现有 `service_results.recover_orphans` 口径一致；8766 测试必须用隔离数据根。
- 不做失败重试、优先级/公平调度、跨进程取消、多实例 lease。

## 8. 不做

- 自动路由（`on`）：本版只攒影子数据，等 `tools/agent_route_report.py` 的一致率有样本再拍板；
- 多 agent 自动编排 / 任务分解（P26.4）；
- 同一任务双跑 A/B 评测；
- Codex 逐条审批（等 app-server）。
