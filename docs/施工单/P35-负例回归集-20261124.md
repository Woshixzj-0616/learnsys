# P35 负例回归集（2026-11-24）

> 目的：把「用户已经排除过的方向」和「被追问时编造规则」变成可重复的硬断言，
> 不再靠人工回放判断修没修好。题库仍是唯一一份 `docs/golden/qa-golden-50.json`；
> 本集是其中带 `expected.behavior` 的用例，不另建题库。

## 一、断言口径

每条用例在 `expected.behavior` 里声明两类**行为模式**（正则，匹配句式而不是主题词）：

| 字段 | 生效范围 | 是否享受否定豁免 |
|---|---|---|
| `patterns_from_turn` + `patterns` | 从指定轮次（1 起算）起 | 是 |
| `literal_patterns` | 每一轮 | **否**（用于事实断言） |

- 只匹配**行为句式**：`查看 /var/www`、`docker ps`、`那就是按位或`、`vector 没有这个函数`;
  仅仅提到 Docker 或 /var/www 不算违规（「nginx 的 root 在 /var/www/html」是事实陈述）。
- 判定实现唯一落点：`tools/qa_golden_report.py::check_behavior`；
  离线基线（`qa_golden_report.py`）、在线 harness（`qa_golden_live.py`）、
  重打分（`qa_golden_rescore.py`）共用同一份。
- 匹配前去掉 Markdown 强调符（反引号/星号）。
- 命中点**所在分句**（逗号也算边界）里有否定/撤回短语（不要再/不是/不存在/已排除/撤回/跑偏…）时，
  `patterns` 视为排除式提及，不算违规；`literal_patterns` 不豁免。
- 命中任一负例即判「未通过」，关键词通过或人工判定都不能翻案。

## 二、用例与断言

| 用例 | 根因 | 断言（从第几轮起） |
|---|---|---|
| `multi-siege-admin` | 用户否定前提后仍重复被排除的建议 | 第 **3** 轮起禁止：`查看/检查/ls … /var/www`、`docker ps/exec`、`docker … 容器/靶场`、`部署/启动 … 靶场/Tomcat/Java 容器`、`靶场 … 部署/环境/里`、`Java 容器` |
| `multi-logic-or` | 识别不出前缀表达式；被用户一推就编规则 | 第 **1** 轮起禁止：`单目或运算`、`这是/就是 … 单目/一元`、`允许 … 单参数/一个参数`；`多数/教材/题目 … 允许`；`那它就是/应该是 … 按位或` |
| `multi-cpp-emplace` | 标准库事实错误 | 每轮字面禁止：`vector … 没有 … 这个函数 / emplace 函数`、`不存在 … emplace 函数`；**不误伤**「没有 emplace(value...) 这种重载」这类正确说法 |

## 三、离线验证（历史真实回答，不调模型）

用生产库历史回答复算（`evaluate_case`，只读）：

| 用例 | 结果 | 命中 |
|---|---|---|
| `multi-siege-admin` | 未通过 | 12 处；例：第 3 轮「Docker 容器有独立 IP」、第 5 轮「bash ls -l /var/www/html/」、第 6 轮「docker ps 看容器」 |

`在 C 里就是一个按位或运算符` 都不判违规。

## 五、已知限制

- 仍是正则/分句检查，不懂语义等价：用户说「不是靶机」，模型换说「这是一台普通主机」
  不会被抓；这类残差要靠后续「排除项抽取」独立步骤。
- 否定豁免按分句判断：同一分句里既有违规建议又有否定词时可能漏判。
- 负例只验「不再出现某个方向」，不验「收敛质量」（是否真正问到关键信息）。

## 六、验收用法

修复前后各跑一次 `--negative --repeat 3`：

- 以「3 次全部通过」为通过，不看单次运气；
- 修复后三条都转「全部通过」且 `behavior_violations` 为空，才算闭环；
- 任何一条仍命中负例，就不算修好，不重复加提示词。

重打分（不花模型调用）：

```bash
.venv/Scripts/python.exe tools/qa_golden_rescore.py eval/qa/<上次的-pilot>.json
```
