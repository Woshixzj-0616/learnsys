# P18.1 · 知识点与全量答题流水

> BKT 的地基：先把「每道题考什么」和「每次作答对不对」变成结构化数据。
> 本轮不做 BKT 概率，也不做按知识点排程。2026-10-23 开工，版本 2.14.0。

## 1. 为什么先做这一步

BKT 需要两样东西：**知识点标签**和**足够答题数据**。盘点现状：

- `wrong_items.tags` 是模型自由文本，没有知识点实体/ID；
- 测验题由模型现场生成，没有题目主键；
- 只有答错进 `wrong_items`，**答对不落库**。

所以先补三块地基：固定 8 类目、每题 1–3 个类目、每次作答（含答对）落流水。

## 2. 8 个固定类目

词汇 / 语音 / 语法 / 听力细节 / 听力主旨 / 听力推断 / 阅读 / 其他。

- 种子写在 `learnsys/knowledge.py::CATEGORIES`，`core/db/connection.py::_seed_knowledge`
  幂等写入 `knowledge_points`；
- 别名归一只做保守映射（生词→词汇、连读→语音、句法→语法、细节→听力细节、
  大意→听力主旨、推断→听力推断、阅读细节→阅读）；识别不了才落「其他」并标 `fallback`。

## 3. 数据模型

| 表 | 作用 |
|---|---|
| `knowledge_points` | 8 个类目（id / name / kind / sort / active） |
| `quiz_attempts` | 一次作答一行：题面、我的答案、对错、批改、来源、知识点原始 token、`origin_key` |
| `attempt_points` | 作答 ↔ 类目多对多 |

关键字段：

- `correct`：`NULL` = 没判出来；`0/1` = 错/对。
- `source`：`quiz` / `backfill`。
- `points_source`：`model` / `tags` / `fallback`。
- `parse_ok`：对错和知识点都解析成功。
- `origin_key`：`quiz:{conversation_id}:{题面指纹}:{答案指纹}`；
  回填用 `backfill:wrong:{wrong_items.id}`；唯一索引防重复提交。

**BKT-ready 口径只定义一处**（`store/knowledge.py::BKT_READY_SQL`）：

```sql
source = 'quiz' AND correct IS NOT NULL
AND points_source = 'model' AND parse_ok = 1
```

回填、兜底「其他」、判不出对错、格式异常都不计入 P18.2 的 BKT 样本。

## 4. 采集链路

1. 出题回合：模型按格式输出题干 + `【知识点】A、B`；前端 `quiz-parse.js` 暂存
   `pending = {no, stem, points}`。
2. 作答回合：模型批改首行输出 `【批改】正确` 或 `【批改】错误`；
   前端只解析一次，用**出题时暂存的 pending** 记当前题，避免把下一题的知识点算错。
3. `done` 后 `POST /api/quiz/attempt`；答对也发；失败只 `console.warn`，不打断作答。
4. 自检 rewrite 前保存旧文本；最终文本缺标记且旧文本有标记时回退。

提示词在四处重复同一份契约（`learnsys/knowledge.py::prompt_rules()`）：

- `ask/study.py` 的两个出题 builder；
- `agent/prompts.py::MODE_ADDITIONS["quiz"]`；
- `agent/tools/schemas.py::SAVE_WRONGBOOK_SCHEMA.tags`；
- `agent/selfcheck.py::REWRITE_SYSTEM`（保留标记与对错结论）。

## 5. 接口与页面

| 接口 | 说明 |
|---|---|
| `POST /api/quiz/attempt` | 记一次作答（token）；空题/空答 400；重复 `created=false` |
| `GET /api/knowledge?days=0` | 8 类目统计 + totals + 回填状态 |
| `GET /api/knowledge/{id}/attempts` | 某类目最近答题（limit/offset/days） |
| `POST /api/knowledge/backfill` | 旧错题回填；`dry_run` / `force`；一次性闸门 |

插件「知识点」`#/knowledge`：

- hero：总作答 / 测验正确率 / 可入 BKT / 回填；
- 左列 8 类目（全部 / 近 30 天 / 近 7 天），0 次也显示；
- 右列最近答题：对错徽标、来源、我的作答、批改或参考答案、知识点；
- 回填按钮先 dry-run 预览，再确认执行。

## 6. 回填

只回填 `wrong_items.source='quiz'`，且 `ts < meta.knowledge_attempts_since`（升级时间）：

- `origin_key="backfill:wrong:{id}"`，`source='backfill'`、`correct=0`、`parse_ok=0`；
- `ts` 保留原犯错时间；`tags` 归一后挂类目；
- `source_id` 能对上 live 流水的跳过（`live_skipped`），避免升级后错题双计；
- 成功后写 `meta.knowledge_backfilled_at`；再次点击不带 `force` 直接返回已回填；
  `force` 只重扫同一 cutoff 窗口，不移动 cutoff。

## 8. 已知边界

- 「其他」如果是模型显式标注，`points_source=model`，当前计入 BKT-ready；
  P18.2 若认为它是兜底类目，可在 BKT 侧排除。
- 同一题同会话同答案重复提交按一次算（`origin_key`）；换会话或换答案会记新样本。
- 题目指纹是题干文本哈希，模型改写题干会产生新指纹；不跨会话合并题目。
- 多标签、多知识点 UI 只展示 20 条，未做分页控件（接口支持 offset）。
