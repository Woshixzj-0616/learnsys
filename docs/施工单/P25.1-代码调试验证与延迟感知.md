# P25.1 · 代码调试验证 + 延迟感知

> 2026-10-27。起因：会话 45/46 粘贴 150 行 C++ 多项式代码问「一组没过」，
> 8 轮全部 0 次工具调用，答案连续猜错；工作台沙箱本来 0.65 秒就能复现。

## 1. 诊断证据

- 8 次运行：`deepseek-flash`、`thinking=false`、`steps=1`、`tool_count=0`、`model_calls=1`；
- 路由建议：`tier=standard, thinking=false, reason=复杂度 2：3660 字长问题`；
- 真实 bug（随机对拍确认）：`calculatenor` 减法只减「指数相同」的项，B 独有的项
  在 `pa->m < pb->m` 分支和结尾 `pc->next=pa?pa:pb` 两处都没取负；
- 对照实验（同一段代码、同一句话）：

| 组 | 配置 | 结果 |
|---|---|---|
| A | flash 不思考、不强制运行 | 0 工具，猜错 |
| B | flash 思考、不强制运行 | 0 工具，猜错 |
| C | v4-pro 思考、不强制运行 | 0 工具，猜错 |
| D | flash 不思考、强制运行 | 跑 8 次、次次超时，答案空 |
| E | flash 思考、强制运行 | **找到减法 bug** |

结论：**执行验证是决定性杠杆；执行必须配思考，否则会瞎试 / 超时。**

## 2. 正确性设计

| 落点 | 做法 |
|---|---|
| 判定 | `agent/debug_intent.py::detect()`：代码迹象（`#include`/围栏/语法）+ ≥5 行 + 调试词（没过/WA/报错/超时…）；单独「错误」不算 |
| 路由 | `router._auto_tier`：命中即建议 `deep + thinking`（仍用主模型 flash，不换强模型，避免更慢） |
| 实际提档 | `loop._prepare`：`balanced` 且非手动 routes 时**强制 `thinking=True`**（shadow 也生效）；`fast` / 手动 routes 尊重用户 |
| 提示词 | `prompts.CODE_DEBUG_RULE`：先跑再答、多组用例合并成一次 stdin、最多 3 次、没跑不许断言某一行是 bug |
| 防抖 | `turn._handle_tool_call`：同代码+同 stdin 不重复跑；一轮最多 3 次 `run_code` |
| 短超时 | 代码调试轮的 `run_code` 超时 5 秒（默认 10 秒）；坏 stdin 不再死等 |
| 验证闸门 | `turn._finish`：命中代码调试但没成功跑过 `run_code`，答案最前面强制加「未运行验证 / 运行未成功」 |
| 入口 | 只在工作台问答页（`surface=ask`、非 quiz、非 system_override）生效；快捷栏没有 `run_code`，不误伤 |

## 3. 延迟感知设计

**不造假进度，只让「已经开始、正在做什么、大概多久」在三秒内可见。**

| 层 | 做法 | 实测 |
|---|---|---|
| 立刻有反馈 | `_prepare` 在调模型前发 `activity`：「代码调试：先编译运行验证，再回答（通常 10–30 秒）」 | **3ms** |
| 思考可见 | 思考增量继续流式（网页展开、快捷栏实时渲染） | 首个思考 **0.6–0.9s** |
| 计时 | 网页 1 秒一刷「思考中 · N 秒」；快捷栏 400ms 一刷 | 已有 |
| 工具白话 | `tool_start.data.label`（唯一映射 `schemas.TOOL_LABELS`）：网页/快捷栏显示「正在运行代码… / 正在联网搜索…」，不再显示 `run_code` | 每次工具 |
| 阶段切换 | 工具结束显示「结果回来了，继续分析…」；失败「这步没成功，正在换路」 | 每次工具 |
| 收尾标记 | 未运行验证在正文第一行 + 网页状态「未运行验证 · 静态分析」 | 命中时 |
| 防卡死 | 重复/超限直接跳过；短超时；取消按钮仍可随时停 | 最坏不再 8×10 秒 |
| 预期管理 | 首条状态直接写「通常 10–30 秒」；长任务不假装很快 | — |

**实测（flash + 强制思考，你的原始代码）**：首事件 3ms、首思考 0.6–0.9s、
第一个运行 28–30s、总 48–88s；最终找到减法符号 bug，且答案带实际输入/输出。

## 4. 试过但撤回的两条路

1. **同轮「先不思考跑、再切思考分析」**：DeepSeek 返回 400
   `The content[].thinking in the thinking mode must be passed back to the API`。
   同一轮里 thinking 不能中途开关，除非伪造 thinking 块（不可靠）。
2. **独立预运行 + 主分析**：预运行 5 秒能出结果，但主模型拿到输出后只复述、
   不再深入分析（78–1486 字，未找到 bug）。等于把「验证」做成了「交差」。

所以最终选择：**一次思考跑到底**，用感知层覆盖等待。

## 5. 验收

- 单测：`test_debug_intent`、`test_agent_code_debug`、路由/事件回归全过；
- 真实模型：你的多项式代码 → 首事件 <10ms、首个思考 <1.5s、`run_code` 被调用、
  最终答案指出「减法未取负」；不跑时答案必须带「未运行验证」；
- 快捷栏/网页：状态行显示中文工具名与计时；未验证时状态明确；
- 门禁：后端全量 / 前端 / ruff / 体量 / 分层全过。

## 6. 不做

- 不为降低时间而关掉思考（A/B/C 实验证明不思考更快但错）；
- 不伪造进度条 / 假 ETA；
- 不自动跑用户代码绕过确认框（`run_code` 仍是确认工具）。
