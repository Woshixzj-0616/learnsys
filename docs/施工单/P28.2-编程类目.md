## 2. 现状：为什么不能只改 `CATEGORIES`

只往 `CATEGORIES` 里加 5 个字典，**生产库不会长出新行**。原因在连接层：

```python
# learnsys/core/db/connection.py:64-68
version = int(conn.execute("PRAGMA user_version").fetchone()[0] or 0)
if version >= SCHEMA_VERSION:
    return conn          # ← 版本已是最新，直接返回
...
_seed_knowledge(conn)    # ← 只有走迁移分支才会补种
```

生产库已是 `user_version = 13`，`connect()` 每次都在 `return` 处结束，`_seed_knowledge()`
永远不跑。P28.2 的测试 `test_reopen_old_db_adds_programming_categories` 就是钉这个：

```
AssertionError: 8 != 13
```

除种子外，还有 3 个落点各自写死了「8 类」：

| 文件 | 现状 | 后果 |
|---|---|---|
| `learnsys/knowledge.py:69-83` | 提示词写死「这 8 个类目」+ 名单 | 模型永远不会输出编程类目 |
| `learnsys/agent/tools/schemas.py:219-223` | `save_wrongbook.tags` 自己拼 `CATEGORY_NAMES` | 与提示词两份名单，容易漂移 |
| `web/pages/knowledge.html:6`、`web/js/pages/knowledge.js:1,232`、`web/css/knowledge.css:1` | 页面文案写死 8 类 | 实现后页面说 8、实际 13 |

`learnsys/services/today.py:125` 用的是 `focus in CATEGORY_NAMES`，**会自动接受新类目**；
只需改注释，不改逻辑。

**结论**：P28.2 不是「加 5 行常量」，而是三件事：
① 类目表 + 别名；② 数据种子版本（行迁移）；③ 提示词/工具只留一份类目说明。

## 3. 数据设计

### 3.1 最终 13 类

`CATEGORIES` 每项增加 `subject` 字段，作为「英语 / 编程 / 兜底」分组的唯一来源：

| name | kind | sort | subject | 说明 |
|---|---|---|---|---|
| 词汇 | vocab | 10 | english | 不动 |
| 语音 | phonetics | 20 | english | 不动 |
| 语法 | grammar | 30 | english | 不动 |
| 听力细节 | listening_detail | 40 | english | 不动 |
| 听力主旨 | listening_main | 50 | english | 不动 |
| 听力推断 | listening_inference | 60 | english | 不动 |
| 阅读 | reading | 70 | english | 不动 |
| 数据结构 | data_structure | 110 | cs | 新增 |
| 算法 | algorithm | 120 | cs | 新增 |
| C/C++ | c_cpp | 130 | cs | 新增；见 §3.2 命名 |
| 计算机网络 | network | 140 | cs | 新增；显示名用「计算机网络」 |
| 操作系统 | operating_system | 150 | cs | 新增 |
| 其他 | other | 999 | other | 永远最后；不建模 |

约束：

- `kind` 必须全局唯一（表上有 `UNIQUE`）；不要复用旧 kind。
- `sort` 保持「英语 10–70 → 编程 110–150 → 其他 999」，知识点页顺序稳定。
- `name` 是数据库唯一键与提示词原文；**上线后不要轻易改名**，改名要数据迁移。

### 3.2 命名决策：`C/C++`（2026-10-29 拍板）

显示名用 `C/C++`，`kind = c_cpp`。别名接受 `C语言 / c / cpp / c++ / C++` 归到这里。

理由：C 与 C++ 在内存模型、语法上不是一回事，但都属于同一块「编程语言基础」知识；
叫 `C/C++` 比只写 `C++` 更贴合用户实际会交的代码。现在改零成本（还没有历史行）；
上线后再改名要迁移 `knowledge_points.name` 与 `attempt_points` 关联。

### 3.3 别名策略

保留现有英文别名不变，新增（保守，不猜）：

| 类目 | 别名（大小写不敏感） |
|---|---|
| 数据结构 | 链表、单链表、双链表、线性表、顺序表、数组、栈、队列、树、二叉树、图、哈希表、散列表、堆、并查集 |
| 算法 | 排序、查找、二分、递归、分治、贪心、动态规划、回溯、复杂度、时间复杂度、空间复杂度、最短路、最小生成树、BFS、DFS |
| C/C++ | C语言、cpp、c++、指针、引用、内存泄漏、虚函数、模板、STL、面向对象、RAII |
| 计算机网络 | 网络、TCP、UDP、HTTP、HTTPS、IP、DNS、协议、路由、子网、拥塞控制、三次握手、OSI、socket、套接字、网络编程 |
| 操作系统 | 进程、线程、死锁、调度、虚拟内存、分页、文件系统、并发、互斥、信号量、系统调用、中断 |

实现口径：

1. 先按**原文精确匹配** `CATEGORY_NAMES`；
2. 再按 `casefold()` 后的 `ALIASES` 精确匹配（解决 `TCP/tcp/Tcp`）；
3. 最后才用现有的「最长类目名包含匹配」兜底；
4. 一个都认不出 → `["其他"], "fallback"`，**不计入 BKT**（口径不变）。

注意：不要加过于宽泛的「内存」「语法」「网络工程」之类别名，避免把英语题/泛问题吸到编程类目。
显示名是「计算机网络」，但别名保留「网络」，旧 tags / 模型口语都按「网络」归到这里。

### 3.4 种子版本：让「只加行」在已是最新版本的库上也能生效

**不升 `SCHEMA_VERSION`**。理由：

- 表结构没变（没有新列/新表/新索引），升版本会把「数据种子」和「结构迁移」混成一个开关；
- 以后每次加类目都升 schema，会让版本号失去「结构」含义；
- 现有 `SCHEMA_VERSION = 13` 保持不动，生产库不会跑一遍无意义的 DDL。

新增独立的数据种子版本：

```python
# learnsys/knowledge.py
SEED_VERSION = 1   # 类目种子版本；以后只加行就 +1
```

```python
# learnsys/core/db/connection.py
def _seed_knowledge(conn):
    # 原有 INSERT OR IGNORE 13 个类目 + knowledge_attempts_since
    # 末尾写入 knowledge_seed_version = knowledge.SEED_VERSION
    ...

def _seed_knowledge_if_needed(conn):
    row = conn.execute(
        "SELECT value FROM meta WHERE key = 'knowledge_seed_version'").fetchone()
    if row and str(row[0]) == str(knowledge.SEED_VERSION):
        return
    _seed_knowledge(conn)

def connect(path=None):
    ...
    if version > SCHEMA_VERSION:       # 降级打开：不要碰更新的库
        return conn
    if version == SCHEMA_VERSION:      # 结构已就绪，只检查数据种子
        _seed_knowledge_if_needed(conn)
        return conn
    # version < SCHEMA_VERSION：原样走完整建表 + 迁移 + 种子
```

成本与边界：

- 每次 `connect()` 多一次 `meta` 主键查询；只有第一次打开旧库时多一次写事务。
- **不要**改成「每次连接都 `INSERT OR IGNORE` 13 行」：路由层每个请求开连接，会反复拿写锁。
- `version > SCHEMA_VERSION`（用旧版程序打开新版库）**原样返回**，不补种、不改库。
- `_seed_knowledge` 仍只做 `INSERT OR IGNORE`，不 UPDATE / DELETE。

### 3.5 旧数据政策

| 数据 | 处理 |
|---|---|
| `knowledge_points` 旧 8 行 | 不动；`id/kind/sort/created_at` 保持 |
| `quiz_attempts` / `attempt_points` | 不做任何 UPDATE；旧答题仍挂旧类目 |
| `wrong_items.tags` | 原样保留（例如旧值「指针」仍是「指针」） |
| `knowledge_attempts_since` / `knowledge_backfilled_at` | 不动 |
| 旧错题回填 | **不自动触发**；用户手动点「回填旧错题」时才走现有接口 |

实现时禁止写：`UPDATE knowledge_points SET ...`、`UPDATE quiz_attempts ...`、
自动调用 `services.knowledge.backfill_wrong_items(...)`。

## 5. BKT 与今日 focus

### 5.1 现有链路自动生效

```
quiz 作答 → /api/quiz/attempt → services.knowledge.add_attempt
         → normalize_points(新类目识别) → quiz_attempts + attempt_points
         → store.knowledge_stats → services.knowledge.attempt_stats
         → BKT（kind != "other" 全部建模）
```

只要 §3 的类目与别名进表，`attempt_stats` **不需要任何改动**：新类目自动参与
`mastery_ready / mastery / 薄弱排序`。`其他` 仍不建模。

### 5.2 编程 BKT 样本从哪来（本轮的口径）

- 现有唯一入口是**测验页的答题流水**：`web/js/pages/quiz.js:319` 每答一题 POST 一次，
  答对也记（`correct=true`），这是 BKT 需要的正负样本都有的路径。
- 代码调试里「收进复习」只写 `wrong_items` + `review_state`，**不写 `quiz_attempts`**。
  所以 P28.2 完成后，光靠代码调试不会产生编程 BKT 样本；要产生样本，需要做编程题
  并在测验页作答。

这是 P28 总验收「BKT 类目有样本」的缺口。**2026-10-29 拍板走 A 案**：

- P28.2 只做类目；BKT 样本由编程测验产生（做编程题并在测验页作答，答对答错都记）。
- P28.3 再把复习评级（记住 / 模糊 / 忘了）映射成答题流水，补上「复习也能产生样本」。
- 不选 B（`save_wrongbook` 顺带写 `correct=false`）：只有负样本会让 BKT 系统性偏低，
  而且多一个写入口，违背「一条规则一个落点」。

### 5.3 今日 focus

`/api/study/today?focus=算法` 应返回 `quiz_focus="算法"`，提示词里出现
「本轮指定重点：算法」；`focus=其他` 与不存在的类目仍被拒绝。测试已覆盖。
