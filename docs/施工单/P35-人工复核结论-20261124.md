## 修复尝试（2026-11-24，两轮）

### 1. 否定轮注入（结构性）

- `correction.negation()` 识别「我没写过 / 不是靶机 / 都和你说了没有」；
- `correction.exclusions(history, message)` 把用户否定过的**原话**摘出来注入系统提示；
- `prompts.NEGATION_RULE` 要求第一行写「已排除」，被排除项不得再建议。

结果（`multi-siege-admin`，`P35-在线试点-20261124-210009.md`）：第 2/3/4 轮都以「已排除」开头，
不再建议 `ls`/Docker；但第 3 轮仍保留「在这台虚拟机上查 Java 容器/端口」的方向，第 4 轮才完全停。
**未达标**（目标是 ≤2 轮停止）。

### 2. 前缀表达式与反顺从

- `core.md`：`&(a,b)` / `|(a,b)` / `!(a)` 先按前缀 / 自定义布尔语法理解，不默认 C；
- `core.md`：用户说「你是不是搞错了」时先核对，冲突就直说，不许编规则改口。

结果（`multi-logic-or`，同上报告）：第 1 轮已识别前缀写法、说明「或」需两个操作数；但第 2 轮被
用户一句「不就是这样」推翻，编出「多数同类题目允许单参数」，第 4 轮才收回。**未达标**。

### 3. 同时修掉的评测误判（与模型无关）

  `claims.is_citation_url`（本机地址、占位示例不算引用），历史用户消息里的链接也计入已知。
- `english-fish-correction` 第二组关键词放宽到 `surplus`（「年年有余」的常见译法）。
- 全量回归（`P35-在线试点-20261124-210943.md`）曾掉到 45/5/4；修正后复跑三条
  （`…-211059.md`）全部通过，账面回到 **48 通过 / 2 未通过 / 4 图片跳过**。

### 停手点

两条缺陷仍未闭环。按「同类问题补到第 3 次不收敛就停手做根因」，不再继续加提示词，先记录根因：

- **根因 A**：用户复述/断言时，模型倾向附和，并会编造「多数教材/一般允许」这类无来源结论。
- **根因 B**：注入的排除项只有原话，没有语义等价替换（「不是靶机」→ 不应再在这台机器上找靶场服务）。

可选方向（待负责人定）：给这两类加负例集并做小样本评估；或在否定/断言轮升级到强模型；
或把「排除项抽取」做成独立步骤（多一次模型调用，换确定性）。
