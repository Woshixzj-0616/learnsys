# P26.4 · Agent 中枢：显式任务链

> 2026-10-28 定稿并完成。目标版本 **2.41.0**。
> 承接 P26.3：队列 + 影子路由 → **显式任务链**。

## 0. 一句话

用户自己把任务排成顺序：第二步接在第一步之后，第一步完成后队列自动开跑第二步，
并把第一步的结果作为**资料**注入第二步；顺序、agent、模式全部由用户选，工作台不替用户决定。

## 1. 方案决策（2026-10-28）

| 决策 | 结论 |
|---|---|
| 范围 | **显式**任务链；不做自动任务分解、不做 draft + reviewer 双 agent（后者要等 A/B 评测证据） |
| 数据结构 | `agent_tasks.depends_on` 指向已存在任务，天然无环；不新建链/步骤表 |
| 结果注入 | 父任务结果正文存 `result_text`（截 20000 字），认领时拼进子任务运行 prompt |
| 总长度 | 组合后 ≤20000；**只截父结果，不截用户原文**；父结果保留头 70% + 尾 30% 并注明截断 |
| 失败级联 | 父任务 failed/cancelled/不存在 → 子任务 `cancelled`（「上一步任务 #N 未完成，链已停止」），循环处理孙任务 |
| 级联状态 | 用 cancelled 而不是 failed：这些任务从未执行，不能污染影子路由的完成率统计 |
| 队列上限 | `queue_max` 仍统计全部 queued（含等待父任务）；不为链放宽，429 文案注明 |
| 分叉 | 同一父任务可接多个子任务：同 agent 串行、异 agent 并行，各自拿同一份父结果 |

## 2. 数据（schema 8 → 9）

`agent_tasks` 只做加法：

| 字段 | 说明 |
|---|---|
| `depends_on INTEGER NOT NULL DEFAULT 0` | 上一步任务 id；0 = 独立任务 |
| `result_text TEXT NOT NULL DEFAULT ''` | 结果正文（截 20000 字）；**任何接口都不返回全文**，列表只给 `has_result` |

- 结果全文仍写 `output_path` 指向的 markdown 文件；DB 里的 `prompt` 保留用户原文。
- 老任务没有 `result_text`：`has_result=false`，不能作为新链的父任务（建链 409）。
- 输出文件的「## 任务」是**组合后的运行 prompt**，与 DB 原文是两个真相源，本版本接受并记录。

## 3. 后端

| 文件 | 作用 |

## 6. 口径与限制

- **显式 ≠ 自动**：顺序、agent、模式都由用户选；工作台不决定下一步做什么。
- 上游输出是模型生成文本，原样作为**资料**注入；提示词与界面都写明「不是指令」，
  但不做指令过滤，链式任务仍可能受上游影响——这里不假装安全。
- 总长 20000 可能截掉父结果的结论；需要完整结果请看结果文件。
- 父任务运行时子任务可以先建；父任务结束前不能认领。
- 已知限制：两个进程共用一库时后启动者会误判 running（与 P26.3 相同）；8766 必须隔离数据根。

## 8. 不做

- 自动任务分解 / 自动排序；
- draft + reviewer 双 agent（需要先有 A/B 评测证据）；
- 多父 DAG、条件分支、循环、失败自动重试续跑；
- 链上自动换 agent（agent 由用户为每一步选）；
- 结果正文的独立查询接口。
