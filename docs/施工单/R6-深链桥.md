## 2. 架构决定

### 2.1 待跳转状态放服务端，只有一份

Qt 和 Web 是两个进程/两个运行时，唯一共同点是有同一个本地后台。
服务端保存「最新一次跳转请求」：`server`（进程随机 id）+ `seq`（单调递增）+ `href` + 写入时间。
Web 只按 `seq` 增量取，**路由解析仍只由 Web 壳负责**（Qt 不复制一份路由表）。

- 过期 30 秒：点击后窗口若没被叫起来，不会过很久突然乱跳。
- 后台重启：`server` 变化，Web 侧把本地 `last` 归零，避免旧 `seq` 比新 `seq` 大导致永远不生效。

### 2.2 传输用轮询，不用 SSE

PWA 在后台会被 Chromium 节流，SSE 连接也可能被挂起；而本场景「Qt 点击 → 窗口被提到前台」
必然触发 `focus`/`visibilitychange`。所以：**前台每 2 秒轮询一次 + 聚焦时立即拉一次**。
不新增 EventSource 的令牌 query、重连、心跳三套逻辑。

### 2.3 Web 窗口 = 浏览器进程窗口

标题后缀是给用户看的品牌，不是身份。判定改为：窗口标题匹配 **且** 进程映像是浏览器
（`msedge.exe` / `msedge_proxy.exe` / `chrome.exe` / `chromium.exe` / `brave.exe` / `firefox.exe`）。
`fit_window` / `focus_window` / `_wait_for_window` 全部走这条判定；`_windows_matching()` 保留默认
「只看标题」供诊断与既有测试使用。

### 2.4 点击顺序：先写队列，再聚焦

页面在 `focus` 事件里立即拉一次，所以必须**先 POST 再 `SetForegroundWindow`**；
顺序反过来会错过这次聚焦，只能等下一轮 2 秒轮询。

### 2.5 安全与输入校验

- 两个接口都要 `X-Learnsys-Token`；Origin 白名单沿用全局中间件。
- `href` 必须 `#/` 开头、≤512 字符、无控制字符；不满足返回 400，不落库、不广播。
- 不做「打开任意 URL」：外部 http(s) 仍走原有 `open_or_focus`，不进队列。

## 3. 接口

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/ui/navigate` | `{"href": "#/quiz?focus=词汇"}` | `{"ok": true, "seq": 3}`；格式错 400 |
| GET | `/api/ui/navigate?since=2` | — | `{"server": "a1b2c3d4", "seq": 3, "href": "#/..."}`；过期或没有时 `href=""` |

`since` 为兼容保留，是否应用由前端按 `server`+`seq` 判断。

## 5. 验收

**自动化**

- 后端：新增用例全过，全量不回归。
- 前端：`node --test web/tests/*.mjs` 全过。
- 门禁：`tools/arch_report.py --check`、`tools/layering_report.py`、ruff 收窄规则。

**真机（源码后台 + 浏览器）**

1. 打开 Web 工作台停在 `#/today`；Qt 今日页点「继续最近的会话」→ 已开窗口跳到 `#/ask/<id>`。
2. 停在 `#/ask`；Qt 今日页点六级断点 → 跳到 `#/cet6?paper=...`。
3. 关掉 Web 窗口后点同一张卡 → 新开窗口直接落在目标页。
4. Qt 设置/今日窗口开着时，托盘「工作台」仍能识别/打开真正的 Web 窗口（不聚焦自己）。
5. 停止后台 → 页面离线提示与「启动后台」不受影响。

**独立信源说明**：第 1–4 条涉及真实窗口与鼠标点击，自动化只能覆盖到接口与纯函数；
最终需要用户目视确认，报告里会明确标注未自动验证的部分。

## 6. B2（Qt 单窗口壳层）判定门

B1 达标后，只有同时满足下面两条才启动 B2：

1. 仍存在「两个窗口」造成的实际摩擦（例如每天都要在 Qt 今日页与 Web 页之间来回切）；
2. B1 已验证深链桥在 PWA/浏览器里稳定（至少连续用 1 周）。

否则不做 B2：Qt 内嵌网页（QWebEngine）会带来打包体积与渲染差异，收益不抵成本。
