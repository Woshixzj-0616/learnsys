# P20.2 · 工作台浏览器（打开网址 + 使用记录）

> 网址不再交给系统默认浏览器：由工作台启动一个**独立 profile 的 Edge/Chrome**，
> 工作台内提供「浏览器」插件页显示状态与历史，Agent 能读你最近看了哪些网页。
> 2026-10-23 定稿，版本 2.18.0。**本阶段不做页面正文读取与点击控制。**

## 0. 先说清「工作台里面」的边界

网页工作台运行在 Edge/Chrome 里，**无法把第三方网页安全地 iframe 嵌进页面**：
多数站点用 `X-Frame-Options` / CSP 禁止被嵌，跨域后也读不到内容。
真正的「同窗口左右分栏」需要把工作台重写成 WebView2/QtWebEngine 壳（阶段 C），
本轮不做。

本阶段的产品形态：

```
工作台页面（#/browser 插件页）
  ├─ 状态：浏览器是否运行、当前标签标题/URL
  ├─ 操作：打开网址、启动/关闭、暂停记录、清空记录
  └─ 历史：最近访问（时间 / 标题 / 域名）
          │
          ▼
独立浏览器窗口（Edge/Chrome，独立 profile，归工作台管理）
  └─ 本机 CDP（只读 /json/list）→ 轮询 URL 与标题 → browser_events
```

窗口是独立的系统窗口，但**由工作台启动、用独立 profile、工作台可关闭**；
Agent 只看到 URL/标题，看不到页面正文、Cookie、表单。

## 1. 选型对比（为什么不用内嵌）

| 方案 | 内嵌程度 | 监视能力 | 成本 | 结论 |
|---|---|---|---|---|
| iframe 嵌入 | 假内嵌 | 跨域读不到 | 低 | ❌ 多数站点拒绝 |
| QtWebEngine 真内嵌 | 真内嵌 | 全（DOM/截图） | 打包 +150MB，工作台 UI 是 Web 不是 Qt | ❌ 本轮不做 |
| WebView2 薄壳 | 真内嵌 | 全 | 重写外壳（阶段 C） | ⏸ 以后评估 |
| **独立 Edge/Chrome + CDP** | 独立窗口 | URL/标题/标签 | **低** | ✅ **本轮采用** |
| Playwright 独立 Chromium | 独立窗口 | 全（可控制） | 体积大、易被反爬 | ❌ 本轮不做 |

CDP 第一版只用 HTTP 端点（`/json/list`、`/json/new`、`/json/close`），
**不引入 WebSocket 依赖，不开放 `Runtime.evaluate` / `Page.navigate`**。

## 3. 进程管理

### 3.1 浏览器与 profile

- 浏览器定位复用 `learnsys/ask/workbench.py::find_browser()`（Edge 优先，Chrome 兜底）；
- profile：`<数据目录>/浏览器配置`（首次自动创建）；
- 下载目录：`<数据目录>/浏览器下载`（用启动参数；若版本不生效，验收记录并退回浏览器默认策略）；
- **绝不使用**用户默认 profile，不导入密码/Cookie/收藏。

### 3.2 启动参数

```text
--user-data-dir=<数据目录>/浏览器配置
--remote-debugging-port=0
--no-first-run
--no-default-browser-check
--disable-sync
--disable-extensions
--disable-background-networking
--disable-component-update
--disable-features=Translate,MediaRouter,OptimizationHints
--download-directory=<数据目录>/浏览器下载
--new-window <url>
```

- 不用 `--app=`：**必须保留地址栏**，用户要能看见真实 URL，防钓鱼；
- `--remote-debugging-port=0` 让系统分配随机端口，端口写在 profile 的 `DevToolsActivePort`；
- 只绑定 `127.0.0.1`（Chromium 默认）。

### 3.3 生命周期

- 启动：`Popen` 记录 PID；轮询等待 `DevToolsActivePort` 出现（最多 8 秒），失败给中文原因；
- 复用：已有实例（端口活着且 `/json/version` 可读）→ 只开新标签/聚焦，不再起第二个进程；
- 关闭：默认工作台退出时关闭自己启动的进程（`close_on_exit=true`）；
  只终止**自己 Popen 的 PID**，并校验命令行包含本 profile 路径，绝不 `taskkill` 用户浏览器；
- 崩溃残留：下次启动先探测端口；不可用则清理 `SingletonLock` 后重启。

### 3.4 CDP 客户端

- `GET /json/list` → 只取 `type=="page"` 的标签：`id`、`url`、`title`；
- `PUT /json/new?<url>` → 新标签（新版 Chromium 要求 PUT；失败时回退“带 URL 启动第二个进程”）；
- `GET /json/close/<id>` → 关闭标签（插件页可选，不做记忆）；
- 所有请求超时 2 秒；异常只记内存状态，不抛给界面；
- **不实现** WebSocket 命令通道；模型永远拿不到 CDP 端口。

### 3.5 轮询与记录

- 后台线程每 2 秒拉一次 `/json/list`；
- 只处理 `http://` / `https://`；`file:`、`chrome:` 等一律跳过；
- 每个 tab 保存 `(url, title)`；URL 或标题变化才写一条 `browser_events`；
  同一 tab 连续相同的 URL 不重复写；
- `exclude_domains` 命中（后缀匹配，忽略大小写）不写库；
- `record=false` 时不写库、`browser_status` 不返回当前页（只返回「已暂停」）；
- 启动时清理早于 `history_days` 的记录。

## 4. 数据与设置

### 4.1 表（只做加法）

```sql
CREATE TABLE IF NOT EXISTS browser_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts TEXT NOT NULL,
  tab_id TEXT NOT NULL DEFAULT '',
  url TEXT NOT NULL,
  title TEXT NOT NULL DEFAULT '',
  domain TEXT NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_browser_events_ts ON browser_events(ts);
CREATE INDEX IF NOT EXISTS idx_browser_events_domain ON browser_events(domain);
```

`ts` 用本地 `YYYY-MM-DD HH:MM:SS`；事件表只需要 `ts`（沿用阶段总览约定）。

### 4.2 设置（`设置.json` 的 `browser` 块）

```json
"browser": {
  "enabled": true,
  "record": true,
  "exclude_domains": [],
  "history_days": 30,
  "close_on_exit": true
}
```

- `config.browser_settings()` 统一读默认值 + 类型清洗（列表去空、域名小写、天数夹到 1–365）；
- `enabled=false`：不启动浏览器、不轮询、工具 `open_url` 返回「浏览器功能已关闭」。

## 5. HTTP 接口（`routes_browser.py`）

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/browser/launch` | 启动/复用浏览器，返回状态 |
| `POST` | `/api/browser/open` | `{url}` → 校验 + 打开新标签 |
| `GET` | `/api/browser/status` | 运行状态、记录开关、当前标签、标签列表 |
| `GET` | `/api/browser/history` | `limit`（≤100）/`days`/`domain` → `{items,count}` |
| `DELETE` | `/api/browser/history` | 清空全部记录 |
| `POST` | `/api/browser/recording` | `{enabled}` 暂停/恢复记录 |
| `POST` | `/api/browser/close` | 关闭工作台启动的浏览器 |

- 写操作一律 `Depends(require_token)`；错误 `{"detail":"中文原因"}`；
- 端口、PID、profile 路径**不返回给前端**；
- `open` 的 URL 校验与 Agent 工具共用同一个纯函数（单一落点）。

## 6. Agent 工具

| 工具 | 类型 | 行为 |
|---|---|---|
| `open_url(url)` | 需确认 | 调 manager 打开；确认框显示完整 URL；拒绝=不打开 |
| `browser_status()` | 只读 | 返回是否运行、当前标签标题/URL（暂停时只说已暂停） |
| `browser_history(limit=20, days=7)` | 只读 | 最近记录（时间/标题/域名/URL），最多 50 条 |

- `open_url` 加入 `CONFIRM_TOOLS`；`WRITE_LABELS` 加 `open_url: 打开网址`；
- 三个工具只在非 `quiz` 模式暴露；
- 工具描述写明：「这些是用户本机浏览记录，只用于回答当前问题，不要主动扩散」；
- **不做** `browser_read_page`、`browser_click`、`browser_screenshot`。

## 7. 安全设计（本阶段的重点）

| # | 风险 | 措施 |
|---|---|---|
| 1 | 接管用户日常浏览器 | 独立 profile；只管理自己 Popen 的 PID；校验命令行含本 profile |
| 2 | 钓鱼 / 看不到真实地址 | 必须保留地址栏，不用 `--app`；插件页显示当前 URL |
| 3 | 扩展/同步/后台服务 | `--disable-extensions --disable-sync --disable-background-networking` |
| 4 | 调试端口被滥用 | 随机端口、只绑 127.0.0.1、端口不返回前端；只开放只读端点 |
| 5 | 模型注入 JS/导航 | CDP 不开放 `Runtime.evaluate` / `Page.navigate`；`open_url` 只能新标签 |
| 6 | 危险 URL scheme | 只 http/https；拒绝 `file:`/`javascript:`/`data:`/`ms-settings:`/userinfo；长度 ≤2048 |
| 7 | 下载文件被执行 | 下载进独立目录；Agent 不执行下载文件；打开文件仍走 P20.1 的可执行拒绝 |
| 8 | 记录外泄 | 只存 URL/标题/域名/时间；不存正文、Cookie、表单、截图；不自动上传 |
| 9 | 关闭残留进程 | 退出关闭（默认）；崩溃后下次探测并清理锁 |
| 10 | 中间人/证书 | 不装根证书、不设系统代理、不解密 HTTPS |

**必须写进 README 与本阶段的已知边界**：本机同用户进程理论上可以访问 CDP 端口；
这是“本机可信”威胁模型，不是多用户隔离。若以后要更强隔离，再评估
`--remote-debugging-pipe` 或 WebView2。

## 8. 隐私设计（「监视」的边界）

- 记录只在本机 SQLite；**不自动**进入模型上下文；
- 只有你提问、模型调用 `browser_history` 时，记录才会作为工具结果发给 DeepSeek；
- 插件页与设置页明确写这句话；
- 可暂停记录、按域名排除、清空记录、设置保留天数；
- 「清空浏览数据」另设按钮：删除 profile 目录（Cookie/缓存），需二次确认；
- 默认**不记录** `localhost` / `127.0.0.1`（工作台自己）以外的敏感场景由用户排除；
- 关闭记录时，`browser_status` 也不暴露当前页。

## 9. 前端插件页 `#/browser`

- 状态卡：运行中/未启动、当前标签标题+URL、记录开关；
- 输入框 + 「打开」按钮（前端只调 `/api/browser/open`，不接触端口）；
- 历史列表：时间、标题、域名；点击「重新打开」；
- 操作：启动浏览器、关闭浏览器、暂停/恢复记录、清空记录；
- 说明区：三句话讲清「独立窗口 / 只记录 URL 与标题 / 查询时才会发给模型」；
- 侧栏插件清单新增 `browser`，`plugin.json` 版本 2.18.0。

## 11. 明确不做

- iframe 内嵌、WebView2/QtWebEngine 壳（阶段 C）；
- 页面正文读取、截图、点击/填表、登录态复用（下一阶段单独评估）；
- 系统代理、HTTPS 解密、根证书；
- 接管用户日常浏览器或已开标签；
- 无痕/隐私窗口管理。

## 12. 验收

- 全量 unittest；前端 node 测试；`arch_report.py --check`；
- 8799 源码后台 + Chrome 真机：
  1. 插件页点「启动浏览器」→ 独立窗口打开，地址栏可见；
  2. 打开 `https://example.com` → 历史出现一条（标题/URL/时间）；
  3. 再打开一个标签 → 两条；
  4. 设置排除 `example.com` → 新访问不落库；
  5. 暂停记录 → 不落库，`browser_status` 只显示「已暂停」；
  6. 清空记录 → 列表为空；
  7. 工作台退出 → 浏览器关闭（`close_on_exit=true`）；
  8. 问一问：「我最近看了什么网页？」→ 模型调 `browser_history` 并回答；
  9. 拒绝 `open_url` 确认 → 浏览器不打开，模型明确说「没有打开」；
  10. 检查浏览器进程命令行包含独立 profile，未触碰用户默认 profile。

## 14. 风险

| 风险 | 应对 |
|---|---|
| Edge/Chrome 版本差异（`/json/new` 要 PUT、`DevToolsActivePort` 位置） | 本机真机验收；失败回退“带 URL 启动第二个进程” |
| 首次启动慢（独立 profile 初始化） | 插件页显示「正在启动」，8 秒超时给中文原因 |
| 轮询记录后台标签 | 第一版接受并在插件页说明；后续可升级 WebSocket 精准记录 active tab |
| 用户误以为窗口是日常浏览器 | 插件页说明「工作台管理的独立窗口，不使用你的日常浏览数据」 |
| CDP 本机可访问 | 随机端口 + 只读端点 + 不暴露给前端；文档写明威胁模型 |
