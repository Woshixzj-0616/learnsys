# P26.6 · 测试进程禁止连接生产库

> 2026-10-28 发现于 P26.5 验收。目标版本 **2.41.1**（与 P26.5 同版发布）。
> 这不是新功能，是数据安全补丁。

## 0. 一句话

测试进程一旦去开真实库就**立即报错**；同时补上两个漏隔离的测试，根因是后台线程
按 `cfg.data_root` 取库。

## 1. 问题与证据

| 项 | 内容 |
|---|---|
| 现象 | 跑全量测试后，生产库 `D:\学习系统\learning.db` 的 `user_version` 从 9 变成 10（被测试顺带迁移） |
| 触发链 | `tests/test_agent_context.py` / `tests/test_server_v2.py` 建了 app 却只 patch `store.connect`；对话流结束时 `routes_agent/chat.py:285` 把**真实** `cfg.data_root` 传给 `post_turn.schedule()`，后台线程 `post_turn.py:195` 直接开生产库 |
| 影响 | 测试可静默迁移/读写生产数据；每次 schema +1 都会在跑测试时改生产库 |
| 为什么以前没暴露 | 旧版本 `SCHEMA_VERSION` 与生产一致，`connect()` 走「版本相同就跳过 DDL」分支，只读不写 |

守门复现：用临时脚本包一层 `connect` 记录目标路径，跑全量 → 17 次落到生产库
（8 次 `test_agent_context.py`、3 次 `test_server_v2.py`、6 次后台线程）。

## 2. 方案决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 守门位置 | `core/db/connection.py::connect()`，唯一入口 | 一条规则一个落点；所有路径都经过它 |
| 判定方式 | 进程里出现 `unittest` 模块 + 目标 == **导入时冻结**的真实库路径 → 抛 `RuntimeError` | 测试会 patch `config.DATA_ROOT`，所以真实路径必须导入时取一次，不能现算 |
| 错误文案 | 中文，写明「禁止连接生产库」与目标路径 | 出问题要一眼看懂 |
| 附带根因修复 | `queue._heartbeat_loop` 起线程时解析库路径一次 | 原实现每拍重读全局，测试 patch 撤销后会落到真实库 |
| 测试隔离 | 两个漏隔离的用例补 `DATA_ROOT` patch | 不能只靠守门报错，正常路径就要隔离 |
| 不做 | 不给每个测试加公共基类、不改 app 的数据根注入方式 | 守门已覆盖；不动更大架构 |

## 3. 改动

| 文件 | 改动 |
|---|---|
| `learnsys/core/db/connection.py` | 新增 `_REAL_DB_PATH`（导入时冻结）与 `_guard_test_process()` |
| `learnsys/services/agents/queue.py` | 心跳线程起线程时解析一次库路径 |
| `tests/test_agent_context.py` | `setUp` 补 `DATA_ROOT` 隔离 |
| `tests/test_server_v2.py` | 同上 |
| `tests/test_db_guard.py` | 守门规则测试：真实库报错、临时库可用 |

## 4. 验收

1. 新增 2 条守门测试通过；
2. 全量 1197 测试全过；
3. 用记录脚本连续跑两轮全量：**生产库连接次数 = 0**；
4. 生产库副本 `user_version = 10`、`runner` / `heartbeat_at` 列存在、材料数不变。
