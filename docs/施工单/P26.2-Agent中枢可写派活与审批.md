# P26.2 · Agent 中枢：可写派活 + 逐条审批

> 2026-10-28 定稿并完成。目标版本 **2.39.0**。
> 承接 P26.1：只读派活 → **可写 + 审批**。

## 0. 一句话

给 Agent 中枢加「可写」模式：Claude Code 每次改文件 / 跑命令都会停下来，
在网页上显示要做什么、diff 或命令原文，等用户点允许 / 拒绝后才执行；
Codex 走 `workspace-write` 沙箱，只在所选目录内写，整任务授权。

## 1. 方案决策（2026-10-28）

先在本机做了三组实测，再定方案：

| 验证 | 结果 |
|---|---|
| Claude `PreToolUse` 钩子 + `--settings` 内联 | 拿到 `Write` 的完整参数；返回 allow 后文件真实写入 |
| 钩子返回 deny | 文件未创建；`permission_denials` 有记录；agent 收到「用户拒绝」并可继续调整 |
| 钩子命令用 `cmd /c` + 中文路径 + curl 环境变量 | 可执行，`X-Learnsys-Hook` / `Task` 头与请求体都正确到达 |

结论：

- **Claude**：`--restricted` 保留（文件工具限制在工作目录、忽略用户设置），
  用 `--tools` 显式放回 `Bash` 等工具；`--permission-mode default --permission-prompts host`
  + `PreToolUse` 钩子逐条问人。钩子只拿得到「提交提议」的令牌，**不能替用户点允许**。
- **Codex**：`codex exec` 是无头的，没有人工审批通道；本版用 `--sandbox workspace-write`
  做目录内整任务授权，界面上明确写「不逐条确认」。逐条审批要等以后接 app-server。
- 不做「提议箱代执行」：agent 只读、工作台代写会导致 agent 看不到执行结果，
  多步任务会断；审批留在工具调用前更自然，diff 也能直接拿到。

## 2. 数据（schema 6 → 7）

新增 `agent_approvals`：

| 字段 | 说明 |
|---|---|
| id / task_id / seq | 主键与所属任务 |
| tool / kind / target | 工具名（Write/Edit/Bash…）、类别（write/edit/command/other）、目标路径或命令 |
| summary / preview | 中文一句话摘要；新建文件预览 / 统一 diff / 命令原文（≤ 8000 字） |
| payload_json | 工具参数（≤ 20000 字，审计用） |
| status | `pending` → `allowed` / `denied` / `expired`，只允许改一次 |
| created_at / decided_at / reason | 提议与决定时间、中文原因 |

## 3. 后端

| 文件 | 作用 |
|---|---|
| `services/agents/approvals.py` | 钩子脚本生成、一次性令牌、工具调用 → 中文摘要 / diff、钩子响应 |
| `services/agents/base.py` | `build_argv(..., mode, settings_json)`：写模式参数；状态文案区分只读/可写 |
| `services/agents/runner.py` | 写任务注册令牌、注入 `LEARNSYS_HOOK_*` 环境、结果文件追加审批审计 |
| `services/agents/registry.py` | `approval_timeout`（默认 110 秒，10–600） |
| `store/agent_approvals.py` | 提议箱读写；只有 `pending` 能被改成终态 |
| `server/routes_agents.py` | 建任务带 `mode`；审批列表 / 决定 / 钩子入口 |

接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/agents/tasks` | 新增 `mode: read \| write` |
| GET | `/api/agents/tasks/{id}/approvals` | 当前任务的提议与结果 |
| POST | `/api/agents/approvals/{id}/decide` | 网页令牌；`allow` / `deny`，重复点击 409 |
| POST | `/api/agents/hooks/approval` | Claude 钩子专用；校验一次性令牌，原地等待用户决定 |

## 4. 安全边界（硬约束）

- 写模式仍用 `--restricted`：文件工具只限工作目录；mcp 仍为空；绝不使用 `--dangerously-bypass-*`。
- 钩子只依赖系统自带 `curl.exe`，脚本落在 `DATA_ROOT/agent_hooks/approve.cmd`；
  URL / 令牌 / 任务号全部走子进程环境变量，脚本本身不含密钥。
- 两枚令牌职责分离：钩子令牌只能**提交提议**；允许 / 拒绝必须用网页令牌。
- 每条提议只能决定一次；等待超时（默认 110 秒）按拒绝处理；任务结束 / 取消时未决提议记 `expired`。
- Codex 写模式只开 `workspace-write`，不碰 `danger-full-access`。
- 结果文件新增「写操作审批」表，保留每次允许 / 拒绝 / 超时的审计。

## 5. 前端

- 派活表单新增「模式：只读 / 可写」，选 Codex 可写时提示「目录内整任务授权，不逐条确认」。
- 任务面板新增审批区：摘要 + 预览（新建文件内容 / 统一 diff / 命令原文）+ 允许 / 拒绝；
  处理后原地变成「已允许 / 已拒绝 / 已超时」记录；历史任务也能回看。
- 任务列表加「只读 / 可写」徽标；SW v37。
