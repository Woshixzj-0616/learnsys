# P20.1 · Agent 打开文件与启动应用

> 网页问一问的 Agent 现在只能读资料库/附件，不能打开本机文件或应用。
> 本轮补两个受控工具：**open_file / launch_app**，全部走人工确认。
> 网址打开由 [P20.2 工作台浏览器](P20.2-工作台浏览器.md) 提供，不在本阶段。
> 2026-10-23 定稿，版本 2.17.0。

## 1. 范围

| # | 能力 | 工具 | 入口 |
|---|---|---|---|
| 1 | 用默认程序打开文件/文件夹 | `open_file(path)` | 网页问一问、快捷栏普通问答 |
| 2 | 按名字启动开始菜单程序 | `launch_app(name)` | 同上 |

**不做**：打开网址、读取网页正文、控制浏览器、执行任意命令行、写入任意路径。

## 2. 工具契约

```json
{"name": "open_file",
 "input_schema": {"type": "object",
   "properties": {"path": {"type": "string",
     "description": "文件或文件夹的绝对路径，例如 D:\\课件\\网络.pdf"}},
   "required": ["path"]}}

{"name": "launch_app",
 "input_schema": {"type": "object",
   "properties": {"name": {"type": "string",
     "description": "开始菜单里能搜到的程序名，例如「记事本」"}},
   "required": ["name"]}}
```

工具描述要写清：**执行前会弹确认框**，用户拒绝就不执行；不要声称已经打开。

返回给模型（同时作为 `tool_end.preview`）：

| 结果 | 内容 |
|---|---|
| 成功 | `已打开文件：D:\课件\网络.pdf` / `已启动程序：记事本` |
| 拒绝 | `没有打开：用户没有确认这次操作。` |
| 校验失败 | 中文原因（路径不存在 / 不允许可执行文件 …） |

## 3. 安全规则（单一落点：`agent/tools/system_tools.py`）

### open_file

1. 空串、超过 4096 字符 → 拒绝；
2. 相对路径 → 拒绝（不依赖服务进程的 cwd）；
3. UNC 路径（`\\server\share`、`//server/share`）→ 拒绝（会触发网络访问）；
4. `resolve()` 后命中 `ops.PROTECTED`（`C:\Windows`、`Program Files`、`ProgramData`）→ 拒绝；
5. 可执行/脚本扩展名 → 拒绝：
   `.exe .bat .cmd .ps1 .msi .lnk .url .scr .com .vbs .js .jse .wsf .hta .cpl .reg`；
6. 路径不存在 → 拒绝并说明；
7. 文件 → `os.startfile`；目录 → 同样 `os.startfile`（资源管理器）。

### launch_app

1. 名字去空白后 1–60 字符；
2. 复用 `ops.start_menu_apps()` 建立索引，`ops.find_app()` 精确/包含匹配；
   索引 = 开始菜单 `.lnk` + `Get-StartApps` 枚举的 UWP 应用
   （Windows 11 的记事本/计算器没有 `.lnk`，真机验收时补上）；
3. 找不到 → 返回「没找到」+ 最多 10 个候选程序名，不猜、不执行；
4. 启动目标只来自索引：`.lnk` 或 `shell:AppsFolder\<AppID>`，一律 `os.startfile`，
   不接受用户给的路径或命令行参数。

## 4. 复用与重构（不复制第二套）

`ask/ops.py` 已有电脑助手的 `open` / `launch_app`。本轮抽成公共函数：

```python
def open_path(path: str) -> str        # 校验 + os.startfile + 返回一句话
def launch_by_name(name: str, index=None) -> str
```

- `ops.execute()` 的 `open` / `launch_app` 改为调用这两个函数；
- 电脑助手因此**同步收紧**：可执行扩展名、UNC、系统目录都拒绝（以前 `open` 只拦系统目录）；
- 电脑助手的 `open` 仍可打开 http/https 网址（走默认浏览器），但**网页 Agent 的 `open_url` 走 P20.2 的工作台浏览器**，两者不是同一条路径。

## 5. 确认与拒绝

- 两个工具加入 `schemas.CONFIRM_TOOLS`（**不进** `WRITE_TOOLS`：不改数据，但有系统副作用）；
- `WRITE_LABELS` 增加：`open_file: 打开文件`、`launch_app: 启动程序`；
- `write_summary()` 增加分支，确认框显示完整路径/程序名（不截断到看不出目标）；
- `loop.py` 的拒绝文案从「用户没有确认这次写入」改为「用户没有确认这次操作」，
  同步更新现有断言；
- 只在非 `quiz` 模式暴露（`schemas_for` 里 `mode != "quiz"` 才加）。

## 7. 测试（先必红）

新文件 `tests/test_p20_open.py`：

1. `open_file` 校验：空、相对路径、UNC、系统目录、可执行扩展名、不存在、正常文件（mock `os.startfile`）、目录；
2. `launch_app`：mock 开始菜单索引，精确/包含命中，找不到返回候选；

4. `loop` 拒绝路径：`confirm` 返回 False → `os.startfile` 未被调用，工具结果含「用户没有确认」；
5. 电脑助手回归：`ops.execute({"op":"open","path":"...\.exe"})` 拒绝；
6. 既有 `test_agent_p16*`、`test_assistant` 全量不回归。

## 8. 明确不做

- 打开网址（P20.2）；
- `fetch_url` / 网页正文读取；
- 任意命令行、任意脚本执行；
- 写文件到任意路径（`write_study_file` 仍限「学习档案」）；
- 打开系统目录、UNC 路径、可执行文件。
