### fact-net-tcp-handshake · 通过
- **问**：用一句话解释 TCP 三次握手
  **答**：三次握手是为了让双方各自确认“我的发送能力对方能收到、对方的发送能力我也能收到”，从而同步初始序列号并建立连接。 要点： - 过程：客户端发 SYN（带自己的初始序号 seq=x）→ 服务端回 SYN+ACK（seq=y, ack=x+1）→ 客户端回 ACK（ack=y+1）。 - 为什么是三次而不是两次：两次握手时服务端无法确认客户端已经收到自己的 SYN，也无法确认客户端具备接收能力，且旧连接的迟到 SYN 会导致服务端白白建立连接、浪费资源。 - 易错点：第三次 ACK 时可以携带数据，前两次不行；SYN 会消耗一个序号，所以 ack 是 x+1 而不是 x。 这与你的六级目标无关，只是普通知识题；本地资料里没有相关内容，以上按通用知识作答。
