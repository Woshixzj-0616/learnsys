## 1. 为什么要等

P13 是平台抽象（ContextSnapshot、统一 Service 入口）。抽象层只有在「六级单点确实被每天使用」
时才有意义；否则会抽象出一套没人用的接口。所以先用 14 天真实数据说话：
**达标 → 进 P13；不达标 → 停止平台化，继续打磨六级单点功能。**

## 2. 六条成功线与口径

| # | 判据 | 数据来源 | 脚本口径 |
|---|---|---|---|
| 1 | 14 天内 ≥ 10 天实际使用 | `asks` + `service_runs` + `cet6_progress` + `cet6_events` 的日期并集 | 任一天有六级问答、翻译、进度或事件即算「用过」 |
| 2 | 使用日每天 ≥ 3 次「带上下文提问 / 划词翻译」 | `asks`（会话 `module=cet6`）/ `service_runs(kind=translate)` | 严格口径只算提问；宽口径提问+翻译。翻译按调用次数，整段译文会按 12 句分块，属**上限** |
| 3 | 分析结果 0 丢失 | `service_results` | `status=error` 记丢失；`pending` 超过 10 分钟记卡死 |
| 4 | 重复请求 < 10% | `service_runs` | `cache_hit=1` 的次数占分析+翻译总调用数 |
| 5 | 首 token < 2s，完整回答 P95 < 15s | `asks.first_ms` / `asks.ms`（仅六级会话） | 最近秩法 P95；`first_ms` 从 2.6.0（2026-10-21）起才有记录 |
| 6 | 抽样 20 次，引用当前句/试卷正确 ≥ 18 次 | 人工填 `docs/闸门-抽检.csv` | 脚本累加「抽样数 / 引用正确数」 |

第 6 条无法自动判断：回答里的引用是否正确只能人看。**建议每周抽 10 次**，
在 CSV 里记一行（日期、抽了几次、其中引用正确几次、备注）。

## 3. 窗口内的动作

- **用户**：正常用六级精听；提问和翻译尽量从工作台 HTTP 页面进（`file://` 模式不计入观测）。
- **每周一次**：运行报告，看趋势；不用每天跑。
- **抽检**：每周随机挑 10 条「直接问」的回答，核对它引用的句子/试卷是否正确，填 CSV。
- **出问题**：只修六级 bug 和数据错误；新功能、平台代码一律不进这个窗口。

## 4. 冻结范围（重要）

窗口内**不写**：

- `ContextSnapshot` 抽象层、上下文条、选区动作框架
- 统一 Service 网关、模型路由、成本面板
- MCP、FSRS、生词统一表等 P13/P14 内容

窗口内**可以**：

- 修六级工作台/后端的 bug、错句、同步问题
- 补观测字段（例如本次新增的 `asks.first_ms`）
- 改文档、加测试

## 6. 已知观测缺口

1. `first_ms` 只在 2026-10-21 之后有；之前的会话没有首 token 数据。
2. 翻译「动作数」包含整段译文的分块调用，比真实点击次数高；严格判定看第 2 条的「只算提问」。
3. 原生快捷栏（`Alt+Q`）的问答不算六级实验；它走 `module=ask`。
4. 抽样正确率完全依赖人工记录，没有自动替代品。
