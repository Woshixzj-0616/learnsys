## 0. 一句话

工作台新增「Agent 中枢」页：写一个任务，选 Claude Code / Codex，在指定目录**只读**执行，
流式看过程，结果自动存成学习档案。

## 1. 方向对账

10-21 的方向是「工作台是上下文与服务的枢纽，不是所有 Agent 的老板」。本阶段把它修订为：

- **中枢 = 派活台**：用户显式把一整件事交给某个本机 agent，工作台负责启动、展示、留痕；
- **不是编排器**：不自动拆任务、不自动多 agent 协作；那要等 P26.1–P26.3 的真实使用数据。

## 5. 安全边界（硬约束）

- **只读**：Claude 用 `--restricted --permission-mode plan`，禁 MCP；Codex 用 `--sandbox read-only`；
  绝不使用 `--dangerously-bypass-*`。
- **目录白名单**：`设置.json` 的 `agents.allowed_roots`；空 = 只允许数据目录。拒绝 UNC、系统目录、不存在的目录。
- **不接管登录/密钥**：用各 CLI 自己的登录态；工作台不读写 `~/.claude` / `~/.codex` 的凭据。
- **可停**：超时默认 300 秒（上限 900），取消走进程树 kill。
- **有界**：prompt ≤ 20000 字，输出 ≤ 5MB，事件文本单条 ≤ 4000 字。
- **并发**：同一 agent 同时只跑一个任务；不同 agent 可并行（最多 2 个）。
- **输出当资料**：agent 的返回不自动执行、不自动写回问答/错题。
