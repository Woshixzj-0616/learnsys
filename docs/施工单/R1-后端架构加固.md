## R1.1 拆 `loop.run()`（先做）

目标：`run()` < 120 行，`loop.py` < 400 行，事件顺序不变。

建议拆分（函数名可调整，职责不要混）：

| 新函数 | 接管内容 | 估计行数 |
|---|---|---|
| `_prepare(request, cfg, abort)` | 就绪/abort、`_plan_config`、route 事件、档案/记忆、视觉转述、system/messages、`_RunState`/`_tool_context` | 70–90 |
| `_stream_once(...)` | 一次模型流式调用：text/thinking/activity 透传、usage 合并、返回 `ProviderResult` | 30–40 |
| `_run_tool_loop(...)` | 工具轮次主循环；调用 `_handle_tool_call` | 60–80 |
| `_handle_tool_call(...)` | `make_plan`、确认闸门、`_execute_tool`、计划状态更新、tool_result | 80–100 |
| `_retry_thinking_only(...)` | 思考-only 自动快答重试 | 25–35 |
| `_finish(...)` | OCR 提示、计划收尾、自检/重写、拒绝写提示、done | 60–80 |
| `run()` | 只做编排与异常映射 | 80–110 |

注意：

- 生成器函数要用 `yield from` 转发事件；不要在抽取时改变事件顺序。
- `_RunState`、`cfg_holder`、`messages` 仍是一条流水，别复制状态。
- 先加**事件序列测试**再拆：正常文本、工具调用、确认拒绝、思考-only 重试、ProviderError。

验收：全量 683+ 测试、事件序列测试、体量门禁；真实模型冒烟一轮。

## R1.4 部署脚本

- 新增 `tools/deploy.py`，默认 `--dry-run`，真实执行需 `--yes`。
- 流程：停 `LearnSysGuard` → 停 `dist\学习工作台\学习工作台.exe` → 备份目录 →
  从 `dist-build\学习工作台` 换入 → `--background` 启动 → 轮询 `/api/health` →
  恢复并触发守护；失败时自动回滚。
- `--rollback`：换回最近备份并重启。
- 用一次 2.20.1 部署验证（备份保留）。
