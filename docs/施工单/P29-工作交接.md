## 3. P29.1：项目 CRUD 与页面

### 3.1 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/projects` | 列表（已有；`status=active` 过滤） |
| POST | `/api/projects` | 按 `name` upsert（已有；补 `repo_path/status/next_step/risk`） |
| PATCH | `/api/projects/{id}` | 部分更新任意字段；`name` 改重复 → 400 |
| POST | `/api/projects/{id}/archive` | 置 `status=archived`（不物理删除，保留交接记录） |
| POST | `/api/projects/{id}/handoff` | 生成本地 HANDOFF，回写 `handoff_path`，返回正文 + 路径 |
| GET | `/api/projects/{id}/handoff` | 读已生成的 HANDOFF（不存在 → 404） |

口径：

- 路由只做鉴权与转接，SQL 全在 `store/personal.py`（门禁 `scan_route_sql`）。
- `project_refs` **不加列、不升 schema**；`status` 只允许 `active / paused / archived`。
- 归档项目在默认列表隐藏（`status=active`），`status=all` 才显示。

### 3.2 页面 `#/projects`

- 新插件 `learnsys/plugins/projects/plugin.json`（`type: native-page`，`entry: pages/projects.html`，`script: js/pages/projects.js`，分组「工具」）。
- 顶部：项目数、进行中数、待办下一步数。
- 项目卡：名称、状态徽章、仓库路径（不存在时标「路径失效」）、下一步、风险、更新时间；
  操作：编辑、生成交接、打开交接、归档。
- 新建/编辑表单：名称（唯一）、仓库路径、状态、下一步、风险。空名称不提交。
- 生成交接后：卡片下方展开预览（前 40 行）+ 「打开文件夹」提示路径。
- 今日页工作域卡 `href` 改为 `#/projects`（`services/home.py::_work`）。

## 4. P29.2：HANDOFF 生成器

### 4.1 新文件 `learnsys/services/handoff.py`

```python
def build(conn, project: dict) -> str        # 纯拼装，不调模型
def output_path(project: dict) -> pathlib.Path
def write(conn, project: dict) -> tuple[str, pathlib.Path]
```

### 4.2 内容结构（顺序固定）

```markdown
# HANDOFF · <项目名>
> 自动生成，不手改；<YYYY-MM-DD HH:MM>

## 状态
- 状态：active / paused
- 下一步：<project_refs.next_step 或「未填写」>
- 风险：<project_refs.risk 或「无」>
- 最近更新：<updated_at>

## 仓库指针
- 路径：<repo_path>（不存在时写「路径失效」）
- 入口：README.md / AGENTS.md（存在才写）
- 最新施工单：docs/施工单/<最近 2 个文件名>（存在才写）
- 架构定位：docs/架构-前后端.md 第 7 节
- 最近提交：<git log -3 --oneline>（失败静默省略）

## 外部记忆（只读）
- 项目现状：<完整路径>
  <首段，≤200 字>
- 坑与经验：<完整路径>
  <首段，≤200 字>

## 交接约定
- 先在仓库根读 AGENTS.md / README.md，再按上面的指针看具体文件；
- 改代码前查 `docs/架构-前后端.md` 第 7 节「改动定位表」；
- 交接页是快照，与仓库冲突时以仓库为准。
```

### 4.3 读取边界（必须守住）

| 项 | 规则 |
|---|---|
| 仓库 | 只读 `README.md`、`AGENTS.md`、`docs/施工单/` 目录名、`docs/架构-前后端.md` 是否存在；**不遍历、不读业务代码** |
| 文件大小 | 单个文件最多读 64 KB；只取标题与首段 |
| git | `git -C <repo> log -3 --oneline`，2 秒超时，失败静默省略 |
| 外部记忆 | 根目录 `config.USER.get("handoff_memory_root")`，默认 `D:\cahier\智库\智库\Codex记忆系统`；不存在 → 写「未配置」 |
| 项目名 | 写路径前清洗 `<>:"/\|?*` 与首尾空格；空名拒绝 |
| 输出 | 只写 `DATA_ROOT/projects/<清洗后的 name>/HANDOFF.md`，**绝不写进 repo_path** |
| 长度 | 全文 ≤ 6000 字，超出截断并注明 |

### 4.4 设置项

`设置.json` 新增可选键 `handoff_memory_root`（默认 Codex 记忆库路径）。
写入设置模板注释；改后重启生效（沿用现有设置口径）。

## 5. P29.3：派活带交接包

### 5.1 schema 13 → 14（只加列）

- `schema_agents.py` 的 `agent_tasks` 末尾加 `project_id INTEGER NOT NULL DEFAULT 0`。
- `migrate.py::_migrate_columns` 白名单加同一列。
- `SCHEMA_VERSION = 14`。
- `store/agent_tasks.py`：`_TASK_COLUMNS` / `_task_dict` / `add_task` / `add_queued` 支持 `project_id`。

### 5.2 认领时拼交接包

- `TaskIn` 加 `project_id: int = 0`；建任务时校验项目存在（不存在 → 400）。
- `queue.compose_chain_prompt(prompt, parent_id, result, project_block="")`：
  顺序为「父结果头 → 项目交接包 → 本轮任务」。交接包截断到 ≤4000 字。
- 读交接包：任务 `project_id > 0` 时读该项目 `handoff_path`；文件不存在就先 `handoff.write()` 一次。
- **DB 的 `prompt` 仍存用户原文**（与任务链同口径：组合文本只用于运行）。

### 5.3 前端

- `web/js/pages/agents/compose.js`：表单加「项目」下拉（`/api/projects?status=active`），
  默认「不挂项目」；提交带 `project_id`。
- 任务列表显示项目名（有则显示，无则空）。

## 11. 不做 / 风险 / 回退

**不做**

- 不自动扫描磁盘找仓库；项目必须手动登记。
- 不把仓库代码/文档正文喂给模型；HANDOFF 不调模型。
- 不写回项目仓库；不修改外部 Codex 记忆库。
- 不做项目间依赖图、自动排期、自动跑任务。
- 不删除项目（只归档）。

**风险**

| 风险 | 处理 |
|---|---|
| 外部记忆库路径不存在 | 写「未配置」，不阻塞生成 |
| 仓库路径失效/被移动 | 卡片与 HANDOFF 标「路径失效」，仍可编辑 |
| HANDOFF 过长 | 全文 ≤6000 字，交接包 ≤4000 字 |
| 交接包把任务 prompt 推过 20000 上限 | `compose_chain_prompt` 预算里扣掉 project_block，超长只截交接包 |
| schema 14 迁移失败 | 只加列；`migrate.py` 幂等；部署前生产库副本回放 |

**回退**

- 代码 revert；`agent_tasks.project_id` 留在库里无害。
- HANDOFF 文件是普通 Markdown，删掉不影响任何数据。
