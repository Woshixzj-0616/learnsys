# P35 · 问答内核与信息源重构方案

> 状态：方案已拍板（2026-11-24）
> 目标：把学习工作台里的 Agent 从「工作台内嵌助手」改成「专属于负责人的学习助手」。
> 三条总原则：**一个 Agent / 多个 App**；**本地优先 / 网络补充**；**天生一份**。
>
> 本文只写方案，不改代码。后续验收按第 12 节清单逐条核对。

## 拍板记录（2026-11-24）

1. **助手作为一级入口**：是。
2. **CET6 内置 AI 分三期退役**（标记 legacy → 隐藏 → 重建 HTML 移除）：可以。
3. **工作/生活/系统工具从助手硬移除，保留 work profile**：可以。
4. **模型策略**：`deepseek-flash` 默认 + 5 类信号升 `deepseek-v4-pro`：行。

## P35.0 基线结果（2026-11-24）

- 题库：`docs/golden/qa-golden-50.json`（50 条：事实 14 / 多轮 11 / 本地 11 / 英语 7 / 代码 7）。
- 报告：`docs/施工单/P35-基线报告.md`；原始结果 `eval/qa/latest-baseline.json`。
- 方法：只读生产库，取历史回答回溯评分；**本次不新调模型**。
- 摘要：**通过 29 · 未通过 3 · 人工复核 5 · 待在线评测 13**（P35.0 时 `local-vocab` 是 1 个能力缺口；P35.1 已补）。
- 关键未通过：
  - `multi-cpp-emplace`：历史最终答案把 `vector` 说成没有 `emplace`，**事实错误**；正确是 `vector` 有 `emplace(pos, args...)`，用户代码缺位置参数。基线判失败。（P35.1 在线试点里 `run_code` 能在第 3 轮纠正。）
  - `multi-rsync-locate`：第 **4** 轮才纠正（目标 ≤2）；
  - `multi-siege-admin`：第 **3** 轮才停止重复建议（目标 ≤2）。
- 人工复核：`multi-quicksearch-key`、`multi-logic-or`、`multi-block-plus1`；关键词过了但用户仍纠正，说明初筛不够。
- 能力缺口（P35.0 当时）：`local-vocab` 没有 `list_vocab` 工具；P35.1 已补，当前题库期望工具已更新。
- 待在线评测：12 条合成题（本地数据/部分英语/快排强模型对照）没有历史回答，留给 P35.1 在线 harness。

**结论：基线可量化，且与之前对话分析的痛点一致——多轮纠错是主战场，本地数据工具覆盖不足。**

## 0. 一句话结论

- **Agent 是独立的一等入口**：助手页 + 快捷栏 + 应用内「问助手」，不是六级/英语页里的内嵌 AI。
- **App 是外部应用**：今日 / 英语 / 实践 / 资料 / 工具，各自拥有 UI 和数据；对 Agent 只提供 **ContextSnapshot + Service**，不提供 prompt、tool、model。
- **信息源按固定顺序取**：当前上下文 → 本地结构化数据 → 本地非结构化数据 → 网络 → 模型通识；每一级都要能引用、能核对。
- **工作/生活/派活退出问答默认路径**：不是删代码，是移到单独的工作 profile。

## 2. 目标架构：App / Context+Service / Agent 三层

```text
┌─────────────────────────────────────────────────────────────┐
│ App Layer（外部应用，各自拥有 UI 和数据）                    │
│  今日 / 英语（CET6 为外部 iframe）/ 实践 / 资料 / 工具       │
│  对外只提供：ContextSnapshot + Service                       │
└──────────────────────────┬──────────────────────────────────┘
                           │ 只读服务 / 显式上下文
┌──────────────────────────▼──────────────────────────────────┐
│ Context & Service Layer（只读上下文与服务）                  │
│  Source Registry：资料 / 问答 / 错题 / 复习 / 训练 / 六级    │
│                   知识掌握 / 录像 / 本机文件 / 网络          │
│  ContextSnapshot 九键（已有）                                │
│  Service Catalog（已有 6 项，按第 4 节扩展）                 │
└──────────────────────────┬──────────────────────────────────┘
                           │ 工具 = 服务适配器
┌──────────────────────────▼──────────────────────────────────┐
│ Agent Layer（一个助手）                                      │
│  助手页 / 快捷栏 / 应用内「问助手」                          │
│  上下文装配 · 检索 · 澄清 · 证据 · 升级 · 记忆 · 评测        │
└─────────────────────────────────────────────────────────────┘
```

**边界规则：**

- App 不得声明 prompt、tool、model、memory scope；只能声明「我能提供什么上下文」「我暴露哪些读写服务」。
- Agent 不得直接读 App 的 SQL；只能走 Service。
- Agent 不得把工作/生活工具默认带进学习问答；需要时切工作 profile。
- ContextSnapshot 是**数据**，不是指令；App 不能借它注入提示词。

### 2.1 App Manifest 契约（在现有 plugin.json 上做可选扩展）

```json
{
  "id": "english",
  "name": "英语",
  "entry": "pages/english.html",
  "agent_entry": "floating",
  "context_providers": ["cet6.current_item", "train.current_question", "review.current_card"],
  "read_services": ["cet6.context", "train.summary", "review.due"],
  "write_services": ["save_training_error", "add_vocab", "rate_review"]
}
```

- `agent_entry`：`floating`（应用内浮出「问助手」）/ `deep-link`（只给链接）/ `none`。
- `context_providers`：这个 App 在用户点「问助手」时能给出的快照类型。
- `read_services` / `write_services`：App 对外暴露的服务；Agent 也走同一份。
- **不新增 `prompt`、`tools`、`model` 字段**——这是本次分离的关键。

### 2.2 Agent 入口设计

| 入口 | 定位 | 说明 |
|---|---|---|
| **助手页（原 `ask`）** | 主入口 | 从 `HIDDEN_NAV` 移出，改名「助手」；放今日之后或之前，由负责人拍板 |
| **快捷栏 Alt+Q** | 全局快捷入口 | 与助手页同一会话真相；不再只写 `thread` |
| **应用内「问助手」** | 带上下文唤起 | 英语/资料/今日/录像页浮出按钮，传 ContextSnapshot，不嵌第二套 AI |
| **CET6 iframe** | 外部应用 | 不再内嵌 Agent；只保留「问助手」唤起或深链 |

## 3. 信息源注册表（本方案的核心）

### 3.1 取数优先级（固定，不按模型喜好变）

| 优先级 | 来源 | 什么时候用 | 引用要求 |
|---|---|---|---|
| 1 | **当前上下文快照** | 用户从某个 App 点「问助手」 | 写清 App / 对象 / 位置 |
| 2 | **本地结构化数据** | 问「我错在哪 / 我学了什么 / 课件怎么讲 / 我掌握得怎么样」 | 资料 id + 页码、错题 #、复习卡、训练 # |
| 3 | **本地非结构化数据** | 问「我以前问过什么 / 老师怎么讲的 / 那份 PDF」 | 时间 + 来源、文件路径 |
| 4 | **网络** | 本地没有、时效性、外部事实、官方文档 | URL + 读取日期 |
| 5 | **模型通识** | 以上都没有，且是稳定常识 | 明确标「凭记忆 / 未验证」 |

**硬规则：**

- 本地能回答的，不联网。
- 个人数据不上网络：搜索只发问题关键词，不发资料正文、错题原文、对话原文。
- 网络结果只引用真读过的 URL；没读过的不写。
- 本地来源与网络冲突时并列，不擅自选一个。
- 数据过期要提示：资料 `updated_at`、六级进度 `last_review`、复习卡 `due`。

## 4. Context 与 Service 契约

### 4.1 ContextSnapshot（沿用现有九键）

`learnsys/context.py` 已有固定九键：`surface / object_type / object_id / title / selection / surrounding / learning_state / recent_actions / provenance`，上限 20KB。

本方案只补充约定：

- `provenance.app` 写 App id（`english` / `materials` / `today` / `recording`）。
- `provenance.version` 写页面/数据版本（如 `cet6:20261119a`）。
- `learning_state` 只放**当前学习状态**，不放工作/生活。
- App 只能传快照，不能借快照写指令；Agent 把快照当数据。

### 4.2 Service Catalog 扩展

现有服务（`services/catalog.py`）：`translate` / `define` / `explain` / `summarize` / `translate_items` / `cet6_analyze`。

新增只读服务（Agent 工具与 App 共用，不复制实现）：

| 服务 | 说明 | 对应数据 |
|---|---|---|
| `materials.search` / `materials.read` | 资料检索 / 分段读 | `materials` |
| `records.search` / `records.today` | 问答/转写/屏幕记录 | `asks` / `messages` / `transcripts` |
| `review.due` / `review.recent_wrong` | 到期卡 / 最近错题 | `review_state` / `wrong_items` |
| `train.summary` | 写作/翻译档位趋势、错误画像 | `train_submissions` |
| `cet6.context` | 当前试卷/段/句/循环/完成 | `cet6_progress` / `cet6_events` |
| `knowledge.mastery` | BKT 掌握度 | `knowledge_points` / `attempt_points` |
| `recordings.list` / `recordings.search` | 录像列表 / 转写检索 | `sessions` / `transcripts` |
| `local_files.search` / `local_files.read` | 白名单本机文件 | `local_files` |
| `web.search` / `web.read` | 联网搜索 / 读正文 | 网络 |

写服务沿用现有：`vocab.add/delete`、`review.rate`、`wrongbook.save`、`training_error.save`、`material_note.save`、`memory.save/forget`；全部走确认。

**约束：**

- 工具层只做参数校验和排版，不写 SQL；SQL 留在 store。
- App 与 Agent 调同一个服务；不允许 App 一份、Agent 一份。
- 服务返回统一 `Evidence`：`{source, title, url/id, snippet, page, retrieved_at}`；引用校验只看这个结构。

### 4.3 会话真相

| 数据 | 角色 |
|---|---|
| `conversations` / `messages` | **唯一会话真相** |
| `asks` | 时间线 / 检索索引（保留） |
| `agent_runs` | 运行流水（模型、工具、耗时、成本） |
| `service_results` | 长任务结果资产（已有） |

快捷栏、助手页、应用内唤起都写 `conversation_id`；`asks.thread` 只做旧数据兼容。

## 5. Agent 设计

### 5.1 提示词：文件化、分层、短内核

```text
learnsys/agent/prompts/
  core.md          # 身份、语言、回答契约、不确定、引用、纠错协议（约 700 token）
  styles/
    explain.md     # 讲解
    guide.md       # 引导
    quiz.md        # 测验
    quick.md       # 速答
  subjects/
    networks.md    # 计算机网络

    english.md     # 六级写作/翻译/批改
```

`prompts.py` 只做拼装；总 system prompt 目标 1.2–1.8k token（现在 4.7–5.4k）。

**core.md 回答契约：**

1. 先给结论（1–3 句）。
2. 给依据：资料 id/页码、错题 #、训练 #、网页 URL、代码运行结果。
3. 给「与你的关系」：你在哪错过、这章练没练、目标是什么；只在相关时说。
4. 不确定就标：`未验证 / 凭记忆 / 需要你确认`。
5. 下一步只给一个最小动作，不强行出题。

**纠错协议（纠错轮专用）：**

1. 先复述：「你是问 X，不是 Y，对吗？」
2. 列已确认/已排除的事实；不再重复被排除的建议。
3. 仍不确定就给 2 个候选解释让用户选，不要只说「贴原文」。
4. 本轮升级强模型 + 重新检索。

```text

```

### 5.5 证据与校验

- `verify.py`：回答后检查引用是否真的出现在工具结果里；伪造的资料 id / URL 删除或标「未验证」。
- 代码事实：`run_code` 编译最小片段验证（如 `vector` 是否有 `emplace`）。
- 资料事实：答案必须能指到资料 id/页码；没有就说「资料里没有」。
- 网络事实：URL + 读取日期；没有就不写。
- 冲突：并列双方，不擅自选。

### 7.2 CET6 边界（重点）

CET6 精听工作台是**外部应用**：

- 自己的 UI、自己的数据（`cet6_progress` / `cet6_events` / 听写/自评/意群流水）、自己的构建链（`D:\cet6_tool` → `cet6/工作台/精听工作台.html`）。

- 它**不再**调用 `/api/agent/chat` 时带 `surface=cet6` 的专属 prompt / 工具 / 快模型。
- 它的内置 AI 抽屉标记为 legacy：Phase 1 不改，Phase 2 隐藏，Phase 3 重建工作台 HTML 时移除。
- Agent 可以通过只读服务 `cet6.context` 回答「我刚才循环的那句 / 这段我标了什么」，但 Agent 不活在 CET6 里。

### P35.1 在线试点（10 条，2026-11-24）

- 报告：`docs/施工单/P35-在线试点-20261124-105144-rescored.md`（按修正后的题库重算）。
- 结果：**7 通过 / 3 人工复核 / 0 未通过**；约 0.28 元。
- 通过：TCP 三次握手、`multi-cpp-emplace`（`run_code`，第 1 轮）、最近错题、资料库 TCP、生词本 `list_vocab`、英语批改、前缀表达式（`run_code`）。
- 人工复核（首次通过都在第 3 轮，目标 ≤2）：`multi-rsync-locate`、`multi-quicksearch-key`、`multi-siege-admin`。

**发现**：

1. **golden set 自身有一处事实错误**：`vector` 从 C++11 起**有** `emplace(pos, args...)`，第一个参数是位置迭代器；用户只传 `(char,int)` 才编译失败。旧题库把「vector 没有 emplace」当成正确答案，已修正。修正后试点第 1 轮答对。
2. **rsync 首轮被个人状态带偏**：`agent_state` 里的英语卡点让模型把「那怎么定位错误」理解成英语改错；这是 P35.2 要把 `agent_state` 学习化、减少无关卡点噪声的直接证据。
3. **纠错协议有效但启动太晚**：siege 到第 4 轮才采纳「我没有 Admin.jsp」；模型在第 1–3 轮仍按「文件在服务器上」回答。说明「先确认前提」应该在**第一轮歧义时**就触发，而不是等用户说「你听不懂」。
4. **quicksearch 需要原题内容**：只有题链、没有题干时，模型会反复要题；应用内唤起必须带 ContextSnapshot（当前题/当前资料/选中文本）。
5. **资料题有工具循环风险**：一次 5 次工具调用通过，另一次触发「工具调用次数太多」上限；需要工具预算/收敛提示（P35.2）。
