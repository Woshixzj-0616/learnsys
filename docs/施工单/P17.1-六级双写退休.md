# P17.1 · 六级双写退休准备

> 目标：在**不直接退休**的前提下，把「连续 14 天无差异」变成可验证的证据，并准备好
> 11-04 的切换开关。2026-10-23 开工，默认不切换。

## 1. 背景

六级精听当前是双写：逐句进度先写 `localStorage`（`WB.state` → `saveState()`），
再经 `58-sync.js` 防抖推到 `POST /api/cet6/sync`，落到 `cet6_progress`。
文档判据是：**`cet6_progress` 与 localStorage 连续 14 天无差异 + HTTP 覆盖日常使用**；
之后 `file://` 降为只读/导出，HTTP 成为唯一写入口。

问题：此前没有任何自动化差异记录，到 11-04 拿不出证据；直接退休等于跳过判据。

## 2. 三个口径纠正

1. **`analysis` 不在 `cet6_progress`**：`58-sync.js` 虽带 analysis，但 `store/cet6.py`
   忽略它；分析真源是 `service_results`，本地 `state.analysis` 只是显示缓存
   （`60-insights.js::restoreLatest` 服务端优先）。不给 `cet6_progress` 加 analysis 列。
2. **`paper_id` 有两个身份**：服务端 `cet6_progress.paper_id` = `WB.session.paperDir`（目录名）；
   localStorage key 用 `paper.paper_id`（目录名 + 时长后缀，见 `stateKey()`）。不能混用。
3. **13 天就是 13 天**：证据最早从 10-23 开始；到 11-04 只有 13 个日历日，第 14 天是 **11-05**。
   报告必须输出 `available_days=13 / eligible=false / earliest=11-05`。

## 3. 「无差异」怎么定义

不是「本地和服务端时刻相等」，也不是「推送后自己跟自己比」。定义为
**打开试卷时的写前比对 + 写后校验**：

1. 前端把整卷本地快照（all section/item/sentence 的 done/tags/note/loops/plays）发给
   `POST /api/cet6/sync-paper`，附带 `hydration`、`client_day`、`mode`、`push_failed`；
2. 服务端**写入前**读该卷 `cet6_progress`，逐行逐字段比对，差异落 `cet6_dualwrite_diffs`；
3. 再执行写入；
4. 写后按行数/关键字段校验一次 `post_ok`；
5. 一次请求同时完成「观测 + 收敛 + 写入验证」。

**干净的一天**：当天至少一条整卷审计（`compared>0`），且所有审计满足
`diff_fields=0`、`missing_db=0`、`orphan_blocking=0`、`invalid=0`、`post_ok=1`、
`status in (ok, ok_minor)`、`mode=http`。仅 `plays` 的小差异（≤2）记 `minor_fields`，
默认不阻断；`--strict-plays` 时阻断。没有审计记录的日期算「未知」，会打断连续天数。

比较规则：

| 字段 | 规则 |
|---|---|
| done | 按句子布尔值比较；`done=[]` 表示整段清零，不能当「没传」 |
| tags | 去空、集合比较（标签不含顿号，服务端用 `、` 拼接安全） |
| note | 原串比较，两边按 1000 字截断；前端 textarea 已加 `maxlength=1000` |
| loops/plays | 整数比较；plays 归 minor |
| 行存在性 | 以 `(section,item,sentence)` 并集；只统计「有意义」的行，新试卷全零行不算差异 |

## 4. 实现

### 4.1 表

- `cet6_dualwrite_runs`：一次整卷审计一行（ts/day/client_day/paper_id/mode/hydration/
  paper_sig/compared/diff_fields/minor_fields/missing_db/orphan_db/orphan_blocking/
  invalid/post_ok/status/error）。
- `cet6_dualwrite_diffs`：只记差异明细，干净的一天不写这张表。
- 都在 `learnsys/core/db/schema.py`，`CREATE TABLE IF NOT EXISTS`，旧库自动补。

### 4.2 后端

- `learnsys/services/cet6_sync.py`：`canonical_rows` / `compare_rows` / `audit_and_write`。
  空快照保护：本地 4 个同步字段全空、服务端有进度、`hydration != state` →
  记 `blocked_empty`，不写，返回 409。
- `learnsys/server/routes_cet6_sync.py`：
  - `GET /api/cet6/state?paper_id=`：从 `cet6_progress` 重建本地状态所需行；
  - `POST /api/cet6/sync-paper`：整卷审计 + 写入 + 写后校验；
  - 两者无 token，和现有 `/api/cet6/sync`、`/api/cet6/import` 一致；`null` Origin 可访问。
- `learnsys/server/cet6_models.py`：请求模型；`routes_cet6.py` 只 include 新路由。
- 保留 `POST /api/cet6/sync` 给增量编辑，不改入参。

### 4.3 六级前端

- 新 `04-mode.js`：`WB.FLAGS.retired`（00-core.js 构建常量）、`readOnly`、`ensureWritable`、
  只读横幅。
- 新 `56-dualwrite.js`（纯函数，node 可测）：
  `mapServerState`（服务端行 → state；Section 精确 → 字母回退 → item 标题 → 尾号 → 规范化；
  歧义一律 `unmatched`，该段跳过不写）、`canonicalRows`、`snapshotIsEmpty`、`paperSig`、`clientDay`。
- `58-sync.js`：`syncPaper()` 改为「先本地快照审计 → 409 则 hydration 后重试」；
  增量编辑仍走 `/api/cet6/sync`；`pagehide/visibilitychange` flush 防抖中的最后一笔。
- `90-boot.js`：先审计/恢复，再拉分析、生词、译文；审计期间 `hydrating=true`，
  4 个同步字段的写操作被拦。
- `20-paper.js`：`toggleDone/toggleError/setNote/bumpLoopStat` 加只读守卫；
  `bumpLoopStat` 后补 `schedule()`，loops/plays 不再等下次打开。
- `05-bridge.js`：退休后 file:// 不推送、不合并 legacy 快照；HTTP 的恢复交给 58-sync。
- `70-vocab.js` / `60-insights.js` / `10-storage.js`：只读时拦生词写入、分析提交、导入。
- `40-render.js`：笔记 textarea `maxlength=1000`。

### 4.4 退休开关

`00-core.js` 的 `WB.FLAGS = { retired: false }` 是**唯一构建常量**。

- 不用运行时设置：`file://` 与 `http://127.0.0.1:8765` 是不同 origin，运行时设置在离线
  `file://` 读不到；切换本来就要重建工作台 HTML + 快照 + exe。
- `retired=true` 时：
  - HTTP：审计前必须先 hydration；服务端优先（done/tags 仍取并集防丢）。
  - file://：只读。不是把 `saveState` 全局 no-op（那会连 pos/starts/ab/loopCfg 一起坏），
    而是在 4 个同步字段入口 + 生词/分析/导入入口分别拦；本机状态仍可保存。
  - 页面顶部显示「只读模式 · 进度以学习系统为准 · 可以查看和导出，不能修改」。

## 8. 已知边界

- 本轮不做多标签 `rev`/冲突检测：两个标签同时写同一卷，后写覆盖前写；审计能记录差异，
  但不会阻止覆盖。
- `blocked_empty` 会让当天不算干净；这是为了保护服务端进度，属于预期行为。
- `done/tags` 合并取并集，可能让「另一处删掉的完成/标签」在下次打开时复活；这是沿用
  迁移桥的旧语义，退休后再评估是否改为严格服务端优先。
