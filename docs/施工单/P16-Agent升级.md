## 1. 四个阶段（顺序已确认）

### P16.1 计划 → 执行 → 自检（只读优先）

目标：复杂问题先出计划，再逐步调用只读工具，最后回核引用；不再「一口气答完」。

- 计划是显式事件（`plan`），界面上能看到步骤和当前进度；
- 每步工具调用有目标、有结果摘要；失败可换路，不静默跳过；
- 最后自检：引用是否来自工具结果、有没有编造页码/记录；
- **只读工具先行**；任何写操作（改档案、写错题、改记忆）必须用户确认；
- 验收：一个跨 3 个工具的真实学习任务（如「找出我最近错的题 + 对应资料段落 + 出 2 道变式题」）
  全程可回放；单元测试覆盖计划截断、工具失败、自检不通过。

### P16.2 文件 / 资料写入 + 代码运行沙箱

目标：让 Agent 能产出可运行、可保存的东西，而不是只在聊天框里给代码。

- 写入范围只允许数据目录（资料库 / 学习档案 / 错题导出），写前弹确认；
- 代码运行：临时目录 + 超时 + 输出上限 + 禁网（至少默认禁网），运行结果落审计；
- 不接管用户任意程序、不读系统目录；
- 验收：生成并运行一个 C++ 最小例子；写入一份资料笔记后能在资料页看到；失败有中文原因。

### P16.3 可观测性与成本

目标：每次工具调用、耗时、token、缓存命中都能追溯，不再靠猜。

- 新增 `agent_runs` / 复用 `service_runs`，**只留一份流水**；
- 记录：会话、模型、首 token、总耗时、工具名/参数摘要/结果摘要、tokens、成本估算；
- 设置页或独立面板：最近 N 次、按工具聚合、异常列表；
- 验收：一次真实对话能在面板里逐事件对上；不记录密钥/完整隐私正文。

### P16.4 真实任务 A/B 评测

目标：证明「加工具/加计划」真的更好，而不是更慢。

- 固定 10–20 个真实学习任务（查记录、读资料、出题、复盘、错题变式）；
- 指标：正确性（人工/引用回核）、首 token、总耗时、工具调用数、token 成本；
- 对照组：2.10.2 的单轮 Agent；实验组：P16.1–P16.3；
- 只有正确性不降、耗时/成本可接受才保留默认开启；否则做成开关。

## 2. 纪律（沿用现行约定）

- 一个功能一个落点；能一份就不做两份。
- schema 只做加法：`CREATE TABLE IF NOT EXISTS` / `ADD COLUMN` / `CREATE INDEX IF NOT EXISTS`。
- 写接口必须 `require_token`；错误信息中文。
- 先写会失败的测试，再实现；每个阶段跑满 444+ 测试再进下一阶段。
- 不自动 commit / push / 发版；等负责人发话。
- 每阶段先出粗版，验收通过再打磨。

## 3. 明确不做

- 不做任意 app 宿主 / 窗口管理 / 应用商店；
- 不做静默后台执行；所有写操作可见、可取消、可审计；
- 不为了「像 Claude Code」而堆工具；没有 A/B 证据的增强不默认开启。
