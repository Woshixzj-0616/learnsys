# P23 录像 · 真实使用实测方案

> 2026-10-25 · 针对生产 2.28.3 · 只回答三个问题，不做功能清单式验收

## 0. 为什么这样定

本机已有 3 段真实录像（10-25 上午）：

| 会话 | 时长 | 声音 | 结果 |
|---|---|---|---|
| 2 | 92s | 全程静音 | 无转写 |
| 3 | 118s | 12s 起有声音，85s 起有人声 | 10 条转写 |
| 4 | 7s | 全程静音 | 无转写 |

三条证据说明两件事：

1. **真实场景是「播视频课 / 知识视频，系统出声」**，不是线下课收音。录像只抓 WASAPI 回环，不抓麦克风——这是产品口径，不是缺陷。
2. **「没声音」是真实高发路径**（3 段里 2 段），必须单独验它是否诚实：不空跑分析、不编内容、不说「还在识别」。

会话 3 前 73 秒有声音但本地 whisper 转写为空，已单独复核：该段是前奏/BGM，没有可识别语音；转写从真正人声开始，**不是丢转写**。这项复核方法保留在场景 A 里，用来区分「丢转写」和「本来没人声」。

本轮只测三件事：**网课全链路能不能用 / 无声场景是否诚实 / 长录与中断会不会丢数据**。

不做：麦克风录制、多显示器、视频逐帧视觉、点提纲跳视频、PDF 导出——功能不存在或已明确后置，不占本轮工时。

## 2. 场景 A：一节完整网课（主场景，约 60 分钟）

目标：走完「录 → 转写 → 看 → 分析 → 问 → 出题 → 归档」全链路，量化音画同步和转写覆盖。

### 步骤

| # | 动作 | 记录点 |
|---|---|---|
| A1 | 浏览器打开「大号秒表 + 每秒提示音」页面（我可以生成） | 用来量音画同步 |
| A2 | 开始录像（横栏按钮），3 秒倒计时结束时秒表应为 00:00:00 | 倒计时是否准 |
| A3 | 录 20 秒秒表，切到网课，播放 10 分钟 | 至少切 6 页 PPT |
| A4 | 右键横栏「录像」→ 暂停 3 分钟；期间正常说话、放一段音乐 | 验证暂停不收音 |
| A5 | 右键「继续」，再播 30 分钟；中途切浏览器查资料 1 分钟再切回 | 验证切窗口不断录 |
| A6 | 用 `Ctrl+Alt+S` 停止；另一次短测试改用托盘「结束录像」 | 两个停止入口各验一次 |
| A7 | 页面自动跳到 `#/recordings?session=<id>` | 记录 saved 时间 |
| A8 | 等转写完成 | 记录首条落库时间、总条数 |
| A9 | 回放 4 个点：0:05、暂停前 5s、恢复后 5s、结尾 30s | 听滴答/人声是否对得上画面 |
| A10 | 点 3 条转写时间轴 | 跳转误差 |
| A11 | 看幻灯片列表，抽查 3 张 OCR 文字 | 是否清晰、有没有重复页 |
| A12 | 点「分析这段」 | 耗时、成本、五节结构 |
| A13 | 从分析里挑 3 条具体说法，回看视频找依据 | 是否编造 |
| A14 | 连续问 3 个问题（第 1 个回答完立刻问第 2、第 3） | 气泡是否独立、chip 是否带录像 |
| A15 | 出 1 道题 → 故意答错 → 打开错题本 | 是否带录像/资料归档 |
| A16 | 「存为资料」→ 资料库搜关键词 | 能否搜到 |
| A17 | 用另一段 10 秒测试录像走「删除」 | 文件夹和库记录是否都清掉 |

### 判定

| 指标 | 通过线 | 怎么取 |
|---|---|---|
| 时长一致性 | 文件时长、`sessions.duration_ms`、墙钟（扣除暂停）三者差 ≤1s | PyAV / 数据库 / 手记 |
| 音画同步 | 秒表读数与提示音偏差 ≤200ms | A9 抽帧 + 听感 |
| 暂停不收音 | 暂停区间 AAC 波形 RMS < 0.003，且听感静音 | PyAV 逐秒 RMS |
| 横栏不入镜 | 暂停前后各抓一帧，画面无红色横栏 | 抽帧目视 |
| 主屏边界 | 副屏内容完全不出现 | 抽帧目视 |
| 转写覆盖 | 有人声时段覆盖率 ≥95%；首条延迟 ≤90s | 转写时间戳 vs 音频 RMS |
| 转写准确 | 抽 20 句，肉眼字符错误率 <10% | 人听对照 |
| 时间轴跳转 | 3 次误差都 ≤2s | 手测 |
| 幻灯片 | 翻页数与课程一致，无重复，OCR 可读 | 列表 + 抽 3 张 |
| 分析耗时 | ≤300s（硬超时）；目标 <120s | `service_runs` |
| 分析依据 | 3 条说法 3/3 能在视频找到 | 回看 |
| 连问 3 问 | 3 个独立气泡，DB 3 条助手消息，无串泡 | 页面 + DB |
| 成本 | 分析 + 3 问 + 1 题 < 0.05 元 | `agent_runs` / `model_usage` |
| 删除 | 目录消失、`sessions`/`transcripts` 无残留 | 文件系统 + DB |

### 深挖点（这轮真正值钱的部分）

1. **音画同步不是「看起来对」**：用秒表 + 滴答声量化到 200ms 内，特别是暂停恢复之后。
2. **转写覆盖要排除「本来没人声」**：用逐秒 RMS 找有人声区间，再和转写时间戳对；避免把 BGM 当成丢转写。
3. **分析必须可证伪**：抽 3 条断言回看视频，接受「没有依据」即失败，不接受「总结得像」。
4. **连续追问**：2.28.3 刚修串气泡，这是回归点；同时看 chip、历史徽标、DB 条数三处一致。

## 3. 场景 B：无声 / 线下课边界（10 分钟）

目标：验证产品在「没有系统声音」时是否诚实，而不是假装分析。

### 步骤

1. 关闭所有播放器声音（或直接录线下课环境，不播放任何音频）。
2. 录 5 分钟：正常翻 PPT、自己讲话（麦克风不录）。
3. 停止 → 等转写 → 点分析 → 问一句「这段讲了什么」。
4. 检查页面提示、分析结果、回答内容、成本记录。

### 判定

| 检查 | 通过 |
|---|---|
| 视频 | 可播放；音轨存在但静音（或明确无音轨） |
| 转写 | 0 条，页面明确说明「没有转写」 |
| 分析 | 不空跑模型；给出中文原因；不生成编造提纲 |
| 问 AI | 不假装有内容；**不出现「还在识别」等假话**（2.28.2 回归） |
| 成本 | 不为空内容产生模型调用 |

### 决策出口

如果结论是「我真实需要录线下课」，这就是需求缺口，记为 **M4 麦克风候选**，另写隐私与设备说明；
如果只是偶尔误触，把「只录系统声音」写进入口提示和 README 即可。

## 4. 场景 C：长录与中断恢复（30 分钟，可自动）

目标：数据安全底线。真人不用守着，我能用接口 + PowerShell 跑。

### 步骤

| # | 动作 | 预期 |
|---|---|---|
| C1 | 通过 `POST /api/quickbar/record` 开始，播放 30 分钟音视频 | 正常起录 |
| C2 | 第 10 分钟 `Win+L` 锁屏 3 分钟再解锁 | 不崩溃；解锁后画面恢复 |
| C3 | 第 20 分钟 `taskkill /F` 后台进程，等守护拉起 | 守护 ≤2 分钟恢复；录像页能列出这段 |
| C4 | 第 25 分钟停止（接口或界面） | 收尾完成 |
| C5 | 检查文件、库、转写、分析 | 见下 |

### 判定

| 检查 | 通过线 |
|---|---|
| MP4 完整性 | 能打开、时长误差 ≤2s、末尾可播 |
| 摄像头/锁屏 | 锁屏段可为黑帧，但不得导致文件损坏 |
| 库记录 | `sessions` 有行，`video_path` 指向真实文件 |
| 崩溃恢复 | 守护拉起后页面可见；文件仍能分析 |
| 资源 | 30 分钟 CPU 均值 <40%；RSS 增量 <200MB；磁盘 >2GB 余量 |
| 转写 | 有声时段有转写；进程崩溃前的分块不丢已落库部分 |

## 6. 分工与顺序

| 场景 | 谁做 | 时长 | 说明 |
|---|---|---|---|
| A | 你真人操作，我核对数据 | 60 min | 托盘/热键/右键暂停只有真人能点 |
| B | 你真人操作，我核对 | 10 min | 同上 |
| C | 我自动跑，你只需不关机 | 30 min | 接口启停 + 锁屏 + 强杀 |

建议顺序：**先 A**（真实价值最大，失败项最有信息量）→ B（快）→ C（可放后台）。
A 通过后再决定是否需要补测；不为了「测得多」重复跑。

## 7. 结果怎么用

- A 全过 → 网课场景定稿，可以写进 README/引导，并考虑在今日页加录像入口。
- A 有失败 → 按失败项开修复单，修复后只重跑失败项，不重跑全案。
- B 诚实 → 把「只录系统声音」写进入口提示；需求真实则开 M4。
- C 通过 → 数据安全基线成立；失败则优先修，阻塞后续功能。
