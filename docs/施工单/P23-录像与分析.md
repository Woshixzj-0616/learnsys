# P23 · 录像与分析：真录 MP4 + 专门文件夹 + 转录 / 幻灯片 / AI 分析

> 目标：把快捷栏的「录制」改成**真正的屏幕录像**——录主屏 + 系统声音，存成标准 MP4 放到专门文件夹；停止后能**在页面里播放、看转写、看幻灯片、让 AI 分析**，整个文件夹也能直接拿出去用别的工具分析。
> 起点 `ad3892d`（2.24.1，878 后端 / 23 网页 / 25 六级）。
> 2026-10-25 用户拍板：**要真视频、要专门文件夹、要能拿出来分析**。上一版「只录声音的录音笔记」方案作废。

## 1. 可行性实测（已跑过，不是估计）

| 验证项 | 结果 |
|---|---|
| PyAV | 19.0.1 已装且已进打包 spec；`libx264` / `aac` / MP4 都可用 |
| 编码速度 | 1600×1000 合成画面 125 fps；10 fps 录制余量很大 |
| 屏幕采集 | `mss` 采 2560×1600 约 **25 ms/帧**；Qt `grabWindow` 约 36 ms/帧 → 用 mss，放独立线程 |
| 音视频合流 | 5.1 秒样片成功：H.264 + AAC 两条流，容器时长 5.1 秒 |
| 无声时的回环 | `pyaudiowpatch` 的 `read()` 会一直阻塞；从另一线程 `stop_stream()` 能解锁 → 必须补静音、按墙上时钟对齐 |
| 崩溃容错 | 分片 MP4（`frag_keyframe+empty_moov`）能正常打开，异常退出也不至于整段报废 |
| 网页播放 | 本地 Starlette `FileResponse` 支持 Range，`<video>` 可以拖动进度 |
| OCR 速度 | RapidOCR 一张 1600×1000 约 **3.3 秒** → 只 OCR「变化过的幻灯片」，并设张数上限 |
| 许可 | PyAV 本身是 BSD，但自带 FFmpeg + libx264 是 GPL；需补第三方声明，或优先用硬件编码 |

## 2. 目标形态

1. 快捷栏点「录像」→ **3 秒倒计时**（留时间切到网课窗口）→ 开始录主屏 + 系统声音。
2. 录制中横栏显示：`● 录像 03:21 · 96 MB · 转写 812 字`。
3. 停止 → MP4 立刻落盘 → 页面可播放/拖动；转写在后台补齐。
4. 停止后可点：**播放 / 分析这段 / 打开文件夹 / 问这段**。
5. 工作台新增「录像」页：列表 + 播放器 + 转写时间轴 + 幻灯片 + 分析结果。
6. 目录里同时放 `transcript.md`、`transcript.srt`、`analysis.md`、`幻灯片/`，整个文件夹拿出去也能用。

**明确三条口径：**

- **只录系统输出，不录麦克风**（线下老师说话录不到）。
- **视频不上传**。分析只把「转写文字 + 幻灯片 OCR 文字」发给模型，MP4 始终留在本机。
- **MP4 是唯一原件**；转写、SRT、分析、幻灯片都是它的衍生物，删了可以重做。

## 3. 边界

**做：**

| 区域 | 内容 |
|---|---|
| 视频 | 主屏、10 fps、最长边 1600、H.264 + AAC、标准 MP4 |
| 声音 | WASAPI 系统回环；AAC 进视频，同时降采样给 whisper |
| 文件夹 | `D:\学习系统\录像\<日期-时间>\`：`video.mp4` + `transcript.md/.srt` + `analysis.md` + `幻灯片/` + `thumb.jpg` + `meta.json` |
| 快捷栏 | 「录像」按钮、3 秒倒计时、录制行、停止后结果卡 |
| 录像页 | 列表、`<video>` 播放/拖动、转写时间轴、幻灯片、分析、删除、打开文件夹 |
| 分析 | 转写 + 幻灯片 OCR → AI 提纲/要点/术语/追问；存 `analysis.md` 和资料 |
| 复用 | 存为资料、资料出题、错题本、成本账本、深链桥、`#/ask?recording=` |
| 兜底 | 磁盘余量检查、单段上限、分片 MP4、无声/丢帧计数 |

**不做：**

- 麦克风 / 摄像头 / 系统混音
- 指定窗口 / 指定区域录制（v1 只录主屏）
- 4K、多显示器拼接、直播
- 剪辑、字幕烧录、视频转码
- 把 MP4 上传给多模态模型（DeepSeek 直连接口不支持视频/图片）
- 自动保留期与磁盘配额（先手动删）
- Qt 独立录像页（v1 走 Web）

## 4. 文件与数据

### 4.1 目录

```text
D:\学习系统\录像\
  20261025-140312\
    video.mp4          # 标准 H.264 + AAC，可拖到任何播放器 / 剪辑软件
    transcript.md      # 带时间戳的转写
    transcript.srt     # 字幕，播放器可直接挂
    analysis.md        # AI 分析（完成后生成）
    thumb.jpg
    meta.json          # 时长/大小/字数/模型/生成时间
    幻灯片\
      slide_0001_140312.jpg
      ...
```

- 文件夹名用开始时间 + 会话 id，稳定不冲突；**不要手动改名**（DB 里存的是路径）。
- 默认根目录 `D:\学习系统\录像`，以后可在 `设置.json` 用 `video_dir` 改。

### 4.2 数据库

`sessions` 加列（纯加法，`SCHEMA_VERSION` 2 → 3）：

| 列 | 类型 | 用途 |
|---|---|---|
| `kind` | TEXT NOT NULL DEFAULT 'video' | `video` / `focus` |
| `title` | TEXT NOT NULL DEFAULT '' | 显示名，如「10-25 14:03 录像」 |
| `video_path` | TEXT NOT NULL DEFAULT '' | MP4 路径 |
| `video_bytes` | INTEGER NOT NULL DEFAULT 0 | 文件大小 |
| `duration_ms` | INTEGER NOT NULL DEFAULT 0 | 视频时长 |
| `thumb_path` | TEXT NOT NULL DEFAULT '' | 缩略图 |
| `slides_dir` | TEXT NOT NULL DEFAULT '' | 幻灯片目录 |
| `material_id` | INTEGER NOT NULL DEFAULT 0 | 转写/分析存成的资料 |
| `analysis_result_id` | INTEGER NOT NULL DEFAULT 0 | `service_results` 里的分析任务 |

`frame_text` 加 `session_id INTEGER NOT NULL DEFAULT 0`，让幻灯片 OCR 能按这段录像查。

## 5. 技术设计

### 5.1 采集与合流

- **屏幕**：`mss` 在采集线程里抓主屏（2560×1600 约 25 ms），等比缩到最长边 1600，帧率 10 fps。
- **声音**：`pyaudiowpatch` 回环，原生 48k/立体声：
  - 一份直接进 AAC（96 kbps）；
  - 一份降到 16k/单声道，喂现有 whisper 分块。
- **合流**：PyAV 单写线程，两个流；视频 `libx264 veryfast crf 26 g=20`，音频 AAC。
- **无声音时**：`read()` 会阻塞。停止时从另一线程 `stop_stream()` 解锁；写入端按**墙上时钟**补齐静音，保证 A/V 不漂。
- **暂停**：冻结最后一帧 + 静音，时间轴继续走（这样转写时间戳和视频时间戳始终一致）。
- **掉帧**：按 10 fps 时间轴补重复帧；统计丢帧数，结束汇总里如实报。
- **崩溃容错**：写分片 MP4；停止时正常收尾。异常退出最多丢最后几秒。
- **磁盘守卫**：开始前要求至少 2 GB 余量；单段上限 8 GB / 3 小时，到点自动停并提示。

### 5.2 幻灯片与 OCR

- 采集线程每 10 秒算一次 32×32 灰度指纹；和上一张差异超过阈值才存 JPEG 到 `幻灯片/`（上限 240 张）。
- 存图时把 `(session_id, path, 时间)` 交给现有 OCR 队列（RapidOCR，约 3.3 秒/张）。
- 录制中慢慢啃，通常追得上；停止后若还有积压，分析按钮显示「还在识别幻灯片」。
- OCR 文字写 `frame_text(session_id, path, ts, text)`，`search_records` 也能搜到。

### 5.3 分析

- 输入：转写全文（上限 60000 字）+ 幻灯片 OCR（按时间去重，上限 20000 字）。
- 提示词要求输出 Markdown：
  - 这段课讲了什么（2–3 句）
  - 时间线提纲（按时间分段）
  - 关键要点（≤10 条）
  - 术语表（≤10 行）
  - 没讲清 / 值得追问的地方（≤3 条）
- 分析任务走后台队列（复用 `service_runs` / `results` 的持久化与状态机，单独 worker，不堵六级分析）。
- 完成后：写 `analysis.md`，把「分析 + 转写」存成一份资料（`kind=note`、`source=video`、`meta.session_id`），页面可直接「出题」。
- 成本走现有 `model_usage` 账本，按模型计价。
- 视频本体不离开本机；提示词里明确告诉模型「这是自动转写，可能有个别错字，没依据不要编」。

### 5.4 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/recordings?q=&limit=` | 列表（按时间倒序，可按转写搜） |
| GET | `/api/recordings/{id}` | 详情：会话 + 转写 + 幻灯片 + 分析状态 |
| GET | `/media/recordings/{id}.mp4` | 视频流（Range，供 `<video>` 拖动） |
| GET | `/api/recordings/{id}/thumb` | 缩略图 |
| POST | `/api/recordings/{id}/analyze` | 起分析任务 |
| POST | `/api/recordings/{id}/material` | 存为资料（幂等） |
| POST | `/api/recordings/{id}/open-folder` | 打开所在文件夹（复用 `ops.open_path`） |
| DELETE | `/api/recordings/{id}` | 删这段（DB 行 + 视频 + 幻灯片；已存资料不删） |
| POST | `/api/agent/chat` | 新增可选 `recording_id`，把这段转写拼进上下文 |

`/media` 按 id 取文件、不接受路径参数，避免目录穿越；和现有 `/web`、`/cet6/试卷` 一样只在本机监听。

### 5.5 界面

**快捷栏：**

- 空闲：「录像」→ 3 秒倒计时（覆盖层显示 3/2/1，可点取消）。
- 录制中：「停止」+ `● 录像 03:21 · 96 MB · 812 字`；右键仍可暂停/定时停止。
- 停止后：答案区出本次记录卡

```text
【本次录像】10-25 14:03–14:08 · 5 分钟 · 96.4 MB · 转写 812 字

[播放](video:play) · [分析](video:analyze) · [打开文件夹](video:folder) · [问这段](video:ask)
```

**工作台「录像」页 `#/recordings`：**

- 左列表（搜索 + 日期），右详情。
- 详情：`<video controls poster=...>`、转写时间轴（点时间跳到视频对应位置）、幻灯片缩略图、分析结果、动作按钮。
- 分析中显示进度与「取消」；失败给中文原因与「重试」。
- 问这段：`#/ask?recording=<id>`，问一问显示「上下文 · 录像」chip。

**今日页：** 把「快照 N 张」换成「录像 N 段 / X 分钟」，并在时间线里显示录像段。

## 8. 风险与处理

| 风险 | 处理 |
|---|---|
| 无声时回环阻塞 | 停止时 `stop_stream()` 解锁；写入端按墙上时钟补静音（已实测可行） |
| 编码吃 CPU / 掉帧 | 10 fps + 1600 宽 + veryfast；掉帧计数并如实报；M3 可切 NVENC（实测可用） |
| 大文件占盘 | 开始前查余量；8 GB / 3 小时硬上限；结束显示大小 |
| 异常退出文件坏 | 分片 MP4；正常停止收尾；提供「修复/删除」入口 |
| OCR 太慢 | 只 OCR 变化帧 + 240 张上限；分析可先只用转写 |
| 长时间录像上下文过大 | 分析输入上限 6 万字；超长按时间段分块摘要 |
| GPL 许可 | 默认 libx264（GPL），在 `THIRD_PARTY_NOTICES.md` 写清；M3 优先硬件编码 |
| 误录隐私 | 3 秒倒计时、录制指示、停止按钮；只录主屏；不录麦克风 |
