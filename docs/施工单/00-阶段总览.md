## 0. 一句话

先收尾，再做六级 1–2 周实验；实验达标才把「上下文 + 服务 + 结果资产」抽象成平台。
所有阶段共用一套数据层、一套 API 命名、一套单一真源规则，避免每加一个功能就长一套新表。

## 2. 目标架构

```
前端（三套外壳，共用一套后端）
  ├─ Web 工作台   /web/*      原生 ES modules
  ├─ 六级工作台   /cet6/*     单文件 HTML（源码在 D:\cet6_tool\workbench_src）
  └─ 原生快捷栏   Qt           只负责框选/输入/流式显示

后端（一个 FastAPI 进程）
  ├─ server/routes_*.py    HTTP 边界：校验、令牌、SSE、错误中文化
  ├─ services/             业务用例：分析任务、翻译、复习、检索
  ├─ agent/                自研 Agent：流式、工具循环、提示词
  ├─ store.py              单库 CRUD（唯一读写入口）
  └─ core/db.py            schema + 幂等迁移

数据
  └─ D:\学习系统\learning.db（SQLite WAL）
```

**分层纪律**

| 层 | 只做 | 不做 |
|---|---|---|
| routes | 参数校验、鉴权、拼响应、SSE | 写 SQL、拼提示词、算业务规则 |
| services | 业务用例、缓存、状态机、任务调度 | 直接碰 FastAPI `Request` |
| store | SQL、事务、行 ↔ dict | 调模型、判断业务 |
| core/db | 建表、补列、索引、FTS | 业务逻辑 |
| 前端 | 展示与交互 | 自己拼大段上下文（P13 起改为传引用） |

**LLM 分工**（借自智能旅行）：LLM 负责判断与生成；代码负责事实、判定、排程、去重、引用回核。
具体：出题/翻译/分析交给模型；对错判定、复习间隔、缓存键、结果状态、成本记账交给代码。

## 3. 数据资产地图

### 3.1 现有表（不动语义）

`asks`、`messages`、`conversations`、`cet6_events`、`events`、`materials`、`wrong_items`、
`transcripts`、`window_events`、`frame_text`、`sessions`、`search_idx`（FTS5 trigram）。

### 3.2 新增表（P12 建，P13/P14 扩展）

| 表 | 作用 | 唯一键 | 引入阶段 |
|---|---|---|---|
| `service_results` | AI 结果资产（分析/翻译/批改/出题） | `(kind,target_type,target_id,scope,context_hash,prompt_version)` | P12 |
| `service_runs` | 每次调用的流水（重试/缓存/成本） | 自增 id | P12 |
| `cet6_progress` | 六级「当前状态」：每句一行 | `(paper_id,section,item,sentence)` | P12 |
| `vocab_items` | 生词统一表（替代 localStorage） | `(word,paper_id,context_hash)` | P13 |
| `review_state` | FSRS 调度状态 | `(item_type,item_id)` | P14 |
| `review_log` | 每次复习记录 | 自增 id | P14 |

**当前状态 vs 事件日志**：`cet6_progress` 存「现在是什么样」，`cet6_events` 存「什么时候发生过」。
两者不互相替代；页面读 progress，复盘/时间线读 events。

### 3.3 通用字段约定

- 时间一律 `TEXT`，格式 `YYYY-MM-DD HH:MM:SS`（本地时区）。
- 主键：业务实体用 `INTEGER PRIMARY KEY AUTOINCREMENT`；天然联合键用复合主键。
- 软删除：`status='active'|'trashed'`（材料已用）；错题用 `mastered`；其余先硬删。
- JSON 字段命名 `*_json`，只存序列化后的字符串。
- 所有新表必须有 `created_at` / `updated_at`；事件表只需 `ts`。
- 迁移只做加法：`CREATE TABLE IF NOT EXISTS`、`ALTER TABLE ADD COLUMN`、`CREATE INDEX IF NOT EXISTS`；
  **不删列、不改类型、不重命名**。删除/重构走新表 + 迁移脚本 + 备份。

## 4. API 与 CRUD 约定

### 4.1 路径

```
GET    /api/<domain>                 列表（查询参数过滤）
GET    /api/<domain>/{id}            详情
POST   /api/<domain>                 新建
PATCH  /api/<domain>/{id}            局部更新
DELETE /api/<domain>/{id}            删除（或软删）
POST   /api/<domain>/{id}/<action>   动作（review/cancel/restore）
```

- 写操作一律 `Depends(require_token)`；只读按需。
- 错误用 `{"detail":"中文说明"}`，状态码 400/403/404/409/413/500。
- 列表返回 `{"items":[...], "count":n}`；单条返回对象本身。
- 分页先用 `limit/offset`；量大再换游标。
- 流式统一 SSE：`data: {"kind":"text|thinking|tool_start|tool_end|done|error", ...}\n\n`。

### 4.2 结果资产 CRUD

`service_results` 是「一个逻辑请求一行」，不是「一次调用一行」：

- 先按唯一键查 `done` 结果；命中直接返回，`cache_hit=1`。
- 没有则创建 `pending` 行；同一键已有 `pending/streaming` 时返回同一行（去重）。
- 成功后写 `content_json`、`status='done'`；失败写 `error`、`status='error'`。
- 用户点「重新分析」传 `force=true`：把旧行标为 `superseded`，新建一行。
- 每次实际调用模型都往 `service_runs` 写一行，带 `result_id`、耗时、token、缓存命中。

### 4.3 前端约定

- Web 工作台只用 `web/js/api.js`；页面里不直接 `fetch`。
- 六级单文件工作台没有模块系统，新增 `js/55-api.js` 作为它的唯一网络出口。
- 所有网络错误显示中文；不把 `HTTP 500` 裸给用户。
- 长任务必须能取消、能重开、能在刷新后恢复；状态只认服务端。

## 7. 施工纪律

每个阶段照这个顺序，不跳步：

1. **写施工单**（本目录）——接口、数据、函数、测试、验收先定死。
2. **先必红**——先写会失败的测试，确认能复现问题。
3. **实现**——按施工单改，不顺手加需求。
4. **跑满**——`\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p "test_*.py"`；
   六级 `build_workbench.py --check`；前端/接口冒烟。
5. **一个提交**——一个阶段一个 commit，信息写清范围。
6. **停下汇报**——给证据，不 push、不发版，等负责人发话。
