# P25.3 · 深度分析启用

> 2026-10-27 · 目标版本 **2.36.0**
> 依据：`docs/施工单/Agent-能力监控.md`「深度分析未启用」；`learnsys/agent/deep.py` 已有命令/API 两条路。

## 0. 一句话

让「问一问」页的「深度分析」按钮真正可用：默认复用主模型 key 与强模型，不新增第二份密钥。

## 1. 现状

- `agent.deep.available()` 只认设置里的 `command` 或 `api_key`；主模型 key 在
  `~/.claude/settings.json` 的 env 里，深度分析拿不到，所以生产一直是 `available=false`。
- `_run_api()` 默认打 `https://api.anthropic.com`，与本机实际使用的 DeepSeek Anthropic 端点无关。
- 设置页没有深度分析表单项（配置只走 `设置.json`，重启生效）。

## 2. 改法

1. `learnsys/agent/deep.py` 新增 `_api_settings(settings)`：
   - `api_base` 留空 → 用主模型 `cfg.base_url`；
   - `api_key` 留空 → 用主模型 `cfg.auth_token`（**密钥只有一份**）；
   - `model` 留空 → 用 `cfg.strong_model`，再退 `cfg.model`。
2. `available()` / `describe()` / `_run_api()` / `run()` 全部走这一个函数，避免四处各算一遍。
3. `设置.json` 模板补 `agent.deep` 默认值（`enabled=false`，其余留空），并在注释里写明
   「留空 = 复用主模型」。
4. 生产启用：`enabled=true`、`model=deepseek-v4-pro`、`api_base/api_key` 留空；
   直接改 `设置.json` 并备份，部署重启后生效。

## 3. 不做

- 不加设置页表单项（本轮只启用，不改 UI）；
- 不自动触发深度分析（仍由用户点按钮）；
- 不把深度分析结果写回问答/错题（保持只读、独立审计）。

## 4. 验收

- 单测：`available` 在「启用 + 主 key」时为真、禁用时为假；`_run_api` 使用主模型的
  base/key/model；显式设置覆盖主模型；`describe` 不返回密钥。
- 门禁：后端全量 / 网页 / 六级 / ruff / 体量 / 分层。
- 真机：`POST /api/agent/deep` 一次真实调用，返回中文分析；
  `agent_runs` 有 `mode=deep` 流水，`model_usage` 有 `source=deep` 记账；
  能力体检「深度分析」从「未启用」变可用。

## 5. 完成记录（2026-10-27）

- 代码：`deep.py` 的 `_api_settings()` 单一入口；设置模板补 `agent.deep`。
- 测试：**1089 后端**（新增 8）；`test_deep_analysis.py` 隔离真实设置，避免本机启用后误红。
- 真机：21.7 秒、中文正确；`model_usage` 118 + 1034 tokens、0.02898 CNY。
- 配置：生产 `agent.deep.enabled=true`、`model=deepseek-v4-pro`；备份
  `D:\学习系统\设置-20261027-深度分析前.json`。
- 部署：2.36.0，备份 `dist\学习工作台-2.35.0-backup`；未 push / 未 tag / 未 Release。
