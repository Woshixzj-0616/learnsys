# R7 · 模型调用账本与每日上限（2.24.0）

> 目标：为「自动路由开 `on`」补两块地基——**按模型单价**与**每日成本 / 调用上限**。
> 起点 `5e65702`（2.23.0，860 后端 / 23 网页 / 25 六级）。

## 0. 边界

**做：**

| 区域 | 内容 |
|---|---|
| 账本 | 新表 `model_usage`：每次**成功**的模型调用一行（模型 / token / 成本 / 来源） |
| 单价 | `agent.prices` 按模型覆盖；没配的模型用全局 `price_input/output/cache_read` |
| 上限 | `agent.daily_cost_limit`、`agent.daily_call_limit`（0 = 不限）；**硬拒绝** |
| 检查点 | `agent.run()` 准备阶段调用 `agent/budget.py::check()`；超限整轮拒绝，不发模型请求 |
| 覆盖范围 | 所有走 `agent.run` 的调用：问一问、快捷栏、翻译、六级分析、复盘、测验、自检重写 |
| 成本计算 | 一次运行里按「模型 → usage」分开算；`done` 事件带 `usage_by_model` / `cost` |
| 界面 | 网页 + Qt 设置页：每日两个上限、模型单价表（增删行）；运行记录页显示今日调用/花费和上限 |
| schema | `SCHEMA_VERSION` 1 → 2（新表，纯加法） |

**不做：**

- 不统计 `services/textops.py`（解释/摘要）和设置页「测试连接」——它们不经过 `agent.run`。
- 不把 `deep.py` 的外部 CLI 成本算进来（拿不到 token）。
- 不做币种换算；账本沿用 `agent.currency`。
- 不做「按项目/任务」预算，也不做自动降级——超限就是拒绝。
- 不自动开启 `auto_route=on`；本阶段只补前提。

## 1. 判定与口径

- **硬拒绝**（用户 2026-10-24 拍板）：达到上限后不再发起任何模型调用，中文提示已用/上限与怎么调高。
- 上限按「今天已完成的调用」算；当前这一轮最多超出一条的用量。调用次数按成功调用计。
- 成本上限需要先填单价才有意义；没填单价时成本恒为 0，只有调用上限有效。
- 一次运行混用模型（主模型 / 强模型 / 降级模型 / 自检重写）时，按每次调用的真实模型分别记账、分别估价。
- 账本写失败只记 `diagnostics.log_swallow`，不阻断对话；代价是当天用量会少算。
