# P26.5 · Agent 中枢：多进程任务归属

> 2026-10-28 定稿。目标版本 **2.41.1**。
> 承接 P26.4：显式任务链 → 修 P26.3 记录的已知限制「两进程共用一库时后启动者误杀前一个的 running」。

## 0. 一句话

任务认领时记下**谁在跑**（进程实例令牌）并定期刷新**心跳**；恢复只回收
「不属于本进程、且心跳已过期」的任务，不再把库里所有 `running` 一律标失败。

## 1. 问题与证据

| 项 | 内容 |
|---|---|
| 现象 | 生产 8765 正在跑任务时，启动 8766 测试后台（未隔离数据根）→ 生产任务瞬间变 `failed`，错误写「工作台重启，任务中断」 |
| 代码位置 | `learnsys/services/agents/queue.py:78` `recover()` → `store.fail_agent_running_tasks()`，SQL 条件只有 `status = 'running'` |
| 为什么是 bug | 它假设「能打开这个库的只有本进程」。库被两个进程共用时，这个假设直接导致**数据正确性错误**：活任务被静默判死，子任务被级联取消 |
| 影响面 | 派活、任务链、影子路由完成率统计、成本归档 |

复现路径（不依赖界面）：

1. 进程 A 起一个长任务（≥5 秒）；
2. 进程 B 对同一个库调用 `queue.ensure_started()`；
3. A 的任务在库里变成 `failed`，而 A 的进程还在跑。

## 2. 方案决策（2026-10-28）

| 决策 | 结论 | 理由 |
|---|---|---|
| 归属标识 | `agent_tasks.runner` = 进程实例令牌 `"{pid}-{uuid8}"`，认领时写入 | 令牌每进程一个，重启必变；不靠 PID 本身 |
| 存活判定 | 心跳优先：本进程每 5 秒刷新自己 `running` 任务的 `heartbeat_at`；**20 秒（4 拍）未刷新**判死 | 与平台无关、纯 SQL 可测 |
| 不用 PID 判活 | 实测 Windows 下 `os.kill(pid, 0)` 对已退出进程误报「存活」；Win32 `OpenProcess` 可行但平台相关，且有 PID 复用问题 | 见下方实测记录 |
| 恢复时机 | 启动时一次 + 心跳线程每拍顺带扫一次，两处都走同一个 `recover()` | 一条规则一个落点 |
| 不碰自己 | `runner == 本进程令牌` 的任务永不判失败 | 兜住「A 死后 B 接管」时 B 自己的在跑任务 |
| 旧数据 | `runner = ''` 的 `running`（升级前遗留）一律判失败 | 无从得知归属，按最保守处理 |
| 代价 | 崩溃后最多 **20 秒**才回收任务（重启后这段时间队列显示旧任务仍在跑） | 换取「绝不误杀活进程任务」；恢复慢只是体验，误杀是数据错误 |
| 不做 | 不建进程注册表、不做分布式锁、不跨机 | 本机单库场景，够用即可 |

**实测记录（2026-10-28，本机 Python 3.14 / Windows 11）**：

```
存活进程 os.kill(pid,0) → 通过
已死进程 os.kill(pid,0) → 误判为存活   ← 不可用
Win32 OpenProcess+WaitForSingleObject → 存活 True / 已死 False / 不存在 False
```

## 3. 数据（schema 9 → 10）

`agent_tasks` 只做加法：

| 字段 | 说明 |
|---|---|
| `runner TEXT NOT NULL DEFAULT ''` | 认领它的进程实例令牌；空 = 升级前遗留 |
| `heartbeat_at TEXT NOT NULL DEFAULT ''` | 上次心跳时间（`YYYY-MM-DD HH:MM:SS`） |

两个字段**不进任何接口**，只在队列内部使用。

## 5. 测试（先必红）

| 用例 | 断言 |
|---|---|
| 活的外来任务 | `runner="99999-other"`、心跳=现在 → `recover()` 返回 0，任务仍 `running` |
| 死的外来任务 | 心跳 = 现在 − (`STALE_AFTER` + 10) 秒 → `recover()` 返回 1，任务 `failed` 且错误含「重启」 |
| 自己的任务 | `runner = queue.runner_id()` → `recover()` 返回 0，任务仍 `running` |
| 升级前遗留 | `runner=''` → `recover()` 判失败（覆盖原有用例） |
| 认领写归属 | `claim_next` 后 `runner == runner_id()`，`heartbeat_at` 非空 |
| 心跳只刷自己 | `touch_running_tasks` 只改本进程的行，外来行时间戳不变 |

## 6. 验收

1. 单测全过（全量 discover）、`arch_report --check` / `layering_report` / `test_architecture` 0 违规；
2. 真机双进程复现：A 起 8 秒任务 → B 调 `ensure_started()` → A 任务仍 `running`、B 的 `recover()` 返回 0；
3. 回归：单进程重启（`runner=''` 或心跳过期）→ 任务 `failed`，`queued` 继续跑。

## 7. 不做

- 自动任务分解 / 自动编排；
- draft + reviewer 双 agent；
- 多父 DAG、条件分支、失败自动重试。
