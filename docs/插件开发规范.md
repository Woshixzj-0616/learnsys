# 插件开发规范（v2.0.0）

学习系统的舞台只做三件事：侧栏、路由、页面容器。功能全部以插件形式挂进来。
加一个插件**不改壳层代码**，只加一个目录：

```
learnsys/plugins/<id>/
└─ plugin.json
```

## 1. 清单字段

```json
{
  "id": "netlab",
  "name": "网工训练场",
  "icon": "⇄",
  "type": "native-page",
  "entry": "pages/netlab.html",
  "script": "js/pages/netlab.js",
  "order": 25,
  "status": "ready",
  "version": "2.0.0",
  "category": "专业",
  "home": true,
  "tagline": "子网、路由、抓包——每天练一格",
  "description": "给网络工程专业的训练场……"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 唯一标识；路由是 `#/<id>`，设置里的开关也用它 |
| `name` / `icon` | 是 | 侧栏与插件卡片显示 |
| `type` | 是 | `native-page` 或 `iframe` |
| `entry` | 是 | 原生页 = `/web` 下的 HTML；iframe = 后端挂载的 URL |
| `script` | 原生页必填 | `/web` 下的 ES module，导出 `mount(ctx)` / 可选 `unmount()` |
| `order` | 是 | 侧栏顺序，越小越靠前 |
| `status` | 是 | `ready` / `planned`；`planned` 显示「待建」 |
| `version` | 建议 | 插件版本，插件中心显示 |
| `category` | 建议 | 插件中心分类标签 |
| `home` | 建议 | `true` = 出现在学习台「插件舞台」卡片 |
| `tagline` / `description` | 建议 | 卡片短句 / 插件中心长说明 |

清单只在**插件目录**里维护一份；旧的 `learnsys/modules/registry.json` 已删除，
`load_registry()` 读不到插件目录时才会回退到旧文件（兼容老 exe）。

## 2. 原生页插件

`web/pages/myplugin.html`：

```html
<div class="myplugin-page">
  <h2>我的插件</h2>
  <button id="do">记一笔</button>
</div>
```

`web/js/pages/myplugin.js`：

```js
import { api } from "../api.js";
import { toast } from "../ui.js";

export async function mount(ctx) {
  ctx.setSub("插件副标题");
  ctx.setActions("");
  document.getElementById("do").addEventListener("click", async () => {
    await api.post("/api/events", {
      module: "myplugin", kind: "action", title: "完成一次", meta: {},
    });
    toast("已记录", "ok");
    location.hash = "#/today";
  });
}

export function unmount() {
  // 可选：清定时器、取消请求
}
```

`ctx` 提供：`root`（页面容器）、`params` / `query`（路由参数）、`module`（当前清单）、
`registry`（全部插件）、`setSub(text)`、`setActions(html)`。

## 3. iframe 插件

```json
{
  "type": "iframe",
  "entry": "/cet6/工作台/精听工作台.html"
}
```

- 后端挂载路径必须同源（`127.0.0.1:<端口>`），页面里的相对路径才能工作。
- 路由 query 会原样拼到 iframe URL 后面（例如 `#/cet6?paper=卷一` → `...?paper=卷一`）。
- iframe 页面不能读父页面的令牌；需要写数据时走后端专门的无令牌只读/迁移接口，
  或在后端做同源白名单（见 `learnsys/server/security.py`）。

## 4. 学习事件与学习点

插件统一用 `events` 表记「发生过什么」：

```http
POST /api/events
X-Learnsys-Token: <从 /api/health 拿>
Content-Type: application/json

{"module":"myplugin","kind":"action","title":"完成一次","meta":{"id":"x"}}
```

```http
GET /api/events?module=myplugin&limit=50
```

- `module` 建议等于插件 `id`，时间线和成就按它聚合。
- `title` 会显示在时间线；`meta` 存结构化细节（不要放密钥/隐私）。
- 学习点规则在 `learnsys/server/routes_data.py::XP_RULES`；新插件想计分，在这里加一行，
  **只加一处**，不要在插件里自己算。

## 5. 开关与启用

- 插件中心写 `设置.json` 的 `modules: {"<id>": true/false}`。
- 关闭只影响侧栏/学习台显示，不删数据、不卸载后端。
- 新插件默认启用；`status: "planned"` 的插件仍会出现在侧栏「待建」分组。

## 6. 测试

- 清单发现：`tests/test_plugins.py::PluginRegistryTest`
- 事件/学习点：`tests/test_plugins.py::PluginApiTest`
- 前端页面：用 Chrome DevTools MCP 打开 `#/<id>`，检查控制台 0 error、关键按钮可点。

## 7. 安全底线

- 不把密钥、绝对个人路径、真题音频写进插件清单或前端代码。
- 插件写接口必须走令牌；只读公共接口才考虑无令牌。
- iframe 插件不拿令牌、不跨源写数据。
