# P10 · 错题按资料归档

> 日期：2026-10-21 ｜ 版本：`2.4.0` ｜ 状态：完成
> 承接 P9：资料出题产生的错题，要能看出「错在哪份资料」，并能按资料筛。

## 一、数据

- `wrong_items` 新增 `material_id INTEGER NOT NULL DEFAULT 0`；
  老库由 `_migrate_columns()` 自动补列，并创建 `idx_wrong_material`。
- 顺带修了一个老库启动隐患：`idx_asks_conversation` 原本在 `SCHEMA` 里先于补列执行，
  极老库会报 `no such column: conversation_id`；现在移到补列之后创建。
- 迁移顺序原则：**先补列、再建依赖该列的索引**，否则 `executescript(SCHEMA)` 会先撞上。

## 二、错题怎么拿到 material_id

- `ChatRequest.attach_material`（默认 true）：
  - `true`：从资料库挂载，正文进这一轮提示词；
  - `false`：只把 `material_id` 传给 Agent 做归档，不重复塞正文（资料出题用）。
- `AgentRequest` / `ToolContext` 增加 `material_id`；
  `save_wrongbook` 工具落库时写入 `ctx.material_id`。
- 测验页每次 `streamChat` 都带 `material_id` + `attach_material: false`；
  自动收题和手动补收都会归档到这份资料。
- 手动补收 API `POST /api/wrongbook` 接受 `material_id`。

## 三、查询与展示

- `GET /api/wrongbook` 新增 `material_id` 筛选，并返回 `materials` 分面：
  `[{material_id, title, count}]`。
- 错题条目返回 `material_id` 与 `material_title`（join `materials`）。
- 错题本页面新增「资料」下拉：全部资料 / 某份资料（含题数）；卡片详情显示「资料：…」。
- Anki CSV 新增「资料」列。

## 四、实测

1. 全量回归：`Ran 301 tests ... OK`。
2. 真实模型两轮：
   - 第一轮 `read_material` 读资料后出题；
   - 第二轮故意答错，`save_wrongbook` 落库；
   - 错题条目 `material_id=4`、`material_title=P10验收资料.md`、`auto=true`；
   - `/api/wrongbook?material_id=4` 返回 1 条，分面 `[{title, count:1}]`。
3. 老库升级：P7 结构的 `wrong_items`（无 material_id）连接后自动补列并建索引。
4. 验收产生的资料、错题、会话已按 id 清理。
