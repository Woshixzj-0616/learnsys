## 3. P20.2 真机（8799 源码后台 + 真实 Edge）

| # | 操作 | 结果 |
|---|---|---|
| 1 | 插件页「启动浏览器」 | 独立 Edge 窗口启动；状态「运行中」；地址栏保留 |

| 3 | 再打开 `https://example.org` | 历史新增；同一 URL 不重复（标题从空变「Example Domain」时会多一条，属于「标题变化才写」口径） |
| 4 | 设置 `exclude_domains=["example.com"]` 后打开 example.com 新路径 | 不落库；example.org 正常落库；测完已恢复 `[]` |
| 5 | 暂停记录 → 打开 `example.com/paused-secret` → 恢复记录 | 状态 `record=false / paused=true / current=null`；恢复后**不补记**；之后新页面正常落库 |
| 6 | 清空记录 | `GET history` 返回 `count=0` |
| 7 | 问一问「我最近看了什么网页？」（真实模型） | 模型调用 `browser_history`，回答最近记录（时间/标题/域名） |
| 8 | 问一问「打开 https://example.com/p20-confirm-test」→ 拒绝确认 | 模型回答「这个网址没有打开，open_url 没有执行」；该 URL 未进历史 |
| 9 | 关闭浏览器 | 状态 `running=false`；`wmic` 统计独立 profile 的 msedge 进程为 **0** |
| 10 | 进程命令行 | 11 个 msedge 进程均含 `--user-data-dir=D:\学习系统\浏览器配置`、`--remote-debugging-port=0`；未触碰日常 profile |
| 11 | 手工启动同 profile 的 Edge（模拟后台崩溃残留）→ 启动后台 → 「启动浏览器」 | 直接接管已有实例（不再起第二个）；5 秒后仍 `running=true`；「关闭浏览器」按端口反查 PID、校验 profile 后 `taskkill /T`，残留进程 **0** |

**真机发现并修掉的问题 2**：同 profile 已有浏览器时，新起的 `Popen` 会立刻退出（Chromium 单例转发），
原来 `_alive()` 看 `proc.poll()` 会误判成「没运行」。已改成**以 CDP 端口为准**；
接管来的实例没有 Popen，关闭时用 `netstat` 按端口反查 PID，校验命令行含本 profile 后再杀。

前端 `#/browser` 页面：状态、当前标签、启动/关闭、输入框、暂停/恢复、清空、历史「重新打开」均可用；
Chrome DevTools 控制台 **无 error / warn**。

## 4. 未做 / 已知边界

- `close_on_exit` 的**真实工作台退出**路径没有在 Qt 主程序里点掉验证；单元测试覆盖了
  `close_on_exit=false` 不杀进程、`close=true` 只杀自己 PID。后台 `lifespan` 已接 `manager.shutdown()`。
- 快捷栏（Qt 弹窗）的确认框这轮没有单独点验；它走同一个 `confirm` 回调和同一条工具链，
  P16.1 已实测，本轮网页侧实测通过。
- `--download-directory` 不是 Chromium 官方开关，实测不保证生效；下载仍按浏览器自身策略
  （会落在独立 profile 的默认下载目录或系统下载目录）。施工单已允许「退回浏览器默认策略」。
- Edge 新建标签页 `ntp.msn.cn` 会进历史；如嫌吵，把它加进 `exclude_domains`。
- CDP 威胁模型是「本机可信」：同用户进程理论上可访问随机端口；不开放 WebSocket /
  `Runtime.evaluate` / `Page.navigate`，端口/PID/profile 不返回前端。
- 测试期间写入的浏览记录与设置改动均已清理/恢复；启动的记事本与资源管理器窗口已关闭。
