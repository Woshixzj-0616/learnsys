# P23 · M3：把问一问内置到录像里（同一 Agent / 同一套历史）

> 日期：2026-10-25
> 版本：`2.28.1`（已部署生产）
> 目标：录像页里直接问 AI，但**不新建一个 AI**；对话进同一套历史，又能区分来源。

## 做法（不是第二个 AI）

- 录像页的「问一问 · 这段录像」调用同一个 `POST /api/agent/chat`、同一套系统提示词/工具/模型。
- 对话落同一张 `conversations` / `messages` 表，`module=ask`（所以问一问侧栏能看到）；
  额外带 `origin=video` + `recording_id=<sessions.id>` 标来源。
- 问一问页面（`#/ask`）的会话列表照常显示这些对话，只是加一个「录像」徽标和录像标题。
- 录像页只列出**这一段录像**的对话（`origin=video&recording_id=`），可切换/继续/新开；
  「在问一问里打开」跳到完整问一问会话（`#/ask/<id>`）。
- 快捷栏「历史」里，这些提问带 `[录]` 标签；`问一问` 里的普通提问仍是 `[文]/[图]`。

数据形状：

| 字段 | 值 |
|---|---|
| `conversations.module` | `ask`（统一进问一问） |
| `conversations.origin` | `ask` / `video` / `cet6` |
| `conversations.recording_id` | 录像里的对话指向 `sessions.id`，普通问一问为 0 |
| `messages.content.recording_id` | 每条提问实际挂了哪段录像 |

## 交互

1. 录像详情 →「问一问 · 这段录像」面板：
   - 自动带出**这段录像最近的对话**（线程 + 历史列表）；
   - 输入框直接问，流式 Markdown 回答；
   - 「新对话」开一条新会话（旧会话保留在历史里）；
   - 「在问一问里打开」跳完整问一问。
2. 问一问侧栏：视频对话带「录像」徽标，meta 里带录像标题；点开自动挂回录像上下文，
   后续追问继续带这段转写。
3. 快捷栏「历史」：视频问答显示 `[录]`，悬停提示带录像标题。

## 口径与限制

- 录像页是**紧凑视图**，不是把整个问一问页面 iframe 进来；完整界面点「在问一问里打开」。
- 问一问侧栏默认 `module=ask`，所以视频对话会出现；复盘/测验等 `internal` 会话仍不混入。
- 「问一问里打开」在没有历史会话时是 `#/ask?recording=<id>`，会新建一条 **origin=ask**
  的会话（问一问里问的，挂录像上下文）；这符合「知道在哪问的」口径。
- 快捷栏的「历史」来自 `asks`，问一问侧栏来自 `conversations`；两边是同一批提问的不同视图，
  录像内嵌提问会同时进两边。
- 生产尚未在录像内嵌面板里问过真实问题（部署后还没有新对话）；需要用户点一次验证。
- 未提交、未 push。

## 真机 bug 修复（2.28.2，2026-10-25）

**现象**：生产最新会话 36（录像 4，6.9 秒、音频静音）里，用户问「我帅吗」，
助手答完后多了一句「课堂转写那段是空的，还在识别，没法拿来当参考」。

**根因**：`chat.py` 在录像没有转写时仍追加了一条
「【录像转写】（这段还没有转写，可能还在识别）」；模型看到这条提示后，
把「转写是空的」当成了回答的一部分，连普通闲聊也被带偏。

**修复**：

- 只有**真实转写**才拼进上下文；没有转写就什么都不加。
- 有转写时的前缀改成「背景资料，只在问题需要时引用；不要主动评论转写是否完整」。
- 新增 `test_recording_without_transcript_adds_no_note`，锁住这个行为。

**验证**：915 后端 / 23 网页 / ruff / 门禁全过；生产 8765 = **2.28.2**，
旧版备份 `dist\学习工作台-2.28.1-backup`。

**历史数据说明**：会话 36 里已经落库的那条旧回答不会被改写；新问的问题走新逻辑。
需要的话可以删掉这段测试会话（录像/转写不受影响）。

另：录像 2（92 秒）和录像 4（7 秒）的音频峰值都是 0.0（录制时是静音），
所以 0 条转写是正常的；录像 3（118 秒）音频有声音，10 条转写正常。

## 第二个回答写进第一个回答（2.28.3，2026-10-25）

**现象**：同一个录像会话里问两个问题，第二个回答被写进了第一个回答的气泡里。

**根因**：`ai-panel.js::appendStreaming` 用
`thread.querySelector(".rec-ai-stream")` 取「当前正在写的助手气泡」；第一问完成后
没有移除 `rec-ai-stream` 类，第二问插入新气泡后再查，拿到的仍是**第一问的旧气泡**，
流式文本就写进了第一条回答。

**修复**：

- 插入后取**最后一条**助手气泡（`querySelectorAll(...).at(-1)` 等价写法）；
- done / error / finally / stop 都移除 `rec-ai-stream` 类，避免下一条再拿到旧的；
- SW 缓存升 v24。

**验证**：8766 假模型连问「第一问」「第二问」，页面气泡为
`回答：第一问`、`回答：第二问`，第一气泡不含第二问；DB 消息为
user/assistant × 2，顺序正确。

**数据说明**：会话 36 的 DB 里本来就是 4 条独立消息（两个问题、两个回答），
只是**实时视图**写错了气泡；重新打开会话/刷新页面会按 DB 正确显示。
生产 8765 = **2.28.3**，旧版备份 `dist\学习工作台-2.28.2-backup`。
